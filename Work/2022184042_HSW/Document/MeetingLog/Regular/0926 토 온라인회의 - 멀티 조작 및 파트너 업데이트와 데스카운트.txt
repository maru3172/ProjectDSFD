- 회의명: 온라인 개발 논의 (팀 채팅 및 1:1 채팅 통합)
- 기록 기준일: 2026년 09월 26일 토요일
- 실제 대화 날짜: 두 파일에 날짜가 없어 미확인. 사용자가 함께 전달한 이번 회의의 두 채팅을 같은 날의 기록으로 취급하여 시각순으로 정렬했다. 파일명은 전달일 기준이다.
- 대화 시간: 오후 4:44~오후 11:08
- 참여자: 홍승우, 이규아, 백경철
- 출처 구분: 첫 첨부 파일(오후 4:44 시작)은 팀 채팅, 두 번째 첨부 파일(오후 5:17 시작)은 홍승우·이규아의 1:1 채팅으로 내용에 따라 분류했다.
- 주요 안건: 멀티 마네킹 조작과 카메라 전환, 파트너 및 시야 업데이트, 심박수 연계, 데스카운트와 포획 검토
- 기록 원칙: 중간 제안보다 이후의 명시적 구현·조정 보고를 구분하여 정리했다. 구현 완료와 테스트 결과는 참석자의 보고이며, 이 회의록 작성 과정에서 코드를 검증한 것은 아니다.

- 22:23~22:29 / 팀: 심박수 시스템 문서 업로드를 알리고 Git 브랜치·rebase 작업 흐름을 논의했다.
- 22:50~23:08 / 팀: 수동 공격·포획 아이디어와 멀티 난이도를 검토했다. 마지막에 데스카운트를 멀티 0, 싱글 3으로 조정 완료했다고 보고했다.

3. 멀티 마네킹 조작 방식

3.1 빙의와 명령의 구분

- 초기 구현 이해는 숫자키로 마네킹에 빙의하면 즉시 직접 조작하는 방식이었다.
- 홍승우는 빙의를 카메라 전환으로 보고, 모드 변경은 별도의 동작으로 설명했다.
- 추적 중인 마네킹의 위치와 상황을 확인할 때마다 이동이 중단되거나 추격 명령을 다시 입력해야 하는 불편을 피하려는 의도다.
- 이규아는 빙의 중 직접 조작하고 이탈 후 기억한 명령을 수행하는 방식을 생각했다고 설명했다.
- 여러 마네킹의 위치와 상태를 파악하는 편의성, 설명의 단순함, 정지 기능을 어디에 포함할지를 두고 논의가 이어졌다.

3.2 정리된 방향과 구현 보고

- 개념상 정지·조작·추격을 구분하더라도 조작 모드는 직접 조작과 추격의 두 가지로 정리하는 방향이다.
- 홍승우는 직접 조작 상태에서 다른 마네킹으로 전환하면 기존 마네킹이 정지하는 방식으로 정지 기능을 설명했다.
- 중간에는 F1 직접 조작·F2 추격을 제안했으나, 18:24에 E/R 사용을 제안·수용했다.
- 이후 20:29 팀 채팅의 구현 보고 기준으로 키 배치는 E = 추적, R = 조작이다.
- 같은 보고에서 빙의 상태는 시점 공유·AI 상태라고 설명했으며, 20:36 1:1에서도 원래 요청한 방향으로 구현했다고 밝혔다.
- 직접 조작 상태에서 이탈한 개체의 정지와 개체별 모드 유지의 세부 동작은 요청 내용과 실제 동작이 일치하는지 후속 플레이 확인이 필요하다.

3.3 시점 및 소통 방식

- 3인칭과 탑뷰를 잠시 검토했으나 현재는 1인칭을 유지하는 방향으로 정리됐다. 시점 변경은 확정하지 않았다.
- 문자만으로 개념을 전달하는 데 시간이 많이 걸려, 개발 토의는 디스코드 음성 또는 대면이 가능한 상태에서 하자는 요청이 있었다.
- 우선 구현한 뒤 플레이해 보고 필요하면 피드백하기로 했다.

4. 파트너·추적·데이터 업데이트 보고

- 파트너의 시야 메커니즘을 수정하고 실제 시야와 시야 범위를 구분하여 반영했다고 보고했다.
- 파트너가 플레이어 이동 경로의 반대를 바라보는 기본 방향은 유지했다.
- 플레이어 정지 상태에서 시점이 반복 전환될 때 파트너가 뒷걸음질하는 메커니즘을 추가했다고 보고했다.
- 원문은 'n초이상 n번 이동한게 반복'이라고 표현하며 수치가 제시되지 않았다. 이전 논의의 시간창 조건과 동일한지, 정확한 발동 조건은 이 기록만으로 확정하지 않는다.
- 뒷걸음질은 특수한 상황에서 발생해 체감하거나 재현하기 어렵다는 설명이 있었다. 해당 기능의 충분한 검증 완료로 해석하지 않는다.
- 생존자 한 명만 추적하던 메커니즘을 가까운 플레이어를 추적하도록 수정했다고 보고했다.
- 기존 요청 변수와 신규 개발 변수를 데이터 테이블에 추가했다고 보고했다. 이번 대화에는 전체 변수명·수치 목록이 없다.
- CSV를 수정했다가 되돌리는 변경이 추가될 수 있다고 예고했다. 완료 여부는 별도 확인이 필요하다.
- 플레이어 데스카운트 기능을 추가했으며 20:30 시점에는 기능만 존재한다고 설명했다.

5. 시야 판정과 심박수 연계

- 화면 안의 모든 마네킹을 기준으로 멈추는 대신, 플레이어별 별도 시야 범위에서 감지된 마네킹을 정지시키는 방식으로 변경했다고 설명했다.
- 화면에 보이는 모든 마네킹이 반드시 정지하는 것은 아니며, 시야 범위의 정확한 크기는 대화에서 확인되지 않았다.
- 시야 범위의 디버그 시각화는 별도로 그려져 있지 않다고 설명했다.
- 이규아는 현재 구현에서 카메라 기반 판정이 멀티에서 문제를 일으켜 범위 기반으로 바꿨다고 설명했다. 이를 일반적으로 멀티에서 카메라 기반 판정이 불가능하다는 기술적 결론으로 확대하지 않는다.
- 홍승우는 심박수를 플레이어에 적용하는 방향으로 보고, 백경철에게 카메라 화면 기반으로 구현하지 않도록 전달할 필요가 있다고 정리했다.
- 싱글·멀티 시야 방식의 적용 관계와 심박수 연계는 백경철과 추가 논의할 사항이다. 장애물 가림 등의 상세 판정은 이번 대화에서 새로 확정되지 않았다.
- 심박수의 '시야 내' 조건을 빼는 방안도 잠시 고민했지만 제거 결정은 없었다.
- 홍승우는 심박수 문서를 작성 중이라고 설명한 뒤, 22:23 팀 채팅에서 업로드 완료를 알렸다. 이규아에게 이번 문서와 관련한 추가 작업은 없다고 답했다.

6. 테스트·버그 및 실행 구조 보고

- 1:1에서 마네킹 모델이 보이지 않던 버그를 수정했다고 보고했다. 원인 설명은 레벨에 마네킹을 배치하지 않았다는 것이며, 자세한 생성·표시 과정은 코드 확인 없이 추가 해석하지 않는다.
- 여러 번 테스트했으며 잘 동작한다고 보고했고, 이후 팀 채팅에서도 싱글·멀티 동작을 재확인했다.
- 멀티 렉은 클라이언트를 세 개 동시에 실행해서 생기는 것으로 추정했다. 원인 분석 완료나 성능 문제 해결 보고는 아니다.
- 싱글에서도 서버가 개입하는 구조라고 설명했다. 이는 현재 구현에 대한 개발자의 설명이며 별도 외부 서버 접속 의무나 상시 온라인 정책을 결정한 내용은 아니다.
- 데스카운트를 데이터 테이블 변수로 추가하는 안은 21:12에 다음 날 작업 아이디어로 제시됐다. 뒤의 데스카운트 수치 변경 보고만으로 테이블 추가까지 완료됐다고 판단하지 않는다.

7. 공격·포획 및 데스카운트 논의

7.1 수동 공격 아이디어

- 홍승우는 적 플레이어가 일정 거리 안에서 공격키를 눌러 포획 모션을 실행하고, 거리 밖에서는 헛스윙하는 아이디어를 기록용으로 제안했다.
- 키 후보는 스페이스 또는 좌클릭이며, 포획 시 지하 1층으로 보내는 구상을 설명했다.
- 당장 개발하라는 요청이 아니라고 명시했다.
- AI의 포획 처리, 전체 활성화 여부 및 추가 복잡성을 논의한 뒤 '하지말죠?'라고 제안했다. 구현 착수·채택 결정으로 기록하지 않는다.
- 음성·채팅, 활성화 UI 역시 검토 중 나온 생각이며 신규 확정 요구사항이 아니다.

7.2 최신 수치와 미결 밸런스

- 멀티에 데스카운트가 존재한다는 사실을 확인한 뒤 홍승우는 멀티를 0으로 설정하는 방향을 요청했다.
- 이규아는 생존자 난이도를 우려해 1회 부여를 제안했다. 3회 유지, 지하 미구현 시 1·구현 시 0 등의 안도 논의됐다.
- 마지막 23:08 보고는 '멀티 0, 싱글 3개' 조정 완료다. 중간의 1·3회 제안보다 이 보고를 현재 적용 수치로 기록한다.
- 최종 밸런스는 팀 테스트와 QA를 통해 조절하기로 했다. 인간 생존 난이도와 마네킹 10기 조작 난이도에 대한 의견 차이가 있었다.
- 멀티 달리기에 스태미나 제한을 두겠다는 홍승우의 구상과, 생존자가 어렵다면 시야를 넓히는 아이디어가 언급됐다. 구현 완료나 확정 수치로 기록하지 않는다.

8. 후속 공유 및 확인 사항

- 백경철: 업데이트를 반영한 뒤 마네킹·심박수 작업을 이어가며, 플레이어별 시야 범위와 연계 방식을 홍승우·이규아와 확인한다.
- 홍승우: 업로드한 심박수 문서를 기준으로 질문을 받고 시야 조건 및 적용 방식을 추가 논의한다.
- 이규아: 구현 보고된 모드 전환·파트너 후퇴·가까운 생존자 추적이 요청과 일치하는지 피드백을 받는다. 데스카운트의 데이터 테이블 추가는 완료 여부를 확인한다.
- 팀 테스트: 현재 데스카운트(멀티 0·싱글 3), 생존자·마네킹 간 난이도, 조작 편의성을 점검한다.
- Git 논의: 개인 브랜치에 커밋한 뒤 main의 최신 변경을 fetch/pull하고 개인 브랜치를 rebase하여 반영하는 흐름을 공유했다. 이는 대화 내용의 기록이며 이 작업에서 Git 변경 명령을 실행하거나 무조건 충돌·merge commit을 방지한다고 보장하는 지침은 아니다.
