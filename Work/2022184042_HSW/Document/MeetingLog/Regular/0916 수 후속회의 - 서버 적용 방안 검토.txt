[회의 내용 정리]

1. 회의 개요

- 회의명: 후속회의
- 일자: 9월 16일 수요일
- 회의 배경: 전체미팅에서 게임에 서버를 추가하라는 교수 피드백을 받은 뒤 진행
- 주요 안건: 기존 게임 콘텐츠와 방향성을 수정하지 않으면서 서버 요구사항에 대응할 방법 검토
- 기록 방식: 참석자의 기억을 바탕으로 작성

2. 논의 전제

- 파트너와 협력하여 백화점을 탈출하는 기존 핵심 경험은 유지한다.
- 기존 게임 콘텐츠와 전체적인 방향성을 서버 구현 때문에 변경하지 않는 것을 우선한다.
- 서버를 도입한다면 기존 게임에 자연스럽게 추가할 수 있고 실제 활용 목적이 분명한 기능이어야 한다.
- 서버 구현 비용이 기존 핵심 콘텐츠의 완성도를 낮출 가능성도 함께 고려한다.

3. 서버 적용 방안

3.1 서버를 통한 데이터 관리

- 서버에 플레이어의 업적과 클리어 기록을 저장하는 방안을 논의했다.
- 저장한 기록을 이용해 게임 안에서 순위표를 제공할 수 있다.
- 랭킹에 활용할 수 있는 기록의 예시는 다음과 같다.
  - 게임 클리어 여부
  - 클리어 시간
  - 달성한 업적
  - 엔딩 달성 기록
- 기존 싱글플레이 콘텐츠를 크게 수정하지 않고 서버 기능을 추가할 수 있다는 장점이 있다.
- 어떤 기록을 저장하고 어떤 기준으로 순위를 정할지는 추가 설계가 필요하다.

3.2 2인 PvP 모드 개발

- 기존 백화점 탈출 구조를 활용한 별도의 2인 대전 모드를 추가하는 방안을 논의했다.
- 한 플레이어는 기존 게임과 같이 백화점에서 탈출하는 역할을 맡는다.
- 다른 플레이어는 마네킹 군체를 조종하여 탈출을 방해하는 역할을 맡는다.
- 서버를 단순 기록 저장이 아니라 실제 플레이 콘텐츠에 직접 활용할 수 있는 방안이다.
- 마네킹 군체 플레이어가 조작할 수 있는 범위, 승리 조건, 정보 비대칭, 기존 AI와의 역할 분담 등을 새로 설계해야 한다.
- 네트워크 동기화와 별도 게임 규칙 개발이 필요하므로 세 방안 중 개발 범위가 가장 커질 가능성이 있다.

3.3 서버 미구현

- 서버를 구현하지 않고 해당 개발 시간과 인력을 기존 콘텐츠 구현에 집중하는 방안도 논의했다.
- 서버를 추가하면 네트워크 구조, 데이터 저장, 테스트 등 새로운 작업이 발생하므로 기존 핵심 시스템과 연출의 완성도가 낮아질 수 있다는 우려가 있다.
- 서버 기능의 교육적·평가적 필요성과 기존 게임 완성도 중 무엇을 우선할지 판단해야 한다.

4. 대안 비교

- 데이터 관리 방식
  - 기존 게임 방향에 미치는 영향이 비교적 작다.
  - 싱글플레이 구조를 유지하면서 서버 활용 근거를 만들 수 있다.
  - 기록 저장, 계정 식별, 랭킹 조회 등의 서버 기능이 필요하다.
- 2인 PvP 방식
  - 서버를 활용한 새로운 플레이 경험을 분명하게 보여 줄 수 있다.
  - 기존 자산과 백화점 탈출 구조를 일부 재사용할 수 있다.
  - 네트워크 동기화, 밸런스, 조작 체계 등 추가 개발 부담이 크다.
- 서버 미구현 방식
  - 기존 콘텐츠와 핵심 경험의 완성도에 자원을 집중할 수 있다.
  - 교수 피드백을 직접 반영하지 못한다는 문제가 있다.

5. 회의 결과

- 기존 게임 콘텐츠와 방향성을 유지한다는 원칙을 확인했다.
- 서버 대응 방안으로 데이터 관리, 2인 PvP 모드, 서버 미구현의 세 가지 선택지를 검토했다.
- 이번 기록만으로는 최종 방안이 결정된 것으로 확인되지 않으므로 세 안 모두 검토안으로 남긴다.

6. 추가 검토 사항

- 교수님이 요구한 서버 구현의 필수 범위와 평가 기준을 확인해야 한다.
- 남은 일정 안에서 각 방안을 구현하는 데 필요한 기간과 담당 인력을 산정해야 한다.
- 업적·클리어 기록 방식에서 저장할 데이터와 랭킹 기준을 정해야 한다.
- 개인 식별에 계정 시스템이 필요한지 확인해야 한다.
- 서버 장애나 연결 실패 시에도 싱글플레이가 가능한지 결정해야 한다.
- 2인 PvP 모드의 승리 조건과 한 판의 진행 시간을 설계해야 한다.
- 마네킹 군체 플레이어가 직접 조작할 대상과 명령 방식을 정해야 한다.
- 서버 개발이 파트너, 마네킹 AI, 레벨 디자인, 연출 구현 일정에 미치는 영향을 비교해야 한다.
- 최종 방안을 선택한 뒤 통합 게임 기획서에 반영해야 한다.

전체미팅에서 교수님이 게임에 서버를 추가하고 서버를 활용하는 콘텐츠를 구현하라는 의견을 주셨다. 이에 기존 게임 콘텐츠와 방향성을 바꾸지 않으면서 서버 요구사항에 대응하는 방법을 논의했다.

첫 번째 방안은 서버를 통해 게임 데이터를 관리하는 것이다. 플레이어의 업적과 클리어 기록 등을 서버에 저장하고, 해당 기록을 기준으로 랭킹을 표시하는 방식을 검토했다. 이 방식은 기존 싱글플레이 콘텐츠를 크게 수정하지 않으면서 서버 기능을 추가할 수 있다.

두 번째 방안은 2인 모드를 추가하는 것이다. 한 플레이어는 백화점에서 탈출하고, 다른 플레이어는 마네킹 군체를 조종하여 탈출을 막는 PvP 모드를 개발하는 방안을 논의했다. 서버를 실제 게임 플레이에 적극적으로 활용할 수 있지만 추가 개발 범위가 커질 수 있다.

세 번째 방안은 서버를 구현하지 않는 것이다. 서버 구현에 필요한 개발 시간과 인력을 기존 게임 콘텐츠 구현에 사용하여 핵심 시스템과 연출의 완성도를 높이는 방안을 함께 검토했다.

세 방안 가운데 어떤 방향을 선택할지는 아직 결정하지 않았다.
