- 일자: 2026년 10월 04일 일요일
- 참여자: 홍승우, 이규아, 백경철
- 주요 안건: 마네킹 영역 전환, 심박수 및 데이터 테이블 개편, 서버·리더보드, 조명·SFX 구현과 로딩 오류 해결
- 기록 범위: 10월 4일 주말 논의와 그에 연결되는 앞선 개발 보고를 함께 정리했다. 원문에 10월 1~4일 날짜 구분이 있으며, 첫 23:52~23:59 구간은 10월 1일로 넘어가는 흐름상 9월 30일로 해석했다.
- 기록 방식: 전달받은 채팅을 요약하고 아래에 날짜 구분과 발언 순서를 유지한 전문을 보존했다.

2. 마네킹 영역 전환 로직 수정

- 외부에서 내부 영역으로 진입할 때는 새 영역의 로직을 즉시 실행한다.
- 내부에서 외부 영역으로 이동할 때는 기존 이동 로직을 한 번 끝까지 실행한 뒤 새로운 영역의 로직을 실행하도록 구현했다.
- 기존 플레이어의 마지막 위치를 기억하는 키를 추가했다고 설명했다.
- 수정 범위는 BTService_MannequinAI의 cpp·h 파일과 에디터의 BT·BB 일부다. 다른 부분은 수정하지 않았다고 보고했다.
- 10월 1일 00:00에 main에 merge한 상태라고 공유했다.
- 백경철은 아직 완전하지 않아 여러 번 테스트하면서 보완하고, 추가 수정 시 팀 채팅에 공지하겠다고 밝혔다.
- 기존 방식에 문제가 없었으나 의도한 동작을 구분해 달라는 요청으로 수정했다는 설명도 있었다. 앞선 경계 오작동 방지 목적과 별개로, 이번 대화에서 구체적 재현 버그가 확정된 것으로 기록하지 않는다.

3. 심박수 시스템 및 데이터 테이블 개편

3.1 기본 BPM과 조우 BPM 분리

- 10월 1일 백경철이 BPM 수정 완료를 보고하고 의사코드를 공유했다.
- 기본 시야와 조우 시야를 각각 반지름·부채꼴 조건으로 분리하고 LineTrace를 통한 장애물 판정을 함께 사용한다.
- 공유된 의사코드에서는 매 프레임 BaseBPM을 0으로 시작하고, 모든 마네킹에 대해 기본 시야 조건을 만족하는 BPM 중 최댓값을 반영한다.
- 기본 시야 조건은 기본 반지름 내부, 기본 부채꼴 내부, LineTrace 성공의 조합이다.
- 조우 조건도 조우 반지름·부채꼴 내부와 LineTrace 성공을 함께 검사한다.
- '완전 미확인'은 원문상 조우 부채꼴/반지름 밖 AND LineTrace 실패로 표현됐다. 부채꼴과 반지름 사이의 세부 논리 관계는 발췌만으로 추가 확정하지 않는다.
- 완전 미확인이 3초 이상 지속되면 재조우 준비 상태가 되는 예시가 제시됐다. 이후 EncounterMemorySeconds로 조절하는 항목이 설명됐으므로 3초를 최종 고정값으로 단정하지 않는다.
- 의사코드는 '거리 비례로 Encounter...'에서 잘려 있어 이후 최종 BPM 합성·갱신 절차를 임의로 복원하지 않는다.
- 원문은 거리 비례라고 표현했으나 변수 설명은 먼 거리에서 최소 BPM, 가까운 거리에서 최대 BPM을 의미한다. 구체적인 보간식은 이번 기록에서 확정하지 않는다.

3.3 새로 반영한 설정 변수 10개

- BaseVisionRange: 기본 BPM 시야 부채꼴 반지름
- BaseVisionHalfAngleDegrees: 기본 BPM 시야 부채꼴 반각
- BaseMinBPM: 기본 시야의 가장 먼 지점에서 적용되는 최소 BPM
- BaseMaxBPM: 플레이어와 가장 가까울 때 적용되는 최대 기본 BPM
- EncounterVisionRange: 조우 BPM 시야 부채꼴 반지름
- EncounterVisionHalfAngleDegrees: 조우 BPM 시야 부채꼴 반각
- EncounterMinBPM: 조우 영역의 가장 먼 지점에서 계산되는 최소 조우 BPM
- EncounterMaxBPM: 플레이어와 가장 가까울 때 계산되는 최대 조우 BPM
- EncounterDecayPerSecond: 조우 BPM이 초당 감소하는 양
- EncounterMemorySeconds: 재조우 준비에 필요한 완전 미확인 지속시간

3.4 설정값과 실행 중 상태값 구분

- UnconfirmedStartTime은 각 마네킹이 완전히 감지되지 않기 시작한 실제 게임 시각이다.
- bEncounterArmed는 각 마네킹의 재조우 심박 발생 준비 상태다.
- 두 항목은 실행 중 변하는 상태값이므로 데이터 테이블에 추가하지 않았다고 확인했다.
- 변수 변경을 이름 변경·불필요·신규 항목으로 나누어 공유해 달라는 요청이 있었으며, 최종적으로 제거 목록과 신규 설명이 공유됐다. 기존 변수와 새 변수의 일대일 이름 대응표는 제공되지 않았다.

6. 10월 4일 조명 로딩 오류와 해결

6.1 현상 및 중간 추정

- 홍승우는 조명이 보이지 않고 낮은 밝기와 관련된 로그가 나타난다고 보고했다.
- 이규아의 환경에서는 정상 동작했으며, 수정본 적용 후에도 홍승우 환경에서는 로그만 없어지고 빛은 여전히 보이지 않았다.
- 일반 스팟 라이트를 배치한 뒤 깜빡임이 보인다는 관찰은 이후 어두울 때 생기는 노이즈였다고 정정됐다. 정상 점멸 확인으로 기록하지 않는다.
- 대상은 MannequinReactiveLight이며, 블루프린트를 열 때 부모 클래스가 유효하지 않아 로딩할 수 없다는 오류가 홍승우와 백경철에게 동일하게 발생했다.
- 초기에는 merge, 버전 변경, ignore 설정, 과거 LFS 문제 등을 의심했다.
- .gitattributes 누락으로 LFS 파일이 제대로 풀리지 않았다는 설명은 과거 모델 로딩 문제를 회상한 내용이다. 이번 조명 오류의 확정 원인으로 기록하지 않는다.

6.2 확인 과정과 최종 보고

- 이규아는 main 최신 변경 수신 여부와 오류 로그를 확인하고 프로젝트 DLL의 존재 여부를 확인하도록 안내했다.
- 백경철은 DLL 경로 확인 결과 True를 보고했고, 빌드 결과도 Succeeded로 공유했다. 파일 존재·빌드 성공만으로 조명 오류가 해결되지는 않았다.
- 이후 Binaries 삭제와 Generate Visual Studio Files 실행을 안내했고, 백경철은 수행 후 실행하여 정상 표시를 확인했다고 보고했다.
- 이규아는 바이너리 파일 미갱신 문제로 설명했다.
- 22:42에 백경철은 사운드와 깜빡임이 잘 작동한다고 보고했고, 홍승우도 해결됐다고 확인했다.
- 재클론은 중간에 제안됐으나 실제 수행했다는 기록은 없다.
- 위 과정은 이번 문제의 처리 이력이다. 회의록 작성 중 해당 명령을 실행한 것이 아니며, 매번 조명을 추가할 때 Binaries를 삭제해야 한다는 일반 규칙으로 정하지 않는다.
