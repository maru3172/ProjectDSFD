[회의 내용 정리]

1. 회의 개요

- 회의명: 정기회의
- 기록 기준일: 2026년 9월 29일 화요일
- 실제 회의 일시: 녹취에 날짜와 시작 시각이 없어 미확인. 파일명은 전달일을 기준으로 작성했다.
- 주요 안건: 기본·거리 기반 심박수와 조우 심박수 설계, 마네킹 발걸음 효과음, 추가 마네킹 아이디어, 성능 진단 도구 사용법
- 기록 방식: 갤럭시 녹음 앱으로 추출한 텍스트를 바탕으로 정리했다. 음성 인식 오류로 정확하지 않은 수치와 용어는 확정하지 않았다.

2. 심박수 시스템

2.1 전체 구조

- 기본 심박수는 60 BPM을 하한으로 사용한다.
- 플레이어가 확인할 수 있는 마네킹과의 거리가 가까워질수록 거리 기반 심박수가 증가한다.
- 마네킹을 새로 발견했을 때는 거리 기반 심박수와 별개로 조우 심박수가 순간적으로 추가된다.
- 최종 심박수는 `기본·거리 기반 심박수 + 현재 남아 있는 조우 심박수`로 계산한다.
- 기본 심박음은 약하게 계속 재생하는 방향으로 논의했다. 위험 상황에서만 재생하는 방식은 범위 밖 가시 대상 처리와 로직 충돌 가능성이 있어 채택하지 않았다.

2.2 가시성 판정

- 장애물 뒤의 마네킹이 심박수에 영향을 주지 않도록 플레이어와 마네킹 사이를 라인 트레이스로 확인한다.
- 카메라 객체를 직접 기준으로 삼으면 멀티플레이에서 서버와 클라이언트가 보는 화면 차이 때문에 문제가 생길 수 있다.
- 심박수 판정은 플레이어에 둔 범위와 라인 트레이스를 조합하는 방향으로 유지한다.

2.3 조우 심박수

- 마네킹이 조우 판정용 시야 부채꼴 안에 새로 들어오면 조우 심박수를 발생시킨다.
- 조우 당시 마네킹이 가까울수록 큰 값을, 멀수록 작은 값을 적용한다.
- 조우 심박수는 최초값에서 0까지 시간에 따라 감소한다.
- 새 마네킹을 발견하더라도 조우 심박수를 계속 더하지 않는다. 새로 계산한 값이 현재 감소 중인 값보다 클 때만 현재 값을 새 값으로 교체한다.
- 예를 들어 현재 조우 심박수가 20이면 새 값이 10일 때는 기존 값을 유지하고, 새 값이 30일 때는 30으로 교체해 다시 감소시킨다.
- 동일한 마네킹을 잠시 보지 않았다가 다시 보는 행동만으로 조우 심박수가 반복 상승하지 않도록 마네킹별 재조우 대기시간을 사용한다.

2.4 조우 판정용 부채꼴

- 기존 시야와 별도로 더 큰 조우 판정용 부채꼴을 추가한다.
- 부채꼴의 거리와 각도는 레벨 디자인에 맞춰 조정할 수 있는 변수로 만든다.
- 회의에서는 약 15m와 기존 범위의 2배 이상이 예시로 언급됐으나 최종 수치로 확정하지 않았다.
- 부채꼴 진입과 라인 트레이스 가시성을 모두 만족할 때 조우로 판정한다.
- 개발 중에는 기존 시야와 조우 범위를 서로 다른 색으로 표시해 구분한다. 색상은 확정하지 않았다.

2.5 확인이 필요한 값

- 기존 코드에 마네킹별 재조우 타이머가 구현된 것으로 보이나 정확한 시간이 확인되지 않았다.
- 회의에서 3초와 0.75초가 모두 언급됐지만 각각 어떤 타이머에 사용되는 값인지 불분명하므로 코드를 확인한다.
- 조우 심박수를 초당 고정값으로 감소시킬지, 정해진 지속시간에 맞춰 보간할지도 현재 구현을 확인한 뒤 결정한다.
- 기본 심박수, 최대 심박수, 거리별 증가량, 조우 심박수 최소·최대값을 조절 가능한 변수로 정리한다.

3. 마네킹 발걸음 효과음

- 마네킹이 걸을 때 발걸음 소리가 나도록 기능을 추가하는 방안을 논의했다.
- 프로토타입에서는 보유한 사운드 팩의 임시 음원을 사용할 수 있다.
- 최종적으로는 애니메이션 몽타주 또는 애니메이션 노티파이를 사용해 왼발과 오른발의 접지 시점에 소리를 재생하는 방식으로 구현한다.
- 현재 기본 걷기 애니메이션에 먼저 연동하고, 기괴한 보행 연출은 충돌 캡슐과 마네킹 겹침 문제가 생길 수 있어 우선 적용하지 않는다.
- 심박수 시스템보다 우선순위가 낮으며 여유가 있을 때 진행한다.

4. 추가 마네킹 아이디어

- 반신 마네킹이 플레이어를 감지하면 소리를 내고 주변 마네킹을 불러 모으는 감지형 개체 아이디어가 제시됐다.
- 천장이나 환풍구에서 소리가 들리다가 플레이어가 일정 시간 머물면 마네킹이 떨어지는 연출도 제안됐다.
- 천장 마네킹은 이동 경로를 예측하는 복잡한 AI보다 일정 시간 정지를 감지하는 단순 트리거 방식이 현실적이라는 의견이었다.
- 두 아이디어 모두 확정된 개발 항목이 아니다. 현재 작업 범위를 늘리지 않기 위해 후속 검토안으로 남긴다.

5. 맵·모델링 및 개발 방향

- 주요 시스템 구현이 진행됨에 따라 백화점 맵, 레벨 디자인, 모델링과 애니메이션 작업의 비중이 커질 것으로 보았다.
- 백화점 전체 구조를 러프하게 만든 뒤 구역을 나누어 팀원이 분담하는 방식이 제안됐다.
- 프로토타입 단계에서는 보유 모델이나 구매 자산을 활용하고 기능 검증에 필요한 기본 형태를 우선한다.
- 기존 통로 기반 테스트 맵은 범위 기반 방식을 선택한 근거와 성능 비교에 활용할 수 있으므로 보존한다.

6. 성능 진단 및 로그 도구

6.1 설치 및 측정 절차

- 성능 진단 도구가 최신 버전으로 업데이트됐다.
- 최신 저장소 내용을 받은 뒤 기존 빌드 산출물인 bin과 obj 폴더를 정리하고 다시 빌드한다.
- 정확한 빌드 명령과 실행 경로는 디스코드에 공유한 내용을 따른다. 녹취에서 불명확한 명령은 임의로 기록하지 않는다.
- 게임 테스트를 시작할 때 Start를 누르고, 종료하기 전에 Stop을 눌러 두 시점 사이의 측정 기록을 저장한다.
- 저장된 기록은 실행별·레벨별로 확인한다. 진단 파일이 기본 위치와 다르면 도구에서 해당 경로를 지정한다.

6.2 주요 기능

- FPS 변화와 급격한 하락 구간을 시간 흐름에 따라 표시한다.
- CPU, GPU, 메모리, 네트워크 및 다이얼로그 오버헤드 등의 성능 지표를 확인할 수 있다.
- 정상 상태, 위험 요소, 검토 필요 항목과 변경된 요소를 분류해 보여준다.
- 코드 검사, 빌드 및 자동화 결과를 통해 현재 오류와 잠재적 위험 요소를 확인한다.
- 이벤트 검색과 필터링을 지원하며 특정 상태나 항목만 골라 볼 수 있다.
- 측정 기록이 누적되면 이전 실행과 비교해 성능과 위험도의 변화 추이를 시각화한다.
- 정밀 분석용 Unreal Trace는 성능 부담이 있으므로 일반 측정과 분리하고 필요할 때만 사용한다.

6.3 활용 방향

- 도구는 주로 프로그래머가 구현 상태와 성능 문제를 확인하는 데 사용한다.
- 기능을 변경한 뒤 로그를 남겨 최적화 전후와 장기적인 성능 변화를 비교한다.
- 기획자는 모든 세부 진단을 직접 확인하기보다 요약 결과와 변화 기록을 참고할 수 있다.
- 첫 실행과 전체 코드 검사는 시간이 걸릴 수 있으며, 컴퓨터별 실행·경로 문제는 추가 확인한다.

7. 결정 사항

- 기본 심박수 60 BPM을 하한으로 사용한다.
- 거리 기반 심박수와 일시적인 조우 심박수를 분리한다.
- 조우 심박수는 시간에 따라 감소시키고, 새 조우 값이 현재 값보다 클 때만 교체한다.
- 기존 시야보다 큰 조우 판정용 부채꼴을 별도로 추가한다.
- 장애물 가시성은 라인 트레이스로 확인한다.
- 마네킹 발걸음은 애니메이션과 연동하되 심박수 구현 이후의 후순위 작업으로 둔다.
- 성능 진단 도구를 최신화해 기능 변경과 최적화 기록에 활용한다.

8. 후속 작업

- 심박수 담당
  - 기존 코드에서 재조우 대기시간과 조우 심박수 감소 방식을 확인한다.
  - 조우 판정용 부채꼴과 거리·각도 조절 변수를 추가한다.
  - 현재 조우 심박수와 신규 조우 값을 비교해 더 큰 값만 반영하는 로직을 구현한다.
  - 범위와 라인 트레이스의 조합을 멀티플레이 환경에서 검증한다.
- 성능 진단 도구 담당
  - 최신 설치·빌드 절차를 팀원에게 공유한다.
  - 다른 컴퓨터에서 실행과 진단 파일 경로를 확인한다.
  - 기능 변경 전후의 측정 기록을 누적한다.
- 기획·아트 담당
  - 백화점 맵의 러프한 전체 구조와 구역 분담안을 준비한다.
  - 발걸음 음원과 걷기 애니메이션의 적용 수준을 추후 확정한다.

9. 미확정 사항

- 기본 심박음의 상시 재생이 실제 플레이에서 적절한지 체감 테스트가 필요하다.
- 조우 부채꼴의 거리·각도와 기존 시야 대비 배율은 레벨 디자인에 따라 조정한다.
- 재조우 대기시간과 조우 심박수 감소 수치는 코드 확인 후 확정한다.
- 반신 감지 마네킹과 천장 마네킹은 제안 단계이며 현재 개발 범위에 포함하지 않는다.

※ 이 문서는 녹취를 바탕으로 한 회의 기록이며, 코드 구현 완료나 통합 게임 기획서 반영 완료를 의미하지 않는다.
