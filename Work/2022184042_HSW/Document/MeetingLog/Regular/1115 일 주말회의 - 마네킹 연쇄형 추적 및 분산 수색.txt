[회의 내용 정리]

1. 회의 개요

- 회의명: 주말회의
- 회의 일자: 2026년 11월 15일 일요일
- 주요 안건: 0·1·2·3차 마네킹 역할을 이용한 연쇄형 추적, 예상 위치 계산 및 분산 수색 시스템
- 기록 방식: 전달받은 「1·2·3차 마네킹 연쇄형 추적 시스템 개발 명세」를 회의 결정 및 개발 기준으로 정리했다.

2. 개발 목적

- 모든 마네킹이 플레이어의 정확한 위치를 항상 공유하고 한 지점으로 몰리는 단순 추적 방식을 개선한다.
- 마네킹이 플레이어 정보를 얻은 방식에 따라 0·1·2·3차 역할을 부여한다.
- 플레이어를 직접 관측한 정보가 있으면 정확한 위치를 우선 사용한다.
- 직접 관측자가 없으면 플레이어의 시야로 정지한 마네킹들의 위치 관계와 마지막 관측 정보를 이용해 예상 위치를 계산한다.
- 위치 정보는 전체 마네킹이 공유하되 실제 수색은 중앙 관리 시스템이 지정한 3차 마네킹만 수행해 군집을 방지한다.

3. 마네킹 역할

3.1 0차 마네킹: 기본 상태

- 유효한 추적 정보나 수색 목표가 없는 상태다.
- 기존 무작위 배회, 지정 위치 대기 또는 범위 기반 이동을 수행하며 새 정보를 기다린다.
- 직접 관측 시 1차, 플레이어 시야로 정지 시 2차, 수색 목표 배정 시 3차로 전환한다.

3.2 1차 마네킹: 직접 관측자

- 시야각·시야 거리·차폐 여부를 확인해 플레이어를 직접 볼 수 있는 마네킹이다.
- 플레이어의 현재 위치, 이동 방향과 속도, 관측 시각, 정보 생성자, 신뢰도와 정보 번호를 중앙 관리 시스템에 전달한다.
- 플레이어가 바라봐 이동이 정지하더라도 마네킹이 계속 플레이어를 볼 수 있으면 1차 상태와 정보 갱신을 유지한다.
- 여러 1차 정보가 있으면 최신 정보를 우선하고, 시각이 같을 때는 가까운 관측자의 정보를 우선할 수 있다.

3.3 2차 마네킹: 간접 단서 제공자

- 플레이어를 직접 보지 못하지만 플레이어의 시야 때문에 정지한 마네킹이다.
- 명령, 충돌, 길 찾기 실패, 애니메이션, 피격, 대기 또는 연출에 의한 정지는 2차 판정에서 제외한다.
- 정확한 플레이어 위치 대신 “플레이어가 해당 마네킹을 볼 수 있지만 마네킹은 플레이어를 보지 못할 가능성이 있는 위치”라는 제약을 제공한다.
- 유효한 1차 마네킹이 없을 때 여러 2차 단서를 조합해 예상 위치를 계산한다.

3.4 3차 마네킹: 수색 실행자

- 1차 또는 2차 마네킹 주변에서 중앙 관리 시스템으로부터 수색 목표를 배정받은 마네킹이다.
- 직접 관측 위치 또는 예상 후보 구역으로 이동해 플레이어를 수색하고 결과를 반환한다.
- 다른 3차 마네킹을 임의로 추가 지정하지 않으며, 역할 배정은 중앙 관리 시스템이 담당한다.
- 수색 중 플레이어를 직접 발견하면 즉시 1차로 전환한다.

4. 역할 및 정보 우선순위

- 역할 판정 순서는 `직접 관측 1차 → 플레이어 시야 정지 2차 → 목표 배정 3차 → 기본 상태 0차`다.
- 한 마네킹은 한 시점에 하나의 역할만 가진다.
- 플레이어에게 관찰되어 정지했더라도 마네킹 자신도 플레이어를 보고 있다면 2차가 아니라 1차로 판정한다.
- 위치 정보 우선순위는 다음과 같다.
  1) 현재 1차 마네킹의 직접 관측 정보
  2) 2차 단서와 마지막 관측 정보를 결합한 예상 정보
  3) 마지막 관측 정보만으로 계산한 예상 위치
  4) 유효한 정보가 없을 때의 0차 기본 행동
- 1차 마네킹이 하나라도 플레이어를 직접 보고 있으면 2차 기반 예상 정보는 사용하지 않는다.

5. 정보 공유와 3차 지정

- 위치 정보 공유 범위는 전역으로 두되 역할 지정과 행동 전환은 지역 단위로 제한한다.
- 1차 또는 2차 마네킹의 반응 범위 안에서 수색에 적합한 개체만 3차로 지정한다.
- 동일한 마네킹이 여러 정보원의 3차 후보가 되면 정보 우선순위, 신뢰도, 정보원과의 거리, 현재 담당 3차 수를 기준으로 담당 정보원을 선택한다.
- 3차 마네킹 수와 후보 구역 수에 따라 구역별로 분산 배치하며, 한 구역에 중복 배치하기 전에 미배정 구역을 우선한다.

6. 2차 마네킹 기반 예상 위치 계산

- 정지 시각, 마네킹 간 거리, 하나의 플레이어 시야각에 함께 포함될 가능성, 벽과 통로의 공간 연결성을 기준으로 2차 마네킹을 그룹화한다.
- 오래된 단서와 현재 플레이어 시야에서 벗어난 마네킹은 제외한다.
- 2차 마네킹을 볼 수 있는 주변 영역, 마지막 관측 위치, 플레이어의 이동 가능 거리와 실제 이동 가능 공간의 NavMesh 위에 후보 지점을 생성한다.
- 후보 위치는 다음 조건으로 필터링한다.
  - 후보 위치에서 2차 마네킹을 볼 수 있어야 한다.
  - 후보 위치가 2차 마네킹의 시야 밖이거나 장애물로 가려져 있어야 한다.
  - 마지막 관측 위치와 시간이 있다면 플레이어가 해당 시간 동안 실제로 도달할 수 있어야 한다.
- 이동 가능성은 가능하면 직선거리가 아니라 NavMesh 경로 거리로 판정한다.
- 후보가 없으면 오래된 단서 제외, 그룹 분리, 이동 가능 거리 확대, 일부 단서만 만족하는 후보 허용, 마지막 관측 위치 주변 수색 순으로 조건을 완화한다.
- 조건을 완화할수록 후보 신뢰도를 낮춘다.

7. 후보 점수와 후보 구역

- 후보 지점은 설명 가능한 2차 마네킹 수, 정보 최신성, 마지막 관측 위치와의 거리, 이동 방향 일치도, 이동 가능 시간, 공간 구조, 기존 수색 여부를 기준으로 평가한다.
- 개념식은 `후보 점수 = 시야 조건 점수 × 정보 최신도 × 이동 가능성 × 미수색 보정값`이다.
- 정확한 가중치는 데이터 테이블로 조정한다.
- 가까운 후보 지점을 묶어 후보 구역을 만들고 대표 위치, 후보 지점, 신뢰도, 배정된 3차 수, 수색 완료 여부와 마지막 수색 시각을 관리한다.
- 3차 마네킹은 후보 구역의 중심에만 몰리지 않고 구역 내 주요 길목, 미배정 지점, 마지막 이동 방향과 이어지는 지점으로 나누어 배치한다.

8. 수색 결과 처리

- 3차 마네킹이 목표에 도착하면 일정 시간 주변을 탐색한다.
- 플레이어 발견 시 해당 마네킹을 1차로 전환하고 직접 관측 정보를 전역 공유한다.
- 새 직접 관측 정보가 생기면 기존 예상 위치의 신뢰도를 낮추거나 제거하고 다른 3차 마네킹의 목표를 재계산한다.
- 발견 실패 시 후보 구역의 신뢰도를 낮추고 수색 완료를 기록한 뒤 미수색 구역으로 재배치한다.
- 모든 후보를 확인하면 탐색 범위를 확대하고, 일정 시간 새 정보가 없으면 0차로 복귀한다.

9. 중앙 추적 관리 구조

- 각 마네킹이 다른 모든 마네킹을 직접 검사하지 않고 별도의 중앙 관리 객체를 둔다.
- 권장 예시 명칭은 `MannequinTrackingCoordinator`다.
- 중앙 관리 객체는 역할, 직접 관측 정보, 2차 그룹, 예상 후보, 후보 점수, 3차 배정, 신뢰도·유효시간, 중복 방지와 디버그 정보를 관리한다.
- 멀티플레이에서는 역할 지정, 위치 정보와 수색 목표 결정을 서버 권한으로 처리한다.

10. 데이터 및 조정 항목

- 추적 정보에는 정보 유형, 위치, 이동 방향·속도, 생성·만료 시각, 신뢰도, 생성 마네킹, 참여한 2차 목록과 정보 번호를 포함한다.
- 마네킹별 상태에는 현재 차수, 정지 원인, 직접 관측 여부, 담당 정보, 후보 구역, 이동 목표, 도착 여부, 역할 변경 시각과 수색 실패 횟수를 포함한다.
- 시야 거리와 각도, 정보 갱신·유효시간, 그룹 조건, 3차 지정 범위와 수, 후보 생성·병합 조건, 탐색 시간, 신뢰도 감소량과 재계산 주기 등은 데이터 테이블로 관리한다.

11. 디버그 및 테스트

- 역할별 색상은 0차 회색, 1차 빨간색, 2차 노란색, 3차 파란색을 권장한다.
- 직접·마지막 관측 위치, 후보 지점과 구역, 3차 목표, 시야 범위, 정지 원인, 정보 유형·신뢰도·번호와 역할 변경 이유를 표시한다.
- 필수 테스트에는 역할 판정과 전환, 최신 직접 정보 선택, 2차 그룹화, 후보 생성·완화, 분산 배치, 수색 실패와 재배정, 정보 만료, 차폐·층 구조 반영, 성능과 멀티플레이 동기화가 포함된다.

12. 구현 단계

- 1단계: 0·1·2·3차 상태, 직접 관측, 정지 원인 구분, 1차 정보 공유, 단순 3차 이동을 구현한다.
- 2단계: 2차 수집, NavMesh 후보 생성, 시야·차폐 검사와 후보 무작위 배정을 구현한다.
- 3단계: 후보 점수와 구역, 3차 분산 배치, 수색 실패·재배정, 신뢰도·만료를 구현한다.
- 4단계: 계산 주기 분산, 후보 캐싱, 경로 재계산 제한, 서버 권한 관리, 디버그 시각화와 데이터 테이블 조정을 진행한다.
- 초기 버전은 소수의 NavMesh 후보 생성과 무작위 분산 배정까지 먼저 검증하고, 이후 후보 점수와 신뢰도 시스템을 추가한다.

13. 결정 사항과 주의점

- 전역 정보 공유와 지역 행동 배정을 분리한다.
- 직접 관측 정보는 모든 예상 정보보다 우선한다.
- 플레이어 시야 정지와 다른 정지 원인을 명확히 구분한다.
- 3차 마네킹은 중앙 시스템이 지정하며 서로를 연쇄적으로 3차로 만들지 않는다.
- 모든 확률·거리·시간 수치를 코드에 고정하지 않고 데이터 테이블로 조정한다.
- 처음부터 전체 확률 모델을 구현하지 않고 단계별로 동작을 확인한다.

# 1·2·3차 마네킹 연쇄형 추적 시스템 개발 명세

## 1. 개발 목적

마네킹이 플레이어의 정확한 위치를 항상 공유하는 단순 추적 방식 대신, 각 마네킹이 플레이어 정보를 얻은 방식에 따라 역할을 구분한다.

- 1차 마네킹은 플레이어를 직접 관측한다.
- 2차 마네킹은 플레이어에게 관찰되어 정지한 상태를 위치 추정의 단서로 제공한다.
- 3차 마네킹은 전달받은 위치 정보에 따라 실제 수색을 수행한다.

플레이어를 직접 관측한 정보가 있으면 정확한 위치를 우선 사용하고, 직접 관측자가 없으면 정지한 마네킹들의 위치 관계를 이용해 플레이어의 예상 위치를 계산한다.

정보는 모든 마네킹이 공유하되, 실제 수색 행동은 지정된 3차 마네킹만 수행한다. 이를 통해 모든 마네킹이 한 지점으로 몰리는 현상을 방지한다.

---

## 2. 역할 정의

### 2.1 0차 마네킹: 기본 상태

플레이어 추적에 사용할 수 있는 유효 정보나 수색 임무가 없는 마네킹이다.

기본 행동:

- 기존 무작위 배회
- 지정 위치 대기
- 기존 범위 기반 이동
- 새로운 추적 정보 대기

전환 조건:

- 플레이어 직접 관측 → 1차 마네킹
- 플레이어의 시야로 정지 → 2차 마네킹
- 수색 목표 배정 → 3차 마네킹

### 2.2 1차 마네킹: 직접 관측자

플레이어의 위치를 직접 확인할 수 있는 마네킹이다.

판정 조건:

- 플레이어가 마네킹의 시야각 안에 있음
- 플레이어가 마네킹의 시야 거리 안에 있음
- 마네킹과 플레이어 사이에 벽·문·셔터 등의 차폐물이 없음

1차 마네킹은 다음 정보를 추적 관리 시스템에 전달한다.

- 플레이어의 현재 위치
- 플레이어의 이동 방향
- 플레이어의 이동 속도
- 마지막 관측 시각
- 정보를 생성한 마네킹
- 정보 신뢰도
- 정보 고유 번호

플레이어가 1차 마네킹을 바라보면 마네킹의 이동은 정지하지만, 해당 마네킹이 계속 플레이어를 볼 수 있다면 1차 상태와 정보 갱신은 유지한다.

여러 1차 마네킹이 동시에 플레이어를 관측하면 가장 최근에 갱신된 정보를 우선 사용한다. 관측 시각이 같다면 플레이어와 가까운 마네킹의 정보를 우선할 수 있다.

### 2.3 2차 마네킹: 간접 단서 제공자

플레이어를 직접 보고 있지는 않지만, 플레이어의 시야 안에 들어가 정지한 마네킹이다.

판정 조건:

- 플레이어를 직접 관측하지 못함
- 정지 원인이 `플레이어 시야`임
- 현재 플레이어가 해당 마네킹을 바라보고 있음

다음 원인으로 정지한 마네킹은 2차로 지정하지 않는다.

- 마네킹 플레이어의 정지 명령
- 충돌 또는 길 찾기 실패
- 애니메이션이나 피격에 의한 정지
- 대기 상태
- 스크립트 연출
- 기타 시스템 강제 정지

2차 마네킹은 플레이어의 정확한 위치를 알지 못한다. 대신 다음과 같은 위치 제약을 제공한다.

“플레이어는 이 마네킹을 볼 수 있는 위치에 있지만, 이 마네킹은 플레이어를 직접 볼 수 없는 위치에 있을 가능성이 높다.”

현재 유효한 1차 마네킹이 없을 때, 추적 관리 시스템은 모든 2차 마네킹의 단서를 조합하여 예상 위치를 계산한다.

### 2.4 3차 마네킹: 수색 실행자

1차 또는 2차 마네킹 주변의 일정 범위 안에 있으며, 추적 관리 시스템으로부터 수색 목표를 배정받은 마네킹이다.

역할:

- 직접 관측 위치 또는 예상 위치로 이동
- 다른 3차 마네킹과 후보 구역을 나누어 수색
- 목표 지점 도착 후 플레이어 탐색
- 수색 실패 결과를 추적 관리 시스템에 전달

3차 마네킹은 주변 마네킹을 추가로 3차로 지정하지 않는다. 역할 지정은 중앙 추적 관리 시스템이 담당한다.

3차 마네킹이 이동 중 플레이어를 직접 발견하면 즉시 1차 마네킹으로 전환한다.

---

## 3. 역할 판정 우선순위

마네킹의 역할은 다음 순서로 판정한다.

1. 플레이어를 직접 볼 수 있음 → 1차
2. 직접 볼 수 없고 플레이어 시야로 정지함 → 2차
3. 수색 목표가 배정되어 있음 → 3차
4. 위 조건에 해당하지 않음 → 0차

한 마네킹은 한 시점에 하나의 역할만 가진다.

예를 들어 플레이어에게 관찰되어 정지했더라도 마네킹 자신도 플레이어를 보고 있다면 2차가 아니라 1차로 판정한다.

---

## 4. 위치 정보 종류와 우선순위

### 4.1 직접 관측 정보

현재 1차 마네킹이 플레이어를 직접 보고 있을 때 생성되는 정보다.

- 위치 정확도가 가장 높음
- 모든 마네킹에게 공유
- 기존 예상 위치보다 항상 우선
- 정보가 갱신될 때 기존 예상 수색 목표를 재평가

### 4.2 마지막 관측 정보

1차 마네킹이 플레이어를 놓쳤을 때 마지막으로 저장한 정보다.

- 마지막 관측 위치
- 마지막 이동 방향과 속도
- 마지막 관측 이후 경과시간
- 시간이 지날수록 신뢰도 감소

마지막 관측 정보는 정확한 현재 위치로 취급하지 않고, 2차 마네킹의 예상 위치를 평가하는 참고 정보로 사용한다.

### 4.3 간접 예상 정보

유효한 1차 마네킹이 없을 때 2차 마네킹들의 위치 관계로 계산한 정보다.

- 하나의 확정 좌표가 아니라 여러 후보 구역으로 생성
- 후보 구역마다 별도의 신뢰도 보유
- 3차 마네킹을 후보 구역별로 분산 배치
- 수색 결과에 따라 신뢰도 변경

### 4.4 최종 우선순위

1. 현재 유효한 1차 마네킹의 직접 관측 정보
2. 2차 마네킹 단서와 마지막 관측 정보를 결합한 예상 정보
3. 마지막 관측 정보만으로 계산한 예상 위치
4. 유효한 정보가 없으면 0차 기본 행동

1차 마네킹이 하나라도 플레이어를 직접 보고 있으면 2차 마네킹의 예상 정보는 사용하지 않는다.

---

## 5. 정보 공유와 행동 범위

플레이어 위치 정보는 모든 마네킹이 받는다.

그러나 정보를 받았다는 이유만으로 모든 마네킹이 추적을 시작하지 않는다.

- 정보 공유: 전역
- 역할 지정 및 행동 전환: 지역

1차 또는 2차 마네킹의 반응 범위 안에 있는 마네킹 중 수색에 적합한 개체만 3차로 지정한다.

3차 후보가 겹치면 하나의 마네킹을 중복 지정하지 않는다. 다음 기준으로 담당 정보원을 선택한다.

1. 더 높은 우선순위의 정보
2. 정보 신뢰도가 높은 정보
3. 더 가까운 정보원
4. 현재 담당 중인 3차 마네킹 수가 적은 정보원

---

## 6. 2차 마네킹 기반 예상 위치 계산

### 6.1 2차 마네킹 수집

현재 정지 원인이 플레이어 시야인 마네킹들을 수집한다.

오래전에 정지했거나 이미 플레이어 시야에서 벗어난 개체는 제외한다. 정지 시각 차이가 큰 개체는 플레이어가 이동하면서 순차적으로 바라본 것일 수 있으므로 하나의 그룹으로 묶지 않는다.

다음 조건을 이용해 2차 마네킹을 그룹화한다.

- 정지 시각 차이
- 마네킹 사이 거리
- 하나의 플레이어 시야각 안에 함께 들어올 가능성
- 벽과 통로에 의한 공간 연결성

### 6.2 후보 위치 생성

다음 영역의 NavMesh 위에 여러 후보 지점을 생성한다.

- 2차 마네킹들을 볼 수 있는 주변 영역
- 마지막 관측 위치 주변
- 마지막 관측 이후 플레이어가 이동할 수 있는 최대 거리 안
- 플레이어가 실제로 이동 가능한 공간

후보 위치 수, 생성 간격과 탐색 반경은 데이터 테이블 값으로 관리한다.

### 6.3 후보 위치 필터링

각 후보 위치에 대해 다음 조건을 확인한다.

#### 조건 A: 플레이어가 2차 마네킹을 볼 수 있는가

- 후보 위치와 2차 마네킹 사이에 장애물이 없어야 함
- 플레이어의 최대 시야 거리 안이어야 함
- 후보 위치에서 2차 마네킹들이 플레이어 시야각 안에 들어와야 함

여러 2차 마네킹을 동시에 볼 수 있는지는 후보 위치에서 각 마네킹을 향한 방향을 구한 뒤, 모든 방향을 포함하는 최소 각도 범위가 플레이어 시야각 이하인지 확인한다.

#### 조건 B: 마네킹은 플레이어를 보지 못하는가

후보 위치가 2차 마네킹의 시야각 안에 있다면 실제 플레이어가 그곳에 있을 경우 해당 마네킹은 1차가 되어야 한다.

따라서 다음 조건을 검사한다.

- 후보 위치가 2차 마네킹의 시야각 밖인지
- 마네킹과 후보 위치 사이가 장애물로 가려져 있는지
- 마네킹의 현재 바라보는 방향과 일치하는지

#### 조건 C: 플레이어가 도달할 수 있는 위치인가

마지막 관측 위치와 시각이 있다면 다음 조건을 추가한다.

`마지막 위치에서 후보 위치까지의 이동거리 ≤ 플레이어 최대 이동속도 × 경과시간`

직선거리가 아니라 가능하면 NavMesh 경로 거리를 사용한다.

### 6.4 후보가 없는 경우

모든 조건을 엄격하게 적용했을 때 후보가 없을 수 있다. 이 경우 다음 순서로 조건을 완화한다.

1. 오래된 2차 마네킹 단서 제외
2. 서로 멀리 떨어진 2차 마네킹을 별도 그룹으로 분리
3. 마지막 관측 위치 기준 이동 가능 거리 확대
4. 일부 2차 마네킹만 설명할 수 있는 후보도 허용
5. 그래도 후보가 없으면 마지막 관측 위치 주변 수색

조건을 완화할수록 해당 후보의 신뢰도를 낮춘다.

---

## 7. 후보 위치 점수 계산

각 후보 위치에 플레이어가 존재할 가능성 점수를 부여한다.

권장 평가 요소:

- 설명할 수 있는 2차 마네킹 수
- 2차 마네킹 단서의 최신성
- 마지막 관측 위치와의 거리
- 플레이어 이동 방향과의 일치도
- 플레이어 이동 가능 시간
- 장애물과 통로 구조
- 다른 3차 마네킹이 이미 수색 중인지
- 이전에 수색했지만 플레이어를 찾지 못한 구역인지

개념식:

`후보 점수 = 시야 조건 점수 × 정보 최신도 × 이동 가능성 × 미수색 보정값`

정확한 가중치는 데이터 테이블로 조정한다.

---

## 8. 후보 구역 생성

조건을 통과한 후보 지점을 서로 가까운 것끼리 묶어 후보 구역을 만든다.

각 후보 구역은 다음 정보를 가진다.

- 구역 대표 위치
- 구역에 포함된 후보 지점
- 구역 전체 신뢰도
- 배정된 3차 마네킹 수
- 수색 완료 여부
- 마지막 수색 시각

후보 좌표를 개별적으로 무작위 선택하는 것보다 후보 구역 단위로 나누면 여러 3차 마네킹이 동일 지점으로 몰리는 현상을 줄일 수 있다.

---

## 9. 3차 마네킹 배치

### 9.1 3차 마네킹이 후보 구역보다 적은 경우

신뢰도가 높은 후보 구역부터 배치하되, 매번 같은 행동이 반복되지 않도록 신뢰도 기반 가중 무작위를 사용한다.

한 구역에 여러 마네킹을 보내기 전에 다른 미배정 후보 구역을 우선한다.

### 9.2 3차 마네킹과 후보 구역 수가 같은 경우

각 후보 구역에 한 마리씩 배치한다.

### 9.3 3차 마네킹이 후보 구역보다 많은 경우

각 후보 구역에 한 마리씩 우선 배치한 뒤, 남은 마네킹을 다음 조건에 비례하여 추가 배치한다.

- 후보 구역 신뢰도
- 후보 구역 크기
- 수색해야 할 경로 수
- 플레이어가 빠져나갈 수 있는 출구 수

### 9.4 이동 목표 선정

3차 마네킹은 후보 구역의 중심만 향하지 않는다. 구역 안의 서로 다른 지점 또는 주요 통로를 배정받는다.

배정 우선순위:

1. 플레이어가 통과할 가능성이 높은 길목
2. 아직 다른 마네킹이 배정되지 않은 지점
3. 플레이어의 마지막 이동 방향과 이어지는 지점
4. 해당 마네킹이 빠르게 도달할 수 있는 지점

---

## 10. 수색 처리

3차 마네킹이 목표 위치에 도착하면 주변을 일정 시간 탐색한다.

### 플레이어를 발견한 경우

- 해당 마네킹을 즉시 1차로 전환
- 직접 관측 정보를 모든 마네킹에게 전달
- 기존 예상 위치의 신뢰도를 제거하거나 낮춤
- 다른 3차 마네킹의 목표를 최신 위치 기준으로 재계산

### 플레이어를 발견하지 못한 경우

- 해당 후보 구역의 신뢰도 감소
- 수색 완료 상태 기록
- 아직 확인하지 않은 후보 구역으로 재배치
- 모든 후보를 확인했다면 탐색 범위 확대
- 일정 시간 동안 새 정보가 없으면 0차 상태로 복귀

---

## 11. 역할 전환 규칙

### 1차 마네킹

- 플레이어 직접 관측 유지 → 1차 유지
- 직접 관측 상실 + 플레이어 시야로 정지 중 → 2차
- 직접 관측 상실 + 수색 목표 존재 → 3차
- 직접 관측 상실 + 유효 정보 없음 → 0차

### 2차 마네킹

플레이어 시야에서 벗어나 움직일 수 있게 되면 다음 순서로 판정한다.

1. 플레이어를 직접 볼 수 있음 → 1차
2. 수색 목표를 배정받음 → 3차
3. 유효한 추적 정보가 있지만 목표가 없음 → 3차 후보
4. 유효한 정보가 없음 → 0차

### 3차 마네킹

- 이동 중 플레이어 직접 발견 → 1차
- 플레이어에게 관찰되어 정지 → 2차
- 목표 수색 실패 + 새 목표 존재 → 3차 유지
- 모든 정보 만료 → 0차

---

## 12. 권장 관리 구조

각 마네킹이 다른 모든 마네킹을 직접 검사하고 정보를 전달하지 않는다.

별도의 중앙 관리 객체를 두는 것을 권장한다.

예시 명칭:

`MannequinTrackingCoordinator`

주요 역할:

- 모든 마네킹의 현재 역할 관리
- 1차 직접 관측 정보 수집
- 2차 마네킹 목록 및 그룹 관리
- 예상 위치 후보 생성
- 후보 위치 점수 계산
- 3차 마네킹 선정 및 목표 배정
- 정보 유효시간과 신뢰도 관리
- 중복 배정 방지
- 디버그 정보 제공

멀티플레이에 적용한다면 역할 지정, 위치 정보와 수색 목표 결정은 서버 권한으로 처리한다.

---

## 13. 권장 데이터 구조

### 플레이어 추적 정보

- 정보 유형
  - 직접 관측
  - 마지막 관측
  - 간접 예측
- 위치
- 이동 방향
- 이동 속도
- 생성 시각
- 만료 시각
- 신뢰도
- 정보 생성 마네킹
- 정보에 참여한 2차 마네킹 목록
- 정보 고유 번호

### 마네킹별 추적 상태

- 현재 차수
- 현재 정지 원인
- 직접 관측 여부
- 담당 정보 번호
- 배정된 후보 구역
- 이동 목표
- 목표 도착 여부
- 마지막 역할 변경 시각
- 수색 실패 횟수

---

## 14. 전체 처리 순서

1. 각 마네킹의 플레이어 직접 관측 여부 검사
2. 직접 관측 마네킹을 1차로 지정
3. 1차 정보가 있으면 최신 직접 위치를 전역 공유
4. 1차가 없으면 플레이어 시야로 정지한 마네킹을 2차로 지정
5. 2차 마네킹을 시간·거리·시야 조건으로 그룹화
6. NavMesh에 예상 위치 후보 생성
7. 시야·차폐·이동 가능 조건으로 후보 필터링
8. 후보별 신뢰도 계산
9. 후보를 구역 단위로 묶음
10. 1차·2차 주변에서 3차 마네킹 후보 선정
11. 후보 구역과 주요 지점을 3차 마네킹에게 분산 배정
12. 수색 결과에 따라 후보 신뢰도 수정
13. 플레이어를 발견한 마네킹을 새로운 1차로 전환
14. 정보가 만료되면 마네킹을 기본 상태로 복귀

---

## 15. 의사 코드

```text
매 추적 갱신 주기:

    직접관측목록 = 플레이어를 직접 보는 마네킹 수집

    if 직접관측목록이 비어 있지 않음:
        직접정보 = 가장 최근의 직접 관측 정보 선택
        직접정보를 모든 마네킹에게 공유
        기존 예상정보보다 직접정보를 우선
        3차 마네킹의 목표 재배정

    else:
        2차목록 = 정지원인이 플레이어시야인 마네킹 수집

        if 2차목록이 비어 있지 않음:
            2차그룹목록 = 시간·거리·시야 조건으로 그룹화
            후보지점목록 = NavMesh 위에 후보 생성
            후보지점목록 = 시야·차폐·이동 가능 조건으로 필터링
            각 후보의 신뢰도 계산
            후보구역목록 = 가까운 후보끼리 그룹화
            예상정보를 모든 마네킹에게 공유
            3차 마네킹을 후보구역별로 분산 배정

        else if 마지막관측정보가 유효함:
            마지막 위치와 이동 정보로 후보구역 생성
            3차 마네킹 배정

        else:
            모든 추적정보 만료
            수색 중이 아닌 마네킹을 0차로 복귀
```

## 18. 필수 테스트 항목

1. 한 마네킹만 플레이어를 직접 보는 경우 1차로 지정되는가?

3. 여러 1차가 있을 때 최신 정보가 선택되는가?
4. 직접 관측자가 사라지면 2차 기반 예측으로 전환되는가?
5. 명령 정지와 플레이어 시야 정지가 정확히 구분되는가?
6. 한 개의 2차 마네킹만 있을 때 넓은 후보 영역이 생성되는가?
7. 여러 2차 마네킹이 있을 때 후보 영역이 좁아지는가?
8. 동시에 관찰할 수 없는 2차 마네킹들이 별도 그룹으로 분리되는가?
9. 교집합이 없을 때 조건 완화 또는 마지막 위치 수색이 작동하는가?
10. 3차 마네킹들이 동일 지점에 몰리지 않는가?
11. 2차 마네킹이 움직일 수 있게 되었을 때 1차·3차·0차 순으로 올바르게 전환되는가?
12. 3차 마네킹이 플레이어를 발견하면 즉시 1차가 되는가?

14. 새로운 직접 관측 정보가 발생하면 기존 예상 목표가 갱신되는가?
15. 오래된 정보가 만료되고 기본 행동으로 복귀하는가?
16. 많은 마네킹이 있어도 후보 계산과 경로 탐색으로 프레임이 급격히 저하되지 않는가?
17. 벽·문·셔터와 층 차이가 시야 및 후보 계산에 반영되는가?
18. 멀티플레이에서 서버와 클라이언트의 역할·목표가 일치하는가?

## 19. 구현 우선순위

### 1단계: 기본 역할 전환

- 0·1·2·3차 상태 정의
- 직접 관측 판정
- 플레이어 시야 정지 원인 구분
- 1차 정보 전역 공유
- 단순 위치로 3차 이동

### 2단계: 2차 예상 위치

- 2차 마네킹 수집
- NavMesh 후보 위치 생성
- 플레이어 관찰 가능 여부 검사
- 마네킹 시야 밖 조건 검사
- 후보 위치 무작위 배정

### 3단계: 분산 수색 개선

- 후보 점수 계산
- 후보 구역 생성
- 3차 마네킹 분산 배치
- 수색 실패와 재배정
- 정보 신뢰도와 만료 처리

### 4단계: 최적화 및 멀티플레이

- 계산 주기 분산
- 후보 위치 캐싱
- 필요한 마네킹만 경로 재계산
- 서버 권한 역할 관리
- 디버그 시각화와 데이터 테이블 조정

핵심 기능을 먼저 확인하기 위해 처음부터 완전한 확률 계산을 구현하지 않는다. 초기 버전에서는 소수의 NavMesh 후보 지점을 생성하고 무작위 분산 배정까지 구현한 뒤, 동작이 확인되면 후보 점수와 신뢰도 시스템을 추가한다.
