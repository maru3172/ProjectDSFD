  4) 외곽 배회 중 우회 이동 가능성

2. 녹음 이전 논의 요약

- 파트너의 시야 로직에 관한 구현 전달과 우려 사항을 논의했다.
- 파트너의 감시 영역은 커버 범위와 실제 시야로 구분한다.
- 커버 범위는 플레이어 진행 방향의 반대편에 형성한다.
- 실제 시야는 커버 범위 안에서 방향을 바꾸며 마네킹을 감시한다.
- 현재 구조는 기존 회의에서 논의한 방향과 동일하다.
- 가까운 소수의 마네킹과 멀리 있지만 수가 많은 마네킹 중 어느 쪽을 먼저 감시할지 우선순위를 정해야 한다.
- 현재 우선 검토하는 방식은 가까운 마네킹 두 개의 방향각을 계산하여 파트너의 시야 방향을 결정하는 것이다.

3. 주요 논의 내용

3.1 파트너 시야 대상의 우선순위

- 파트너의 실제 시야는 플레이어 후방의 전체 커버 범위 안에서 계산한다.
- 가까운 마네킹은 즉각적인 위험이 크지만, 멀리 있는 다수의 마네킹도 한 방향에서 접근하면 위험할 수 있다.
- 우선은 가까운 마네킹 두 개를 기준으로 각도를 계산해 파트너가 바라볼 방향을 정하는 기존 안을 유지한다.
- 거리와 마네킹 수가 서로 충돌하는 상황에서 어떤 요소를 우선할지는 추가 검증이 필요하다.

3.2 후방 충돌과 위험 전달

- 플레이어가 뒤로 이동하다가 파트너 또는 후방의 마네킹과 충돌하는 상황을 검토했다.
- 파트너가 후방을 모두 막지 못하는 상황을 플레이어에게 전달하는 후보 방식은 다음과 같다.
  - 화면 가장자리 또는 하단에 붉은 위험 효과를 표시한다.
  - 파트너가 자신의 시야에 마네킹이 모두 들어오지 않는다는 대사를 출력한다.
  - 플레이어가 앞으로 이동하거나 뒤를 직접 확인하도록 유도한다.
  - 위험이 극단적으로 가까워지면 플레이어를 약간 앞으로 밀어낸다.
- 단순 충돌 시 즉사시키는 방식도 언급됐으나, 벽이나 시선 방향에 따른 예외 상황이 많아 즉시 확정하지 않았다.
- 파트너가 플레이어를 밀어내는 처리는 상호작용을 강화할 수 있지만, 플레이어에게 방해물이나 짐처럼 느껴질 가능성이 있다.
- 해당 상황의 최종 처리 방식은 빠르게 결론 내기 어렵다고 판단해 다음 화요일 정기회의의 논의 안건으로 넘겼다.

3.3 마네킹 행동 범위의 형태

- 현재 디버그 화면에 표시되는 범위는 실제 로직을 이해하고 수치를 조정하기 위한 시각화다.
- 범위가 변경되는 경계에 마네킹이 진입하면 기존 행동을 즉시 중단하고 새 영역에 해당하는 행동을 수행한다.
- 직접 추적 범위와 분산·배회 범위가 시각적으로 겹치지 않도록 표현하는 방안을 논의했다.
- 중간 범위는 반원 또는 안쪽이 비어 있는 반도넛 형태로 표현할 수 있다.
- 실제 행동 로직이 동일하다면 개발 부담이 적은 반원 형태를 사용해도 괜찮다고 봤다.
- 회의 말미에는 우선 직접 추적 범위의 외경만 조절할 수 있도록 해 달라는 요구로 범위를 축소했다.
- 내경을 포함한 추가적인 디버그 표현은 가능하면 적용하되 필수 사항으로 보지 않는다.

3.4 외곽 배회 중 우회 이동

- 외곽 범위에서 무작위로 이동하는 마네킹이 플레이어 주변의 특정 영역을 통과하지 않고 돌아가게 만들 수 있는지 논의했다.
- 정적인 장애물이라면 경로 설정이 가능하지만, 플레이어와 함께 움직이는 동적 경계를 장애물처럼 처리하면 실효성이 낮거나 구현이 복잡할 수 있다는 우려가 있었다.
- 기존에 논의했던 A스타 가중치 또는 벽처럼 인식시키는 문제와 유사하므로 즉시 구현 과제로 확정하지 않았다.
- 당장 필요한 기능이 아니며, 주요 작업이 끝난 뒤 여유가 있을 때 연구하는 항목으로 남겼다.

3.5 디버그 기능과 작업 기록

- 현재까지 구현한 디버그 기능은 다음과 같이 정리했다.
  - 디버그 카메라와 플레이어 카메라를 분리했다.
  - 플레이어 카메라를 기준으로 시야 판정을 유지한다.
  - 마네킹 행동 범위를 확인할 수 있는 디버그 원을 표시한다.
  - 각 범위에 마네킹이 들어왔을 때 로그를 출력한다.
- 이번 주 작업일지에는 디버그 모드 구축과 위 기능을 중심으로 기록한다.
- 다른 팀의 진행 상황과 비교했을 때 현재 구현량은 충분하므로 작업량이 적다는 우려는 하지 않아도 된다는 의견이 있었다.

3.6 조명과 심박수 시스템

- 조명과 심박수 시스템의 구체적인 적용 방식은 이번 회의에서 확정하지 않았다.
- 다음 화요일 정기회의에서 두 시스템의 방향을 다시 논의한다.
- 화요일에 방향을 확정한 뒤 수요일부터 개발을 시작하는 일정으로 검토했다.

4. 결정 및 구현 요청 사항

- 파트너의 커버 범위는 플레이어 진행 방향의 반대편을 기준으로 한다.
- 실제 시야 방향은 우선 가까운 마네킹 두 개의 각도를 계산하는 기존 방식을 유지한다.
- 마네킹이 행동 영역의 경계를 넘으면 기존 행동을 중단하고 새 영역의 행동으로 즉시 전환한다.
- 직접 추적 범위의 외경을 조절할 수 있는 변수를 추가한다.
- 반도넛 내경 등 추가 디버그 표현은 선택 사항으로 둔다.
- 디버그 카메라, 시야 판정, 범위 표시, 진입 로그를 이번 주 작업 내용으로 정리한다.

5. 다음 회의 및 후속 검토

- 화요일 정기회의에서 후방 충돌 시 파트너와 플레이어의 상호작용 방식을 다시 논의한다.
- 화요일 정기회의에서 조명과 심박수 시스템의 구현 방향을 확정한다.
- 가까운 소수의 마네킹과 먼 다수의 마네킹 사이의 시야 우선순위를 테스트한다.
- 직접 추적 범위의 외경 조절 기능을 구현하고 디버그 화면에서 확인한다.
- 외곽 배회 마네킹의 우회 이동은 핵심 작업 이후 연구 항목으로 남긴다.

6. 미결 사항

- 파트너가 감시할 대상을 정할 때 거리와 마네킹 수에 부여할 우선순위
- 후방 마네킹이 지나치게 가까워졌을 때 경고, 밀침, 즉사 중 어떤 처리를 사용할지
- 플레이어가 벽을 등진 경우와 좌우를 바라보는 경우의 예외 처리
- 파트너의 밀침이 보호 행동으로 느껴지도록 만들 수 있는지
- 중간 범위의 디버그 표시를 반원과 반도넛 중 어느 형태로 사용할지
- 외곽 배회 중 동적으로 움직이는 플레이어 주변 영역을 우회할 필요가 있는지
- 조명과 심박수 시스템의 구체적인 입력값과 효과 단계

7. 회의록 작성 참고

- 회의 시작부터 녹음된 것이 아니며, 녹음 이전 내용은 회의 중 구두로 요약한 내용을 바탕으로 작성했다.
- 자동 음성 인식 오류와 반복 발언은 정리 부분에서 의미 중심으로 통합했다.
- 원문에서 혼용된 조력자 관련 표현은 정리 부분에서 '파트너'로 통일했다.
- 확정되지 않은 아이디어는 결정 사항과 구분해 기록했다.
