# 접근성 설정과 크래시 보고서

## 접근성 설정

타이틀 화면과 F1 게임 메뉴의 `환경설정`에서 다음 값을 변경하고 `적용`을 누르면
`GameUserSettings.ini`에 로컬 사용자별로 저장됩니다.

- 자막 표시
- 색상 외 형태·문구 정보 표시
- 색각 보정 종류와 강도
- 화면 번쩍임, 일렁임, 흔들림 강도
- UI 크기·가독성

UI 크기·가독성 배율은 PIE가 공유하는 언리얼 에디터 자체를 확대하지 않도록 스탠드얼론 및
패키지 실행에서 적용됩니다.

자막은 실제 Sound Wave 또는 대화 데이터에 자막 문장이 들어 있는 음성에 적용됩니다.
현재 프로젝트의 심박 화면 효과는 번쩍임과 일렁임 강도 설정을 사용하고, 멀티플레이 핑은
색상과 함께 `[+]`, `[!]`, `[O]` 모양 및 문구를 표시합니다. 현재 카메라 흔들림을 사용하지
않지만 0%를 적용하면 실행 중인 흔들림을 즉시 중지하며, 이후 흔들림 효과는
`UProjectProject01GameUserSettings::GetScreenShakeScale()`을 강도에 곱해야 합니다.

## 크래시 보고서 동작

실행 중인 클라이언트와 데디케이티드 서버는 다음 파일을 유지합니다.

`Saved/CrashReports/Active-<ProcessId>-<ReportId>.json`

정상 종료 시 파일은 삭제됩니다. 비정상 종료로 파일이 남으면 다음 실행에서 `Pending-...json`으로
전환하고 `/api/crash-reports`로 전송합니다. 전송이 실패하면 파일을 보존하여 다음 실행에 다시
시도하고, 성공한 경우에만 삭제합니다. Unreal 자체 크래시 덤프와 로그는 기존처럼
`Saved/Crashes`와 `Saved/Logs`에 남습니다.

전송 필드는 보고서 ID, 감지/실행 시각, 빌드 버전, 맵, 게임 모드, 서버·클라이언트 역할,
플레이어 역할, 상대 로그 경로, 진단 TestRunId, MatchId로 제한됩니다. 계정 ID, 비밀번호,
인증 토큰, 암호화 키, 명령줄과 임의 로그 본문은 전송하지 않습니다. 백엔드는 형식 검증과
IP별 분당 30건 제한 후 MySQL의 `crash_reports` 테이블에 저장합니다.

백엔드 코드나 DB 스키마를 갱신한 뒤에는 MySQL을 켠 상태에서 백엔드를 재시작해야 새 테이블과
`/api/crash-reports` 경로가 활성화됩니다.
