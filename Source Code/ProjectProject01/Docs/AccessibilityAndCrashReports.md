# 접근성 설정과 크래시 보고서

## 접근성 설정

타이틀 화면과 ESC 게임 메뉴의 `환경설정`에서 다음 값을 변경하고 `적용`을 누르면
`GameUserSettings.ini`에 로컬 사용자별로 저장됩니다.

- 자막 표시
- 색상 외 형태·문구 정보 표시
- 색각 보정 종류와 강도
- 화면 번쩍임, 일렁임, 흔들림 강도
- UI 크기·가독성

UI 크기·가독성 배율은 PIE가 공유하는 언리얼 에디터 자체를 확대하지 않도록 스탠드얼론 및
패키지 실행에서 적용됩니다.

자막은 실제 Sound Wave 또는 대화 데이터에 자막 문장이 들어 있는 음성에 적용됩니다.
현재 프로젝트의 심박 화면 효과는 번쩍임과 일렁임 강도 설정을 사용하고, 멀티플레이 핑은
색상과 함께 `[+]`, `[!]`, `[O]` 모양 및 문구를 표시합니다. 현재 카메라 흔들림을 사용하지
않지만 0%를 적용하면 실행 중인 흔들림을 즉시 중지하며, 이후 흔들림 효과는
`UProjectProject01GameUserSettings::GetScreenShakeScale()`을 강도에 곱해야 합니다.

## 크래시 보고서 동작

실행 중인 클라이언트와 데디케이티드 서버는 다음 파일을 유지합니다.

`Saved/CrashReports/Active-<ProcessId>-<ReportId>.json`

정상 종료 시 파일은 삭제됩니다. 다음 실행에서 남은 마커와 Unreal의
`Saved/Crashes/*/CrashContext.runtime-xml`에 기록된 `ProjectReportId`를 대조합니다.
실제 크래시 증거가 있는 실행만 `Pending-...json`으로 전환해 `/api/crash-reports`로 전송합니다.
아직 살아 있는 다른 게임 프로세스의 마커는 건드리지 않습니다. PIE에서는 새 마커를 만들지 않고,
이전 PIE 기록과 크래시 증거가 없는 기록은 `Saved/CrashReports/Excluded`에 보관합니다.
단순 강제 종료와 ensure는 확인된 크래시로 집계하지 않습니다. 서버의 이전 PIE 기록도 관리자 목록에서 제외합니다.

크래시 요약 JSON의 기존 필드는 유지합니다. JSON 전송 후 해당 크래시 폴더의 `.dmp`, 전체 `.log`,
`CrashContext.runtime-xml`을 첨부파일로 전송합니다. 재실행 직후에는 파일 복사가 끝나도록 최소 15초를 기다리고,
실패하면 30초 간격으로 재시도합니다. 모든 선택된 첨부파일 업로드가 성공해야 Pending JSON을 삭제합니다.
원본 덤프와 로그는 삭제하지 않습니다. 첨부파일은 개당 최대 64MiB이며, 크기를 넘긴 원본은 로컬에 남습니다.
Unreal이 파일을 생성하지 않은 경우 해당 첨부파일은 보낼 수 없습니다.
서버 도우미의 패키징 명령은 `-crashreporter`를 포함합니다. 설치형 엔진의 Shipping은
엔진 로그가 컴파일 단계에서 제거될 수 있습니다. 생성된 로그는 전체 내용을 전송하지만,
생성되지 않은 로그를 복원할 수는 없습니다. 엔진 전체 Shipping 로그가 필요하면
소스 빌드 엔진과 일치하는 로깅 설정으로 엔진·프로젝트를 함께 빌드해야 합니다.

요약 필드는 보고서 ID, 감지/실행 시각, 빌드 버전, 맵, 게임 모드, 서버·클라이언트 역할,
플레이어 역할, 상대 로그 경로, 진단 TestRunId, MatchId입니다.
첨부 로그와 XML에서는 토큰·비밀번호·비밀키와 명령줄을 가립니다. 바이너리 덤프는 진단 원본이므로
메모리 내 민감정보가 포함될 수 있으며 관리자만 다운로드할 수 있습니다.
백엔드는 요약을 MySQL `crash_reports` 테이블에, 첨부를
`Tools/ProjectProject01Backend/Saved/CrashReportArtifacts/<ReportId>/`에 저장합니다.
서버 도우미 → 서버 운영 → `크래시 보고서 보기`에서 보고서를 선택해 ZIP을 다운로드합니다.

MySQL 연결에서 `CHAR(36)` 보고서·매치 ID가 `Guid`로 반환될 수 있으므로 관리자 조회는 이를
표준 문자열로 변환합니다. 이 변환 누락으로 발생하던 크래시 목록 HTTP 500을 수정했습니다.
실행 중 백엔드가 닫혀 있으면 로컬 Pending 파일을 보존하고 다음 실행/재시도 때 전송합니다.

백엔드 코드나 DB 스키마를 갱신한 뒤에는 MySQL을 켠 상태에서 백엔드를 재시작해야 새 테이블과
`/api/crash-reports` 경로가 활성화됩니다.

## 설문 편집과 검토

서버 도우미 → 서버 운영 → `피드백/설문조사 관리`에서 문항을 추가/수정/삭제합니다.
저장된 설문을 선택하고 `선택 설문 불러오기 / 수정`을 누르면 문항을 편집기에 불러옵니다.
응답이 없는 비활성 설문은 기존 설문을 수정하며, 진행 중이거나 이미 응답이 있는 설문은
기존 응답 해석을 보존하기 위해 새 초안으로 복사합니다. 종료한 설문은 응답과 함께 삭제할 수 있습니다.

객관식은 체크 목록으로 표시합니다. 단일 선택에서는 마지막 선택만 남고,
복수 선택에서는 최대 개수를 초과할 때 오래된 선택부터 해제합니다. 최대 개수 0은 모든 선택지를 뜻합니다.
함정문항 정답은 서버에만 저장하며 클라이언트에 전달하지 않습니다. 틀린 응답은 보류 상태로 저장되어
문항 통계에서 빠집니다. `결과/통계 보기` → `보류함`에서 전체 답변을 검토한 뒤 반영 또는 삭제합니다.
문항별 그래프의 비율은 해당 문항에 답한 반영 응답자 수를 기준으로 하므로 복수 응답 합계는 100%를 넘을 수 있습니다.

`전체 설문 통계`는 모든 설문의 응답 건수·반영·보류·고유 참여 계정을 집계하며,
설문 행을 더블클릭하면 해당 설문의 상세 통계로 이동합니다.
전체 설문 통계에만 `막대 그래프`(응답 건수 비교), `비율 · 파이`(설문별 및 반영/보류 비율),
`변화 · 꺾은선`(한국 시간 제출일별 응답 건수) 탭이 있습니다. 응답이 없는 중간 날짜는 0건으로 표시합니다.
그래프 탭의 PNG 저장 버튼은 화면 밖으로 스크롤된 그래프까지 그림으로 저장합니다.
개별 설문과 문항별 기존 그래프 구성은 유지합니다.
전체 그래프에도 응답 건수와 비율을 함께 표시하고 고유 참여 계정 수는 상단에 별도로 표시합니다.
같은 계정이 여러 설문에 응답할 수 있으므로 전체 응답 건수와 참여 인원은 서로 다를 수 있습니다.
참여는 유효한 로그인 세션이 있는 계정만 가능하며, 계정당 설문별 한 번 응답합니다.
로비와 경기 ESC 메뉴의 설문 버튼은 운영자가 설문을 활성화했을 때 사용 가능합니다.
타이틀의 `피드백/설문조사`는 설문을 직접 조회하지 않고 로그인 화면으로 연결합니다. 로그인 후 로비에서
설문을 한 번 자동으로 엽니다. 제출 성공 시 `설문에 감사드립니다.` 팝업이 표시되고 확인을 누르면
로그아웃 후 타이틀로 돌아갑니다. 이 경로에서 제출하지 않고 돌아가거나 활성 설문이 없는 경우에도
로그아웃 후 타이틀로 복귀합니다. 로그인 취소·강제 로그아웃 시 자동 열기 요청은 취소됩니다.
로비에서 직접 연 경우에는 같은 팝업의 확인 또는 돌아가기를 눌러도 로그인 상태를 유지하고 로비로
복귀합니다. 기존 경기 ESC 메뉴의 설문 진입도 유지합니다. 조회 도중 로그아웃되거나 로비를 떠난 경우
늦은 응답으로 버튼을 다시 활성화하지 않으며 제출 시에도 서버가 로그인 상태와 계정별 중복 응답을 검사합니다.

설문 진입·완료 수동 확인:

1. 운영자 도우미에서 설문을 활성화하고 새 클라이언트를 실행합니다.
2. 타이틀의 설문 버튼 → 로그인 → 설문 자동 열기를 확인합니다. 제출 성공 후 감사 팝업의 확인을
   누르면 타이틀로 이동하고 다시 멀티플레이를 누르면 로그인이 필요해야 합니다.
3. 일반 멀티플레이 로그인 → 로비의 설문 버튼 → 제출 → 감사 팝업 확인은 로비로 돌아와야 하며
   방 목록·방 생성 등 인증된 기능이 계속 동작해야 합니다. 같은 설문은 다른 계정으로 검사합니다.
4. 제출 실패·필수 문항 누락에는 감사 팝업이 없어야 합니다. 같은 계정의 재제출은 서버가 차단합니다.
5. 로그인 화면에서 취소 후 일반 로그인하면 설문이 자동으로 열리지 않아야 합니다. 설문을 열어둔 채
   관리자 강제 로그아웃을 실행하면 기존 전역 세션 감시 경로로 로그인 화면에 복귀해야 합니다.

## 변경 검증

`Tools/ProjectProject01FeatureChecks`는 기존 JSON 호환·선택 제한·함정문항·비밀값 제거와
관리창 표시를 검사합니다. `Run-IsolatedIntegration.ps1`는 운영 DB와 다른
`Saved/FeatureChecks/IsolatedMySql`, 포트 23307을 사용해 설문 CRUD·보류 검토·전체 통계·덤프 업로드/다운로드를 검증합니다.
검증이 끝나면 테스트 서버는 종료됩니다. Unreal 자동화 테스트는
`ProjectProject01.CrashReports.EvidenceAndRedaction`, `ProjectProject01.Surveys.SelectionReplacement`입니다.
