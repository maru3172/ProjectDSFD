# 보안 (리버스 엔지니어링·치트 대비, 2026-11-12)

리버스 엔지니어링을 완전히 막을 수는 없다. 목표는 두 가지다: 뚫려도 돈·순위를 만들 수 없게(서버 판정), 뚫기 귀찮게(암호화·서명·감지).

## 이미 서버가 판정하는 것

| 부분 | 어떻게 |
| --- | --- |
| 크레딧·뽑기권·아이템·우편·쿠폰·상점 | 백엔드에서만 지급·차감. 구매 시 잔액을 서버가 확인 |
| 경기 결과·리더보드 | `/api/server/…`(게임 서버 인증)로만 기록, 리더보드는 `verified_match_results`만 사용, 사용자 지정 경기 제외 |
| 디버그 포인트 | 서버 설정 + 127.0.0.1 직접 접속 + 로컬 에디터 클라이언트일 때만, 전달 헤더가 있으면 거부 |
| 운영자 API | 게임 클라이언트 코드에 없음(에디터 모듈 전용) |
| 엘리베이터·방화셔터 | 클라이언트가 보낸 시점 위치를 폰과의 거리·요청 간격으로 확인 |
| 미니게임 "발걸음" | 서버가 입력을 다시 재생해 클리어 확인 |
| 배포 빌드 | 클라이언트 Shipping, PDB·.map 배포 제외, 개발용 콘솔 명령은 Shipping에서 빠짐 |

## 이번에 켠 것

### 패키지 암호화·서명
- `Config/DefaultCrypto.ini`: AES 키로 pak 인덱스·ini·uasset 암호화, RSA 서명(`bEnablePakSigning`)으로 바꿔 넣은 pak을 거부.
- **이 파일은 Git에 올라가지 않는다**(`.gitignore`). 키가 GitHub에 올라가면 암호화 의미가 없어진다.
- 백업: `%LOCALAPPDATA%\ProjectDFSD-Keys\DefaultCrypto.ini.backup`. 다른 PC에서 패키징하려면 이 파일을 `Config/DefaultCrypto.ini`로 복사한다. 키를 잃어버리면 에디터 프로젝트 설정 › Crypto에서 새로 만들면 되고(전체 빌드로 배포하므로 이전 버전과 호환 문제 없음), 서버·클라이언트를 같은 키로 함께 다시 패키징한다.
- 키 없이 패키징하면 암호화 없이 만들어진다(빌드는 됨).

### 스피드핵 감지
- `Config/DefaultGame.ini` `[/Script/Engine.GameNetworkManager]`: 클라이언트 시계가 서버보다 빨리 가면 감지하고 끌어당긴다(언리얼 기본값은 꺼짐).
- 게임 속도를 바꾸는 곳은 리플레이 재생뿐이고, 리플레이에는 서버가 없어서 영향 없음.

## 남은 것 (선택)
- **안티치트**: EOS Easy Anti-Cheat. EOS 포털 설정, 부트스트래퍼 배포, 런처 변경 필요.
- **EOS 음성 비밀값**: EOS SDK가 필요로 해 클라이언트에 넣는 값이라 꺼낼 수 있다. EOS 개발자 포털에서 이 클라이언트 정책이 음성 채팅 정도로만 좁게 되어 있는지 확인.
- **미니게임 점수**: "발걸음" 외에는 클라이언트가 점수를 보내고 서버는 시간 대비 그럴듯한지만 확인한다. 영향은 미니게임 순위뿐.
