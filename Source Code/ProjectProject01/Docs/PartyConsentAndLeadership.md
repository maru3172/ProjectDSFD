# 파티 입장 확인과 파티장 위임

## 사용자 동작

- 다른 파티원을 우클릭하면 기존 프로필 확인·귓속말·신고와 함께, 파티장에게만 `파티장 위임`·`파티 강퇴`가 표시된다. 왼쪽 클릭은 파티 메뉴를 열지 않는다. 본인 메뉴는 프로필 확인만 표시한다.
- 위임 즉시 서버 권한이 대상 파티원에게 이전된다. 방장 권한과 파티장 권한은 별개다.
- 파티장이 새 방 만들기·방 참가·별도 봇전 입장·친구 방 초대 수락을 요청하면 나머지 파티원에게 수락·거절 창을 표시한다. 파티장은 버튼을 누른 것으로 동의 처리하며 취소만 가능하다.
- 전원 수락 후 원래 파티장의 동일 요청을 한 번만 확정한다. 그전에는 방을 만들거나 누구를 이동시키지 않는다. 새 방을 만들면 파티장이 방장이다. 기존 방의 방장은 바뀌지 않는다.
- 한 명 거절, 30초 무응답, 파티원 이탈·로그아웃, 파티장 위임, 파티 구성·대상 방 정원 변경은 입장을 취소한다. 일부 파티원만 들어가지 않는다.

## 경기 준비 규칙

| 경우 | 준비가 필요한 사람 | 시작하는 사람 |
|---|---|---|
| 오픈매칭(봇 추가 포함) | 방장을 제외한 실제 경기 참가자와 관전자 전원 | 방장 |
| 관전 중인 오픈매칭 방장 | 본인은 준비 면제, 나머지 실제 참가자·관전자 전원 | 관전 중인 방장 |
| 별도 봇전 메뉴의 2인 파티 | 방장을 포함한 두 사람 모두 | 마지막 준비 요청에서 서버가 자동으로 카운트다운 시작 |
| 별도 1인 봇전 | 기존 즉시 시작 동작 유지 | 기존 동작 |

봇에는 준비 조작이 없다. 경기 플레이 정원 3명은 관전자와 별개로 사람+봇으로 채워져야 한다. 관전자 정원은 기존 최대 2명을 유지한다. 준비 변경과 게임 시작은 같은 방 행을 잠그는 트랜잭션으로 직렬화해 늦은 준비 취소가 시작 상태를 덮지 못하게 한다.

2인 봇전은 별도 시작 클릭 없이 마지막 준비 요청에서 기존 5초 카운트다운으로 진입한다. 마지막 요청자가 방장인지와 무관하다. 게임 서버 운영·정원 검증은 기존과 동일하며, 시작을 취소하면 두 사람의 준비도 해제한다. 대기 중 수동 시작 버튼은 숨기고 카운트다운·세션 대기 중 방장의 취소 버튼은 유지한다. 동시 준비 요청은 방 행부터 잠근 뒤 참가자 상태를 확인해 서로 다른 참가자 행에서 교착하지 않도록 한다.

2인 봇전의 준비·준비 취소와 두 사람의 준비 상태는 봇전 전용 화면 안에 표시한다. 오픈매칭 방 화면·방 이름·참가 코드·방 관리 화면으로 전환하지 않는다. 봇전의 뒤로가기는 대기 중인 경기 준비를 정리한다. 개인의 1인 봇전 신청·즉시 시작 흐름과 오픈매칭 방장의 수동 시작 규칙은 유지한다.

## 서버·클라이언트 경계

`case_party_admissions`와 `case_party_admission_members`가 입장 목적, 파티장, 참여 명단, 만료 시각, 동의를 기록한다. 요청 내용은 비밀번호 해시 방식으로 검증하고 평문 비밀번호를 보관하지 않는다. 타인의 동의나 완료된 동의를 재사용할 수 없다. 최종 방 입장과 동의 소비는 같은 트랜잭션에서 확정한다.

입장 확인 중에는 가벼운 상태 응답을 1초 간격으로 확인한다. 일반 파티 상태 확인은 2초 간격이며, 진행 중인 입장이 없으면 전체 로비 잠금을 획득하지 않는다. 경기 중에는 일반 파티 확인을 중단한다. 로컬 만료 시간도 단조 시계로 제한하며 로그아웃 시 재개 콜백·요청·UI를 폐기한다.

## 검증 자료

- `PartyAdmissionChecks`: 실제 HTTP/분리 MySQL에서 권한·위임·동의·거절·만료·정원 변경·친구 초대·중복 확정·준비 취소 경쟁 검사.
- `OpenObserverChecks`: 관전자 준비 및 관전 방장 예외, 기존 3+2 정원·입장 티켓 회귀 검사.
- `ProjectProject01.PartyAdmission`: 상태 수명, 파티장·본인 메뉴, 수락·대기·취소 화면 검사.
- `ProjectProject01.Operations.LobbyReadability`: 관전자·2인 봇전 방장 준비 버튼과 작은 화면 배치 확인.
- 로그·보고서: `Saved/FeatureChecks/PartyConsent*`. 화면: `Saved/PartyAdmissionUIQA` 및 `Saved/FeatureChecks/ReadabilityUI`.

운영 DB 변경·운영 서버 재시작·패키징은 수행하지 않는다. 추가 테이블은 새 백엔드의 다음 정상 시작 시 생성한다. 실제 서로 다른 PC에서의 배포 실행은 별도 확인 대상이다.
