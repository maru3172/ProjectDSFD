# 멀티 수색·정찰 연결·경기 타임라인

## 마지막 목격 지점 수색 (멀티 전용)

- 실제로 감지/시야 확인에 성공한 위치만 기억한다. 보이지 않는 대상의 새 좌표로 기억을 갱신하지 않는다.
- 대상을 놓치면 마지막 목격 위치까지 완전한 NavMesh/A* 경로로 이동한다. 부분 경로와 도달 불가능한 경로는 거부한다.
- 도착하면 기본 2.5초간 주변을 둘러본다. 이동/둘러보기를 합한 수색은 기본 최대 10초다. 경로 실패, 타임아웃, 대상 탈락/탈출/연결 해제 시 종료한다.
- 수색 중 실제 감지에 성공하면 즉시 추격한다. 시야 정지/정지 명령/직접 조작은 기존 우선순위를 유지한다.
- 수색은 플레이어의 영구 명령을 덮어쓰지 않는다. 완료하면 정찰/추종으로 복귀하며, 범위 추격(X)은 기존처럼 유효 대상이 없으면 정찰로 전환한다.
- 맵 이동·경기 종료·새 명령·추종 초기화 때 수색 기억을 정리한다. 수색 상태는 기존 빙의 마네킹 상태 UI에서 표시된다.
- 싱글 마네킹 AIController/분산 추적 코드는 수정하지 않았다.

조절: 멀티 GameMode 기본값의 `MultiplayerSearchTimeoutSeconds`(10초), `MultiplayerSearchObserveSeconds`(2.5초).

## 정찰 이동 연결

- 이전 기준은 90cm 안에서 다음 목적지로 넘어갔지만, 도착 허용 반경+캡슐 반경으로 이미 도착 처리되거나 AI 갱신 사이에 감속할 수 있었다.
- 이동 속도, 캡슐, 도착 반경, AI 갱신 간격 및 감속 거리를 포함해 전환 거리를 앞당긴다. 다음 후보 탐색도 그보다 먼저 시작한다.
- 새 이동 요청은 기존 언리얼의 속도 유지 경로를 사용하고, 같은 이동 요청을 매 틱 재시작하지 않는다. 도달 가능한 완전 경로만 허용한다.
- 의도된 주변 관찰(기존 기본 확률 25%, 1.5~3초), 생존자 시야 정지, 명시적 정지와 장애물 회피는 유지한다. 이 기능이 모든 정지·길막·네트워크 보간을 없앤다고 보증하는 것은 아니다.

## 종료 후 경기 타임라인

- 서버가 확정한 경기 시작, 실제 데카 감소, 탈락, 탈출, 연결 끊김, 재접속, 기권, 맵 이동/시작, 경기 종료를 기록한다.
- 붙잡힘/구출 시스템을 새로 만들거나 가상의 구출 사건을 넣지 않는다. 기존 점수와 승패 계산도 바꾸지 않는다.
- 진행 중에는 복제하거나 결과에 포함하지 않는다. 종료 결과 RPC로만 전달한다. 숨은 좌표·계정 ID·토큰·마네킹의 실시간 수색 위치는 넣지 않는다.
- 표시 이름은 서버가 인증한 닉네임(로컬 PIE는 PlayerState 이름)을 사용한다. 계정 ID를 표시 이름 대신 쓰지 않는다.
- 결과 화면의 **경기 타임라인** 버튼으로 시간순 기록을 스크롤하여 보고, **결과 요약** 버튼으로 돌아온다. 결과 검증 응답으로 화면이 갱신돼도 행을 중복 추가하지 않는다. 싱글 결과에는 표시하지 않는다.
- 같은 MatchId의 확정된 맵 이동에서는 서버 GameInstance로 이어간다. 맵 로딩 시간은 제외하며 각 맵의 실제 진행 시간을 누적한다. 새 경기는 이전 기록을 초기화한다.
- 최대 128건, 이름 48자/부가 내용 96자로 제한한다. 최초 사건과 최근 기록을 유지하고 중간 생략 건수를 UI에 알린다. 매 프레임 기록·리플레이·영상 저장이 아니다.
- 영구 DB 저장/과거 경기 조회는 추가하지 않았다. 결과 화면에서 확인하는 이번 경기의 메모리 기록이다. 기존 리더보드 데이터/등록 방식은 유지한다.

## 적용

결과 RPC 형식이 바뀌어 네트워크 프로토콜을 **2**로 올렸다.

1. 최신 소스로 클라이언트와 데디 서버를 모두 재패키징한다. 기존 클라이언트/데디와 혼용하지 않는다.
2. 백엔드도 최신 빌드·appsettings.json을 함께 반영한 뒤 안전한 시점에 재시작한다. 별도 환경변수/외부 설정에서 `Compatibility:NetworkProtocolVersion`을 지정했다면 2로 맞춘다.
3. 실행 중인 서버, 운영 DB, 기존 배포 폴더는 이번 작업에서 임의로 재시작/덮어쓰지 않는다. 새 패키지 배포/업데이트 게시는 별도로 해야 한다.

## 확인 방법

1. PIE MultiplayTest에서 클라이언트 3명으로 시작한다. 마네킹이 생존자를 감지하게 한 뒤 벽 뒤로 숨는다. 숨은 생존자의 새 좌표가 아니라 마지막 목격 위치를 수색해야 한다.
2. 다시 감지되면 추격, 끝까지 보이지 않으면 수색 후 기존 정찰/추종으로 복귀해야 한다. 수색 중 생존자가 바라보면 정지 규칙이 그대로 작동해야 한다.
3. 정찰 연속 이동을 관찰한다. 목적지마다 기계적으로 완전히 정지하는 현상은 줄어들어야 한다. 가끔 주변을 둘러보는 정지는 의도된 행동이다.
4. 실제 피해/탈락/탈출/재접속/기권을 발생시킨 뒤 경기 종료 화면에서 타임라인을 연다. 진행 중에는 사건 목록이 공개되지 않아야 한다.
5. 맵 전환 후 경기 종료 시 이전 맵 기록이 남는지, 방 복귀 후 새 경기는 새 기록만 있는지 확인한다.

자동 검사는 시간순/메모리 상한/문자열 길이/직렬화, 종료 전 비공개/종료 후 결과 포함/동일 매치 맵 이동/새 경기 초기화, 결과 UI 토글 및 수색의 기억 좌표/시간 제한/경로 실패/정지 명령을 검사한다. 헤드리스 테스트는 실제 맵의 경로 품질, 보행 연출과 외부 PC 실게임을 대신하지 않는다.
