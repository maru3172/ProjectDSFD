# 생존자 비상 엘리베이터

하차 자동 닫힘 최종 검사: `Saved/ReviewRemediation/TutorialConfirmAndArrivalClose-Final-20261020/index.json`의 `ProjectProject01.Elevator.Flow/Audio` 성공(경고/실패 0). 서버 권위 하차 인원·문 앞 캡슐/여유 범위·한 명이 남은 경우 대기·사망 관전자 제외·하차 벨 상태·닫힘 보간·재진입 시 현재 위치에서 재열림·착륙 위치 정지와 추가 이동/모터 없음 검사를 포함한다. 실제 귀로 듣는 체감과 여러 PC에서 문 애니메이션 동기화는 별도 확인 대상이다.

## 동작

- 멀티 경기 진행 중 다른 생존자가 **사망/포획으로 탈락하거나 기권 확정**된 경우에만 호출 가능.
- `TransitionWaiting`(층 이동 트리거에 먼저 도착), `Escaped`(탈출), 재접속 유예 중인 연결 끊김은 활성화 사유가 아니다.
- 바깥 버튼 볼륨에 기존 상호작용 시선이 적중하고 상호작용 키를 눌러 호출.
- 기본 **20초 대기(작은 우웅 운행음) → 4초 상승(운행음이 서서히 잦아듦) → 띵/1.5초 문 열림**.
- 내부에 있는 생존자가 내부 버튼을 바라보고 상호작용 → **띵/2.5초 문 닫힘 → 2초 하강 운행음 → 운행음이 잦아들며 1.5초 화면 전체 암전 → 서버 맵 이동**. 하강 운행음 구간에는 아직 맵 이동/암전을 시작하지 않는다.
- 목적지에서 생존자의 Pawn을 처음부터 엘리베이터 내부에 생성. 기존 준비 완료 페이드인(0.6초) 경로를 사용.
- 새 맵의 경기 준비가 완료되면 기본 2초 운행음이 점점 잦아든 후 띵/문 열림. 탈락자는 되살리지 않으며 기존 관전/마네킹 재배치 규칙을 유지.
- 기본 저음 모터음과 벨은 코드에서 합성하므로 외부 WAV/CSV 파일 없이 패키징된다. 서버는 소리를 재생하지 않고 클라이언트가 복제된 단계를 따라 재생한다.

## 배치

1. 에디터를 닫고 `ProjectProject01Editor Win64 Development`를 빌드한 뒤 다시 연다.
2. 액터 배치에서 `ProjectProject01Elevator`를 출발 층에 배치한다. 필요하면 이 클래스를 부모로 하는 블루프린트를 만든다.
3. Details의 **Level Transition → Destination Level**에 실제 1층 레벨을 지정한다. `Destination Arrival Id`는 기본 `Elevator_1F` 또는 영문/숫자/`_`/`-`로 지정한다(최대 64자).
4. `CallButtonVolume`(바깥 호출 버튼), `InsideButtonVolume`(내부 버튼)의 위치/크기를 조정한다. `Visibility` 트레이스를 막는 볼륨이다. 벽/문에 버튼이 묻히지 않게 한다.
5. `CabinVolume`은 생존자의 캡슐 중심이 내부에 들어와야 하는 영역이다. `ArrivalSpawn`은 도착 캡슐 중심/시선 방향이다. 기본 위치는 바닥 위 100cm이며 출입구는 액터의 +X 방향이다.
6. 목적지 1층에도 이 액터를 배치하고 **Arrival Only**를 켠다. **Arrival Id**는 출발 쪽 `Destination Arrival Id`와 같게 설정한다. 동일 ID의 도착 엘리베이터는 맵에 하나만 둔다.

   도착 후 문이 열리고 생존자가 완전히 내리면 띵 소리와 함께 문이 닫힌다. 여러 생존자가 탑승하면 전원 하차를 기다리며, 사망/관전자·마네킹은 인원으로 세지 않는다. `Arrival Exit Clearance`는 캡슐 바깥에 추가하는 문 앞 안전 여유(cm, 기본 50)다. 닫히는 중 생존자가 문 앞으로 다시 들어오면 현재 문 위치에서 자연스럽게 다시 연다. 하차 후 닫힘은 하강·모터음·추가 맵 이동 없이 착륙 위치에서 종료한다. 도착 Pawn이 아직 생성되지 않은 빈 객실은 미리 닫지 않는다.
7. 기본 바닥/벽/문/버튼은 엔진 Cube를 이용한 교체 가능한 테스트 외형이다. 블루프린트에서 메시/재질을 바꾸고, 이동 부품은 `CabinRoot` 밑에 둔다. 문은 `LeftDoor`, `RightDoor`의 상대 위치를 기준으로 열린다.
8. 출발 층에는 실제 승강로와 열린 바닥 공간을 마련한다. 기본 상승 시작점은 도착 높이보다 **1200cm(12m) 아래**다. `Below Landing Depth`에서 깊이(cm)를 바꾼다. 기존 맵 바닥이 승강로를 덮으면 바닥을 통과해 보이므로 공간을 비워야 한다.
9. 새 목적지 맵을 만들었다면 패키징 대상 `MapsToCook`에도 추가한다. 목적지 미지정/누락 시 호출이 활성화되지 않는다. 이번 작업은 기존 맵/블루프린트 바이너리를 수정하거나 패키징하지 않는다.

`Call Delay Seconds`, `Rise Seconds`, `Door Seconds`(열림), `Close Door Seconds`, `Descent Sound Seconds`, `Departure Fade Seconds`, `Arrival Ride Seconds`, `Below Landing Depth`, 좌/우 문 오프셋을 조정할 수 있다. 기존 `Below Landing Offset`은 수평 X/Y 보정만 사용하며 Z 대신 새 깊이 설정을 사용한다. 기존 배치에도 기본 12m가 적용된다.

## 안전 처리와 테스트

- 단순히 진입하는 것만으로는 출발하지 않는다. 기존 이동 영역과 엘리베이터의 자동 진입 처리도 분리했다.
- 서버가 소유 플레이어의 시선/거리/버튼/역할/생존 상태를 다시 검사하고, 요청 연타를 제한한다. 호출/문 이동 중 중복 상호작용은 무시한다.
- 멀티 클라이언트의 버튼 판정은 소유자에게 복제된 `SurvivorState == Active`를 사용한다. `AuthenticatedRole`은 서버 전용 값이므로 클라이언트에서 요구하지 않는다. 실제 호출/출발 요청에서는 서버가 인증된 생존자 역할까지 다시 검증한다. 이 수정은 멀티 엘리베이터에만 적용하며 기존 싱글 상호작용은 바꾸지 않는다.
- 에디터 PIE는 원래 게임 참가 티켓 없이 역할을 배정하므로 서버에서도 `AuthenticatedRole`이 비어 있을 수 있다. 이때만(`WITH_EDITOR` 및 `WorldType == PIE`) GameMode의 등록된 경기 기록에서 같은 컨트롤러/Pawn의 생존자 역할, 활동 상태, 연결 상태, 기권 여부를 확인한다. 미등록 Pawn이나 마네킹은 허용하지 않으며, 패키징된 게임에는 이 예외가 컴파일되지 않는다.
- 멀티 RPC는 F를 누른 순간의 카메라 원점/방향도 보낸다. 서버의 원격 카메라 캐시로 재조준하지 않고 이 시선으로 버튼을 직접 검사한다. 카메라와 Pawn 사이 최대 400cm, 카메라 경로의 Visibility 차폐, 서버 설정 상호작용 거리(최대 500cm), 실제 버튼 적중, 내부 탑승 여부, 역할/경기/목적지 검사를 모두 통과해야 한다. 검사 후 다시 오래된 서버 카메라로 재검사하지 않는다.
- 진단 로그: `[ElevatorInteraction] Sending click`은 클라이언트 요청, `Server received click`은 서버 수신, `Rejected ... reason=...`은 서버 거절 사유, `[Elevator] ... phase=...`는 서버 단계 변경이다. 호출이 수락되면 `CallDelay` → 20초 후 `Rising` → `Opening` → `Open` 순서로 기록된다. 내부 버튼 수락 시 `Closing`이 기록된다.
- 문을 닫는 동안 생존자가 나가거나 죽으면 출발하지 않고 문을 다시 연다.
- 문을 닫은 후 하강 운행음 구간에 나가거나 죽어도 이동하지 않는다. 암전이 끝난 뒤에만 실제 맵 이동을 요청한다.
- PIE에서도 이동 직전에 `net.AllowPIESeamlessTravel`을 활성화해 새 경기로 초기화되지 않도록 한다. 티켓 없는 PIE의 사용자/역할 식별자는 기존 서버 경기 기록에서 인계하며, 이 처리는 에디터 전용이다. 사망자는 관전자로, 기권자는 기권 상태로 유지하고 다음 맵에서 Pawn을 재생성하지 않는다. 원래의 일반 트리거/싱글 페이드 기본 시간은 0.6초 그대로다.
- 이동이 거절되면 기존 트리거의 롤백 경로로 입력/충돌/페이드를 복구하고 문을 다시 연다. 기존 30초 이동 감시와 최대 120초 엔진 비동기 로딩 감시를 재사용한다.
- PIE 3클라이언트로 두 생존자 모두 활동 중에는 호출 불가, 한 명 탈락/기권 후 호출 가능, 층 이동 대기/탈출/단순 연결 단절로는 호출 불가를 각각 확인한다.
- 호출 후 20초 동안은 상승하지 않지만 아래쪽에서 운행음이 나고, 상승하면서 잦아들어 도착 직전 충분히 작아진 뒤 벨/문 열림으로 전환되는지 확인한다.
- 내부 버튼 연타/문 닫힘 중 나가기/출발 직전 사망, 목적지 내부 스폰/페이드/도착음/문 열림까지 실제 연결된 맵으로 확인한다.
- 자동 검사 이름: `ProjectProject01.Elevator.Flow`, `ProjectProject01.Elevator.Audio`. 맵 배치 후 실제 멀티 맵 이동/오디오 체감 검증은 별도로 필요하다.

- 기존 맵/블루프린트 바이너리는 수정하지 않았고 패키징도 실행하지 않았다. 배치/연결 후 배포할 때에는 변경된 C++가 들어가도록 클라이언트와 전용 서버를 모두 새로 빌드/패키징한다.
