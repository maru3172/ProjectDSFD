# 탐사 메인 퀘스트와 거래 확인

## 게임 UI

- 개인 조사 파일 → **성장 기록 → 메인 퀘스트**에서 계정별 ‘탐사’ 진행, 조건, 누적 이야기를 확인한다.
- 기본 흐름: 생존자 튜토리얼 → 생존자로 경기 1회 플레이 → 3층 탈출 → 2층 탈출 → 최종 탈출 → 마네킹 튜토리얼 → 포획 → 마네킹 승리. 해당 경기 플레이 단계는 승패와 무관하게 생존자 접속 허가 시 집계하며 마네킹 경기는 제외한다. 카운트다운 취소·서버 미준비로 허가되지 않은 시작은 집계하지 않는다.
- 플레이 조건은 경기 종료를 기다리지 않는다. 접속 티켓 응답의 퀘스트 진행도·새 알림을 즉시 적용하며, 이전 계정 조회 응답이 진행도를 되돌리지 않도록 처리한다. 포획·최종 탈출도 실제 발생 시 완료한다. 명시적인 경기 완료·승리 조건은 검증된 경기 결과를 기다린다.
- 앞 단계를 완료해야 다음 단계 하나가 공개된다. 잠긴 단계의 제목·조건·스토리는 서버 응답에서도 공개하지 않는다. 완료한 단계는 다시 열람할 수 있다.
- 튜토리얼 두 단계만 건너뛰기가 가능하다. 연습모드·마지막 실전만 다시 연습하기는 튜토리얼 완료로 집계하지 않는다.
- 조건 하나만 끝나면 `조건 완료`와 조건명을 표시한다. 그 조건으로 단계도 끝나면 조건 알림을 생략하고 `단계 완료`만 표시한다.
- 마지막 단계 완료와 퀘스트 전체 완료는 동일 알림에 합치지 않는다. 우하단 알림 대기열에서 앞 알림이 사라지고 0.5초 뒤 다음 알림이 나온다.
- 알림 윗줄은 조건 완료·단계 완료·퀘스트 전체 완료를 구분하고, 아랫줄에는 기존대로 완료한 목표명을 표시한다.
- 로그인 후 튜토리얼 완료는 계정 조회/저장 요청과 겹쳐도 세션 안에 보관하고 재전송한다. 로그아웃 시 보류 보고를 지워 다른 계정으로 넘기지 않는다.
- 튜토리얼 완료/스킵 응답의 `questNotices`는 이번 요청으로 생성한 알림만 포함한다. 첫 조회의 과거 기록 생략과 실제 방금 완료한 알림을 분리하며, 재전송 성공은 알림을 중복 생성하지 않는다.
- 알림은 발생 즉시 게임 뷰포트에 연결하고, 화면 정리 과정에서 제거되면 다시 연결한다.
- 일반 저장 성공에는 ‘처리되었습니다.’를 표시하지 않는다. 서버의 일반 성공 응답에서도 문구를 빼며, 상태 표시부는 이전 서버가 보내는 동일 문구도 숨긴다. 오류·구매/획득 확인·퀘스트 완료 알림은 유지한다.
- 개인 기록 저장 중에는 투명한 입력 차단층으로 중복 클릭만 막는다. 본문을 비활성화해 전체가 어두워졌다 밝아지는 연출을 만들지 않는다.
- 랜덤·오픈매칭 역할 선택은 저장 중에도 같은 선택칸을 유지한다. 빠른 연속 선택은 마지막 선택을 모아 순서대로 저장하며, 이전 응답으로 되돌리지 않는다. 오류 시 서버에 저장된 역할로 복귀하고, 로그아웃 시 미전송 선택을 폐기한다. 역할 저장 중에는 경기 시작을 제한한다.
- 참가자 이름·준비·역할 공개 상태는 기존 행의 글만 갱신한다. 개인 기록·친구 목록은 상태 문구나 요청 시작/종료만으로 재생성하지 않고, 같은 조건의 리더보드 새로고침과 결과 사건 기록 갱신도 기존 내용을 유지한다.
- 다른 단계의 과거 이벤트를 재전송해 이후 단계를 건너뛸 수 없다. 새 경기 또는 새로운 조건 사건으로 다음 단계를 진행한다.

## 운영

- 서버 운영 → 보상·시즌 항목의 **메인 퀘스트·스토리**에서 기본 이야기, 단계 제목·완료 이야기, 조건·필요 횟수를 수정한다.
- 이야기는 빈 상태가 기본값이다. 운영자가 작성한 기본 이야기와 완료한 단계의 이야기만 클라이언트에 공개한다.
- 퀘스트 목표 아래에 별도 스토리 읽기 영역을 확보한다. 기본 이야기와 완료한 단계의 이야기를 문단으로 이어 표시하고, 긴 글은 해당 읽기 영역 안에서 스크롤한다.
- **스토리 CSV 내보내기 → 스토리 열 수정 → 스토리 CSV 불러오기 → 저장**으로 파일 편집을 적용한다. 편집 원본은 `Docs/QuestStories/MainQuestStories.csv`이며 `base`가 기본 이야기, 나머지가 각 단계 완료 후 이야기다. 조건·진행도는 CSV로 변경하지 않는다.
- CSV는 UTF-8로 저장한다. 쉼표·따옴표·여러 줄 이야기는 CSV 인용 규칙을 따른다. 내보내기는 Excel에서 한글을 읽을 수 있도록 UTF-8 BOM을 붙인다. 누락·중복·알 수 없는 단계가 있으면 전체 가져오기를 거부한다.
- 공개 API가 아닌 관리자 인증을 사용하는 `/api/admin/main-quest`를 통해 저장한다. 동시 편집은 revision으로 충돌을 감지한다.
- 층 탈출은 `/Game/MyProject/Level/MultiplayTest`(3층), `MultiplayTest1`(2층)에서 서버가 보고한다. 실제 경기 참가자·역할·배정 서버 포트·발생 시각을 확인하며, 관전자·다른 계정의 직접 보고는 인정하지 않는다.
- 포획·최종 탈출은 `/api/server/main-quest/event`에서 실제 참가 역할·배정 서버 포트·발생 시각을 검증한다. 누적 포획 보고는 중복·역순 도착에도 한 번만 집계한다. 검증된 경기 결과는 앞선 보고가 지연되었을 때 복구하며, 이미 집계한 조건을 중복 반영하지 않는다.
- 조건 유형 `Match`·`SurvivorMatch`는 시작, `MatchComplete`는 경기 완료, `MannequinWin`은 마네킹 승리를 뜻한다. 사용자 지정 경기는 기존 공식 기록 제외 규칙을 따른다. 시작 조건 처리로 경험치·재화·경기 보상을 미리 지급하지 않는다.
- 층 탈출·포획·최종 탈출 보고는 기존 결과 아웃박스에 보관해 통신 실패·서버 종료 후 복구 시 재전송한다.

## 구매·뽑기·업적 보상

- 1/5개 뽑기는 `계속 진행하시겠습니까?`, 상점 구매·포인트 재화 교환은 `구매하시겠습니까?`를 표시한다.
- 뽑기와 포인트 구매의 ‘오늘 하루 다시 묻지 않기’는 독립적으로 적용한다. 계정·서버별 클라이언트 설정이며 다음 로컬 날짜가 되면 다시 확인한다.
- 일일·주간 미션 변경도 `변경하시겠습니까?`와 동일한 체크박스·예/아니오를 표시한다. 미션 변경 확인 생략은 PvP·봇전과 일일·주간에 공통이며 뽑기·구매 설정과 독립적이다. 예를 누르기 전에는 재화를 쓰지 않고, 대기 중 미션 기간·변경 횟수·완료 상태가 바뀌면 변경을 취소한다.
- 꾸미기 장착·대표 배너 지정·배너 전시/해제에는 `적용하시겠습니까?`와 동일한 체크박스·예/아니오를 표시한다. 컬렉션 외에 상점의 보유 상품 장착, 레벨 보상 테두리, 배틀패스 완성 봉인 장착도 동일하다. 확인 생략은 코디 적용 전용으로 저장하며 다른 확인창 설정과 섞지 않는다.
- 체크한 뒤 ‘아니오’를 눌러도 그날의 확인 생략 선택은 기억하지만 현재 거래는 실행하지 않는다. 확인 대기 중 계정이 바뀌면 이전 계정 거래를 실행하지 않는다.
- 구매 성공 후 실제 상품/재화와 `구매하셨습니다`, 업적 보상 수령 성공 후 실제 보상과 `획득하셨습니다` 및 확인 버튼을 표시한다. 서버 실패에는 성공창을 표시하지 않는다.
- 업적은 달성과 보상 수령을 분리한다. 조회·병합만으로 보상을 지급하지 않으며, 보상 받기 요청은 서버에서 달성을 확인하고 한 번만 지급한다.
- 업적·도전과제 보상 받기에는 진행 확인창을 띄우지 않는다. 수령 성공 후 획득창만 표시한다.
- 이전에 자동으로 받은 보유 아이템은 유지하고 이미 수령한 상태로 취급한다.

- `Run-IsolatedIntegration.ps1 -FrontendOnly`: 운영 DB와 분리된 23307 포트에서 거래·업적·메인 퀘스트·최초 안내 API를 검사한다. 봇 AI 시뮬레이션은 실행하지 않는다.
- `ProjectProject01.CaseRecords.RenderPages`: 확인창·구매/획득창·퀘스트·업적 UI 및 날짜 변경·계정 변경 시 확인 동작을 검사한다.
- `ProjectProject01.CaseRecords.AchievementToast`: 업적 알림과 퀘스트 조건/단계/전체 완료 알림의 순서·표시 조건명·간격을 검사한다.
