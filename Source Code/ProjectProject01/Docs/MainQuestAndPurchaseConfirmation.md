# 탐사 메인 퀘스트와 거래 확인

## 게임 UI

- 개인 조사 파일 → **성장 기록 → 메인 퀘스트**에서 계정별 ‘탐사’ 진행, 조건, 누적 이야기를 확인한다.
- 기본 흐름: 생존자 튜토리얼 → 경기 1회 플레이 → 3층 탈출 → 2층 탈출 → 최종 탈출 → 마네킹 튜토리얼 → 포획 → 마네킹 승리.
- 앞 단계를 완료해야 다음 단계 하나가 공개된다. 잠긴 단계의 제목·조건·스토리는 서버 응답에서도 공개하지 않는다. 완료한 단계는 다시 열람할 수 있다.
- 튜토리얼 두 단계만 건너뛰기가 가능하다. 연습모드·마지막 실전만 다시 연습하기는 튜토리얼 완료로 집계하지 않는다.
- 조건 하나만 끝나면 `조건 완료`와 조건명을 표시한다. 그 조건으로 단계도 끝나면 조건 알림을 생략하고 `단계 완료`만 표시한다.
- 마지막 단계 완료와 퀘스트 전체 완료는 동일 알림에 합치지 않는다. 우하단 알림 대기열에서 앞 알림이 사라지고 0.5초 뒤 다음 알림이 나온다.
- 다른 단계의 과거 이벤트를 재전송해 이후 단계를 건너뛸 수 없다. 새 경기 또는 새로운 조건 사건으로 다음 단계를 진행한다.

## 운영

- 서버 운영 → 보상·시즌 항목의 **메인 퀘스트·스토리**에서 기본 이야기, 단계 제목·완료 이야기, 조건·필요 횟수를 수정한다.
- 이야기는 빈 상태가 기본값이다. 운영자가 작성한 기본 이야기와 완료한 단계의 이야기만 클라이언트에 공개한다.
- **스토리 CSV 내보내기 → 스토리 열 수정 → 스토리 CSV 불러오기 → 저장**으로 파일 편집을 적용한다. 양식은 `Config/MainQuestStories.csv`이며 `base`가 기본 이야기, 나머지가 각 단계 완료 후 이야기다. 조건·진행도는 CSV로 변경하지 않는다.
- CSV는 UTF-8로 저장한다. 쉼표·따옴표·여러 줄 이야기는 CSV 인용 규칙을 따른다. 내보내기는 Excel에서 한글을 읽을 수 있도록 UTF-8 BOM을 붙인다. 누락·중복·알 수 없는 단계가 있으면 전체 가져오기를 거부한다.
- 공개 API가 아닌 관리자 인증을 사용하는 `/api/admin/main-quest`를 통해 저장한다. 동시 편집은 revision으로 충돌을 감지한다.
- 층 탈출은 `/Game/MyProject/Level/MultiplayTest`(3층), `MultiplayTest1`(2층)에서 서버가 보고한다. 실제 경기 참가자·역할·배정 서버 포트·발생 시각을 확인하며, 관전자·다른 계정의 직접 보고는 인정하지 않는다.
- 경기 완료·최종 탈출·포획·승리는 기존 검증 경기 결과에서 집계한다. 사용자 지정 경기는 기존 공식 기록 제외 규칙을 따른다.
- 층 탈출 보고는 기존 결과 아웃박스에 보관해 통신 실패·서버 종료 후 복구 시 재전송한다.

## 구매·뽑기·업적 보상

- 1/5개 뽑기는 `계속 진행하시겠습니까?`, 상점 구매·포인트 재화 교환은 `구매하시겠습니까?`를 표시한다.
- 뽑기와 포인트 구매의 ‘오늘 하루 다시 묻지 않기’는 독립적으로 적용한다. 계정·서버별 클라이언트 설정이며 다음 로컬 날짜가 되면 다시 확인한다.
- 체크한 뒤 ‘아니오’를 눌러도 그날의 확인 생략 선택은 기억하지만 현재 거래는 실행하지 않는다. 확인 대기 중 계정이 바뀌면 이전 계정 거래를 실행하지 않는다.
- 구매 성공 후 실제 상품/재화와 `구매하셨습니다`, 업적 보상 수령 성공 후 실제 보상과 `획득하셨습니다` 및 확인 버튼을 표시한다. 서버 실패에는 성공창을 표시하지 않는다.
- 업적은 달성과 보상 수령을 분리한다. 조회·병합만으로 보상을 지급하지 않으며, 보상 받기 요청은 서버에서 달성을 확인하고 한 번만 지급한다.
- 업적·도전과제 보상 받기에는 진행 확인창을 띄우지 않는다. 수령 성공 후 획득창만 표시한다.
- 이전에 자동으로 받은 보유 아이템은 유지하고 이미 수령한 상태로 취급한다.
