# 멀티 마네킹 위장·싱글 저장소 미리보기

## 전시물 위장

- 멀티 정찰 중 다음 목적지가 준비된 전환 지점에서 기본 12% 확률로 위장 위치 탐색을 시도한다. 그 자리에서 갑자기 서는 방식은 사용하지 않는다. 수동 마커/태그/전시 위치 액터 배치는 필요 없다.
- 기본 12m 안에서 최대 8개 NavMesh 후보를 검사한다. 주변 벽을 4방향으로 조사해 벽·모서리 옆 또는 넓은 벽 사이 통로의 중심을 추정한다. 평탄한 바닥, 신체보다 여유 있는 빈 공간, 완전한 A* 경로가 있는 곳만 허용한다. 의미 있는 지형을 찾지 못하거나 좁거나 막힌 경우에는 건너뛴다.
- 선택 전에 현재 마네킹과 후보 지점 모두 살아 있는 생존자에게 보이지 않는지 확인한다. 시야각과 몸통/상하/좌우 표본에 대한 차폐 검사를 사용한다. 이동 중 목적지가 보이거나 본체가 관찰되면 위장 접근을 취소한다. 다른 마네킹이 예약한 지점 2.5m 안쪽도 제외한다.
- 선택한 위치로 먼저 이동한다. 도착 후 다시 시야를 확인하고 열린 공간/복도 방향으로 초당 최대 90도씩 방향을 맞춘 뒤 3~6초간 선다. 접근/방향 맞춤은 기본 15초 제한이며, 실패하면 기존 정찰을 잇는다. 위치 이동/순간이동으로 위장을 만들지 않는다.
- 지속 시간에 더해 20초 재사용 간격을 두고 실패한 후보 탐색은 5초간 쉬어간다. 위장 종료 후 다음 경로는 준비한 것을 이어 쓴다. 생존자가 나중에 시선을 어디로 돌릴지는 예측하지 않으며, 현재 시야를 계속 재검사한다.
- 생존자가 바라보면 기존 시야 정지 규칙이 우선하며, 시선을 돌리면 위장 대기를 끝낸다. 아무도 보지 않아도 제한 시간이 지나면 정찰을 재개한다.
- 실제 감지/추격/마지막 목격 지점 수색은 위장보다 우선한다. 숨은 생존자의 좌표를 새로 알아내거나, 벽을 뚫고 감지하거나, 플레이어의 영구 명령을 바꾸지 않는다.
- 정지/추종/직접 조작 명령에서는 새 위장을 시작하지 않는다. 경기 종료·맵 이동 때 초기화된다. 빙의 마네킹 상태 UI에 `전시물 위장`을 표시한다.
- 지능적인 매복 장소 선정이나 새 애니메이션은 아니다. 기존 서 있는 자세를 쓰는 정찰 연출이며, 싱글 AI/분산 추적은 변경하지 않는다.
- 조절: 멀티 GameMode 기본값의 `MultiplayerDisguiseChance`, `MultiplayerDisguiseMinSeconds`, `MultiplayerDisguiseMaxSeconds`, `MultiplayerDisguiseCooldownSeconds`, `MultiplayerDisguiseSearchRadius`, `MultiplayerDisguiseApproachTimeoutSeconds`. 확률을 0으로 하면 새 위장을 시작하지 않는다. 지형 기반 추정이므로 전시 장소의 미술적 의미나 문 액터의 의미까지 이해하는 AI는 아니다.

## 세 저장소 미리보기

- 자동/수동 체크포인트를 저장할 때 현재 카메라 위치/방향/FOV와 후처리를 참고해 게임 장면을 320×180 PNG로 한 번 렌더링한다. 메뉴, 마우스 커서, 확인창 등 UMG는 넣지 않는다.
- 타이틀의 저장소 선택, ESC 수동 저장소 선택, ESC 다른 저장소 불러오기에 160×90 미리보기와 맵 이름·저장 시각(한국 시간)·체크포인트·데스카운트를 표시한다.
- 이미지 슬롯은 가로/세로 Fill로 지정하여 기본 브러시 32×32가 왼쪽 위에만 보이지 않게 한다. 이미지가 유효하면 대체 문구를 숨기고, 없으면 12pt 대체 문구만 표시한다. 기존 이미지도 다시 저장하지 않고 올바른 크기로 표시된다.
- 이미지는 별도 PNG 파일이 아니라 해당 `.sav` 내부에 담는다. 슬롯 덮어쓰기·백업·복구·삭제·새 게임과 함께 처리되어 예전 이미지가 따로 남지 않는다. 서버 업로드는 하지 않는다.
- 저장 형식은 v5. v1~v4 저장 파일을 유지하며 이관하고, 이미지가 없는 기존 저장은 `미리보기 없음`으로 표시한다. 다음 정상 저장부터 이미지가 생긴다.
- 이미지 CRC/PNG 형식/320×180 크기/512KiB 상한을 확인한 뒤 디코딩한다. 이미지 데이터는 게임 상태 무결성과 분리되어, 이미지만 손상되면 대체 표기하고 체크포인트는 불러올 수 있다.
- 렌더러 없는 테스트, 데디 서버, 유효 카메라가 없는 경우에는 이미지 없이 처리한다. 촬영 실패만으로 게임 상태 저장을 취소하지 않는다.
- 매 프레임 캡처하지 않지만 저장 순간에는 작은 장면 렌더와 GPU 읽기 비용이 든다. 해상도/후처리 이력 차이로 화면 원본과 픽셀 단위로 동일한 이미지를 보장하지 않는다.

## 플레이 확인

1. 멀티 PIE에서 정찰을 관찰한다. 위장은 회전 없이 잠깐 서 있고, 기존 주변 관찰은 좌우를 둘러보므로 구분할 수 있다. 빠르게 확인하려면 테스트용 GameMode 기본값에서 위장 확률을 1로 올리고 확인 후 원래 값으로 돌린다.
2. 위장 마네킹을 바라본 뒤 시선을 돌린다. 시야 정지 후 감지되면 추격하고, 유효 감지 대상이 없으면 준비된 정찰을 이어야 한다. 정지/추종/직접 조작은 기존대로 동작해야 한다.
3. 싱글에서 각 저장소에 서로 다른 방향을 보고 수동 저장한다. 메뉴가 아닌 장면이 저장되는지, 세 창에서 맵/시각/이미지가 일치하는지 확인한다.
4. 자동 체크포인트는 현재 플레이 슬롯의 이미지와 상태만 갱신해야 한다. 삭제/새 게임 확인을 취소하면 보존되고, 승인하면 해당 저장소 이미지도 없어져야 한다.
5. 예전 저장 파일은 이미지 없이 플레이가 가능해야 한다. 불러오기만 했을 때 저장 시각과 이미지는 바뀌지 않고 마지막 플레이 시각만 갱신되어야 한다.

기존 실행 중 서버/운영 DB/배포 폴더는 변경하지 않았다. 실제 반영은 최신 클라이언트와 데디 서버를 재패키징해 배포해야 한다. 앞선 타임라인 작업의 프로토콜 2도 함께 들어 있으므로 해당 작업의 백엔드 갱신 안내도 따른다.

- Editor Development 및 Win64 Shipping 빌드 성공. 전용 서버 빌드/패키징/업데이트 게시는 실행하지 않았다.
- `Saved/DisguisePreviewNative/index.json`: 위장 상태/시야 정지/유예 간격/명령 제한/종료 초기화, 저장 이미지 검증/직렬화/손상 대체, 슬롯 UI/메타데이터, v4 저장 이관 및 기존 기능을 포함한 28건 성공, 경고/실패 0건.
- `Saved/DisguisePreviewRender/index.json`: 실제 오프스크린 장면 캡처 1건 성공, 경고/실패 0건. 빈 검은 프레임이 아닌 장면의 기하가 보이는지 검사했고 생성 이미지도 직접 확인했다. 테스트 카메라는 렌더 전 명시적으로 갱신한다.
- 실제 멀티 맵의 연출 빈도/자연스러움, 외부 PC 3인 경기, 실제 저장소 UI의 다양한 화면 해상도에서의 사용성은 별도 플레이 확인이 남아 있다. 자동 검사에서 사용자의 실제 저장 슬롯은 덮어쓰거나 삭제하지 않았다.
- 미리보기 배치 수정 후 `Saved/PreviewLayoutFix/index.json`의 저장/이미지/UI 검사 3건이 경고·실패 없이 통과했다. 실제 Slate UI를 프로젝트 DPI 설정으로 1280×720 및 800×600에 렌더링하고, 이미지가 160×90 논리 크기를 채우는지와 돌아가기 버튼이 화면 안에 있는지 검사했으며 결과 PNG도 확인했다. Editor/Shipping 빌드 성공. 이미지 데이터와 저장 형식은 이 배치 수정에서 변경하지 않았다.
