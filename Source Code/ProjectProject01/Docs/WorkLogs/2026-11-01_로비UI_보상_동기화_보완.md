# 로비 UI·보상·동기화 보완 묶음

## 요약
- 목표: 사용자가 한 번에 요청한 게임 쪽 보완(상점, 일일·주간 미션, 연계 퀘스트 알림, 프로필 업적, 컬렉션 갱신, 주간 조합 보상 표시, 방 관리 깜빡임, 적용 확인창, 역할·파티 깜빡임, 방화 셔터 동기화).
- 핵심 문제: 짧은 요청 동안 버튼을 잠깐 비활성화해서 생기는 깜빡임, 보상이 실제 지급·표시되는지 불명확, 셔터 안내 문구가 클라이언트마다 다를 수 있음.
- 해결: 0.35초 넘게 걸릴 때만 비활성으로 보이는 지연 표시, 서버 지급 경로와 표시 경로를 각각 추가·검사, 셔터 문구를 복제된 동작 상태에서 결정.
- 결과: UI 렌더 테스트 17/17 통과(넘침 수정 후), 격리 통합 검사 통과(미션 보상 29, 미션 예산 8, 일괄 보상 10, 주간 보너스 10, 메인 퀘스트 61, 기록 44, 뽑기 73, 안내 10).
- 상태: 구현·자동 검사 완료. 실제 플레이에서 깜빡임 소멸·컬렉션 증상 소멸은 미확인. 커밋 `3499183`, `6f8f0e6`(사용자 커밋).
- 기록 이력: 2026-11-27 작성 후 파일이 폴더에서 사라져(원인 미확인) 같은 날 같은 내용으로 다시 만듦.

## 원인과 판단
- 깜빡임: 요청이 진행되는 아주 짧은 동안 `SetIsEnabled(false)`로 위젯이 바뀌었다 돌아오는 것이 원인(코드 확인). 대안: (a) 요청 중에도 활성 유지 → 중복 요청 위험, (b) 지연 표시 + 클릭은 그대로 막음 → 채택. `IsStateChangeInFlightLong(0.35)`, `IsWritingLong(0.35)` 추가. 저장 중 누른 역할은 대기시켰다가 끝나면 보냄(`bRoleWritePending`).
- 주간 보너스: `weekly_affix_rewards(user_id, week_start, …, PK(user_id,week_start))` + `INSERT IGNORE`로 주 1회만 지급(동시 요청에도 1회). 크기 `WeeklyBonus(d)=(400d, 200d)`, d는 1~5로 자름. 방 목록 응답 `weeklyAffixes.reward`로 수령 여부 전달.
- 셔터: `OnRep_Motion`에서 `Motion.Target`으로 내리기/올리기 문구를 정해 서버·모든 클라이언트가 같게 표시.

## 시행착오
- `[[&]{...}()]`가 C++ attribute로 해석되어 C3750 → 지역 변수로 분리.
- sed 다중행 삽입이 MatchAffixes.cs에서 한 줄 주석으로 합쳐짐 → 파일 조각을 다시 삽입.
- sed 치환이 `#include`의 `#`를 지움 → 복원.
- RenderPages 800x600에서 넘침: Profile 474 > 431, Pvp/Bot 431.8 > 364.2 → 미션 섹션 제목 제거(행 태그로 대체), 업적 블록을 왼쪽 열로 이동, 여백 축소 → 17/17 통과.
- 실행 중인 실제 백엔드(PID 18288)가 bin을 잠가 빌드 실패 → 검사용 빌드를 scratchpad로 `-o` 출력.
- FeatureChecks의 로컬 함수가 아래에 선언된 변수를 참조 → 선언 순서 수정.

## 검증
- UE: 빌드 성공, `ProjectProject01.UITheme.*`, `CaseRecords.RenderPages` 등 렌더 테스트, 셔터 테스트(서버 문구, 클라이언트 복사본 같은 문구, 되돌릴 때 문구 복귀) 추가·통과.
- 백엔드: `Run-IsolatedIntegration.ps1 -FrontendOnly -ChecksAssembly <scratchpad dll>` (격리 MySQL 23307, 운영 DB 미접촉) → 위 요약 수치 전부 PASS. 새 `WeeklyAffixRewardChecks` 10개: 받기 전 "아직 받지 않음", 크기, 첫 승리 지급, 계정 반영(경험치 +1200·포인트 +600), 방 목록 표시, 같은 주 재지급 없음, 동시 6건 추가 지급 없음, 지난주 기록 분리, 새 주 재지급.
- 미수행: 실제 멀티플레이 접속 상태의 깜빡임 육안 확인, 셔터 다인 동시 플레이 확인, 컬렉션 증상 재현.
