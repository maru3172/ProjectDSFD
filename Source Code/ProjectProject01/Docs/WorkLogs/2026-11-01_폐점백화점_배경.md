# 폐점 백화점 배경 (로비·저장소 공통 배경)

## 요약
- 목표: 싱글 저장소와 멀티 로비의 배경색을 맞추고, 버려진 폐점 백화점(화재 흔적, 으스스·불길, 곳곳이 망가짐)을 코드로 그린 배경으로 바꾼다.
- 핵심 문제: 화면마다 배경이 달랐고(저장소만 색이 다름) 분위기 요소가 없었다.
- 해결: Slate `FSlateDrawElement`로 1600x900 기준 그림을 그리는 `ProjectDFSDUI::PaintStoreBackdrop`를 만들고 공통 페이지(`SProjectDFSDPage::OnPaint`)와 저장소 화면(`UProjectDFSDStoreBackdrop`)에서 같이 사용.
- 결과: 렌더 테스트 `ProjectProject01.UITheme.StoreBackdrop`(1600x900 PNG 저장) 통과, UI 테스트 3개(Contracts·RenderPages·StoreBackdrop) 통과. 진열대는 사용자 요청으로 추가했다가 최종적으로 제거.
- 상태: 완료. 커밋 `3499183`(Correction work, phase 1), `6f8f0e6`(UI Calibration)에 포함(사용자 커밋, 다른 세션 변경도 함께 들어 있음).
- 기록 이력: 2026-11-27 작성 후 파일이 폴더에서 사라져(원인 미확인) 같은 날 같은 내용으로 다시 만듦.

## 요청·범위
- 사용자 원문 요지: "저장소 뒷 배경이 멀티 배경과 다른 색, 일치 부탁. 로비 뒷 배경은 버려진 폐점 백화점, 으스스하고 칙칙하고 어둡게", 이후 "화재도 섞이고 불길하고 이곳저곳 망가진 느낌", "진열대나 구역별 가게 상품이 널브러져", "진열대도 추가", "기둥은 기둥대로 남기고 진열대를 추가해달라는 거였는데", 마지막 "화면에 보이는 진열대는 제거".
- 제약: UE 5.8, 에디터·Live Coding 실행 중 빌드 금지, 깜빡임 금지(사용자가 앞서 깜빡임을 싫어함), UI가 내용을 가리지 않을 것.
- 해석: 텍스처 에셋 없이 코드로 그리는 배경(에셋 추가 없음). 모든 해상도에서 잘리되 늘어나지 않게(cover) 그림.

## 구조
- `Public/ProjectStoreBackdrop.h`: `ProjectDFSDUI::PaintStoreBackdrop(Out,Geometry,Layer,Tint)` (Layer..Layer+2 사용), `UProjectDFSDStoreBackdrop` UWidget.
- `Private/ProjectStoreBackdrop.cpp`: `FStorePainter`(Box·Line·Disc·Stain·Mannequin 보조 함수), 그리는 본문, `SProjectStoreBackdrop`, 렌더 테스트.
- 호출: 테마의 `SProjectDFSDPage::OnPaint`(로비 공통) → `PaintStoreBackdrop`; 저장소 화면 → `UProjectDFSDStoreBackdrop`.
- 그리는 층: Layer(방·바닥·그을음) → Layer+1(구조물·간판·마네킹·잔해) → Layer+2(연기·먼지·잔불·비네트).

## 과정과 판단
| 단계 | 내용 | 결과 |
| --- | --- | --- |
| 1 | 기본 폐점 매장(천장등 하나만 켜짐, 빈 선반, 방화 셔터, "폐 점" 간판, 마네킹 3개, 먼지, 비네트) | 동작. 마네킹 머리가 둥근 브러시로 마름모처럼 보임 |
| 2 | 화재·파손 추가: 그을음 얼룩, 탄 간판, 천장 연기, 잔불, 떨어진 형광등, 기댄 선반, 쓰러진 마네킹, 끊어진 전선, 붉은 비상등, 불규칙한 바닥선·균열 | 동작. 얼룩·머리가 계단처럼 각짐 |
| 3 | `Disc`(가로 줄 쌓기)·`Stain`(동심 링)으로 교체, 조각 수를 화면 배율에 비례(`R*Scale`)하게 바꿈 | 각짐 해소 확인(PNG) |
| 4 | 구역 표지판(의류·잡화·화장품), 쓰러진 행거와 옷, 금 간 화장품 유리 진열대, 진열 테이블, 신발 상자·쇼핑백·가격표·옷걸이 | 첫 결과에서 옷(빨강·파랑)과 쇼핑백이 너무 밝아 튐 → 채도·밝기를 낮춤 |
| 5 | "진열대 추가": 기존 세로 덩어리(사용자 기준 기둥)에 상품을 올림 | **해석 오류**. 사용자는 기둥은 그대로, 진열대를 따로 원함 |
| 6 | 기둥 원복, 바닥에 독립 곤돌라 진열대 4개 + 선반이 무너진 진열대 + 엎어진 진열대 + 계단식 세일대 + 누운 철망 진열대 | 표시 확인 |
| 7 | "화면에 보이는 진열대 제거" | 진열대 전부 제거. 기둥·흩어진 상품·행거·화장품 진열대·진열 테이블·표지판은 유지 |
- 판단: 진열대 묶음은 별도 블록·람다로 작성해 두어 7단계 제거가 블록 삭제만으로 끝남.
- 실수 기록: 5단계에서 "기존 선반=진열대"로 해석했으나 사용자는 그것을 기둥으로 보고 있었다. 다음부터 화면 요소 이름이 모호하면 어떤 요소인지 먼저 확인할 것.

## 시행착오
- `FRandStream` 오타(정답 `FRandomStream`)로 C2065 컴파일 실패 → 수정 후 재빌드 성공.
- 렌더 테스트 1회가 엔진 시작 중 `HttpConnectionPool`/DDC 스레드 Assertion(`InheritedContext.cpp:130`)으로 중단. 코드와 무관한 엔진 측 오류로 판단(프레임 0, 우리 코드 호출 없음). 같은 명령 재실행에서 정상 통과. 원인은 미확인.
- PowerShell 대신 Git Bash에서 `Build.bat` 실행 시 공백 경로로 실패 → PowerShell 호출로 변경.

## 검증
- 빌드: `Build.bat ProjectDFSDEditor Win64 Development -project=...ProjectDFSD.uproject -waitmutex -NoHotReloadFromIDE` (매번 에디터·Live Coding 미실행 확인 후). 결과 Succeeded.
- 테스트: `UnrealEditor-Cmd ... -ExecCmds="Automation RunTests ProjectProject01.UITheme; Quit" -RenderOffscreen` → Contracts·RenderPages·StoreBackdrop 모두 Success.
- 시각 확인: `Saved/UIThemeQA/StoreBackdrop_1600x900.png`를 단계마다 직접 열어 확인.
- 미수행: 실제 게임 실행 화면·다른 해상도에서의 육안 확인, 프레임 비용 측정.
