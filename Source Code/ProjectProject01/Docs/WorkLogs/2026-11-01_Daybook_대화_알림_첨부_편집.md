# Daybook: 1:1 대화, 알림, 1:1 첨부, 입력 끊김 수정, 메시지 수정·삭제

## 요약
- 목표: 협업툴 Daybook에 1:1 대화와 대화방·연락 알림, 1:1 사진·파일, 메시지 수정·삭제를 넣고 입력이 끊기는 문제를 고친다.
- 핵심 문제와 원인(확인됨):
  1. 1:1 내용이 다른 팀원에게 새면 안 됨 → 기존 기록·댓글 테이블에 넣지 않고 전용 테이블로 분리.
  2. 연속 입력 불가 원인 A: 보내는 동안 Enter를 무시하고, 전송이 끝난 뒤 입력칸을 비워 그사이 친 글까지 지움(재현 확인).
  3. 연속 입력 불가 원인 B: 공통 `Modal`이 `onClose`가 바뀔 때마다 포커스를 창 틀로 옮김. 기록 편집 창은 글자마다 `onClose`가 바뀌어 한 글자 치면 포커스가 빠짐(코드 확인).
- 결과: 검사 `check-contacts.mjs` 37/37, 기존 검사(독립 43, 확장 30, 팀 도구 31) 유지.
- 상태: 완료. 커밋 `3499183`, `6f8f0e6`(사용자 커밋). 한글 IME 조합 입력은 자동화로 재현할 수 없어 미검증.

## 요청(원문 요지)
- "1:1로 DM, 혹은 방에서 채팅", "대화창이나 연락이 오면 알림", "1:1에서도 사진·파일", "입력을 연속으로 할 수 없고 하나 치면 끊긴다", "대화방만 해결되고 나머지는 안 된다", "쓴 것·목록 만든 것 수정·삭제".

## 구조
- 서버(독립 실행 Node): `self-host/contacts.mjs`
  - 동작: `pulse`(안 읽은 대화방 메시지·1:1·알림), `dmThread`, `dmSend`, `dmRead`, `dmEdit`, `dmDelete`, `messageEdit`, `messageDelete`, 파일 경로 `/api/direct-file`.
  - 테이블: `direct_messages`, `direct_reads`, `direct_attachments`. 마이그레이션 `0008`~`0010`.
  - `server.mjs`: 경로 연결과 11MB 제한. `backup.mjs`: 시스템 백업에 1:1 파일 포함.
- 화면: `app/contacts.tsx`
  - 사이드바 버튼, 1:1 창(문서 body로 portal), 알림 카드.
  - 창을 내려 둔 동안에는 브라우저 알림(허용 시).
  - 6초마다(숨김 상태 15초) 새 소식 확인.

## 판단과 대안
| 쟁점 | 대안 | 결정·이유 |
| --- | --- | --- |
| 1:1 비공개 | 기존 entries에 비공개 표시 / 전용 테이블 | 전용 테이블. 기록 목록·검색·내보내기·보고·파일 경로가 모두 entries/comments를 읽으므로 표시 하나로는 새는 길을 다 막기 어려움 |
| 1:1 파일 저장 | 기존 attachments / 전용 | 전용. 기존 첨부는 공간 팀원 누구나 내려받는 구조 |
| 알림 중복 | 대화방 카드 + 댓글 알림 둘 다 | 같은 소식이면 하나로 합침 |
| 대화창 위치 | 사이드바 안 / body로 portal | portal. 사이드바 스타일이 상속되어 사람 목록이 어둡게 늘어남(브라우저 확인) |
| 1:1 창 열림 중 알림 | 떠 있는 카드 / 창 안 | 창 안. 카드가 입력칸을 가림(사용자 원칙: UI가 내용을 가리지 않음) |
| 입력 끊김 B | 각 화면에서 onClose 고정 / Modal 수정 | Modal이 열릴 때 한 번만 포커스, onClose는 ref로 읽음. 같은 Modal을 쓰는 모든 창이 함께 해결 |
| 파일 메시지 수정 | 허용 / 금지 | 금지. 파일 메시지 본문은 파일 이름이라 고치면 의미가 깨짐. 삭제 시 파일은 휴지통으로 |

## 시행착오
- 사이드바 안에 그린 1:1 창이 어둡게 깨짐 → portal로 해결.
- 셸 이스케이프로 정규식 `[\x00-\x1f]`가 실제 제어 문자로 바뀌어 contacts.mjs 문법 오류 → 문자 코드로 다시 씀.
- 직접 만든 시험용 PNG가 깨져 사진이 안 보임 → 경로는 정상(200, inline, image/png) 확인 후 캔버스로 만든 PNG로 재확인(240px 표시).
- 검사의 "자신에게 보내기" 사례를 잘못된 상대로 작성 → 검사 코드 수정.
- 처음엔 1:1 입력칸만 고쳐 "다른 입력칸은 그대로"라는 지적을 받음 → 원인 B(Modal) 발견.

## 검증
- 자동: `node scripts/check-contacts.mjs` 37/37. 주요 확인:
  - 제3자·공간 밖 사람 차단, 1:1 내용이 기록 목록·검색·내보내기·알림·관리자 백업에 나오지 않음.
  - 1:1 파일은 두 사람만 열람, 형식·크기 제한.
  - 수정·삭제 권한, 파일 메시지는 휴지통으로, 1:1 삭제 시 파일까지 제거.
- 브라우저(내장 브라우저, 로컬 미리보기 서버):
  - 알림 카드와 배지가 뜨고, 1:1 창에서 보내기·읽음이 동작.
  - 연속 3건 전송이 순서대로 나가고, 이어서 치던 글이 남음.
  - 기록 편집 창 제목·본문을 연속 입력하고 6초 대기 뒤에도 포커스가 유지됨.
  - 대화방 메시지 수정에 "수정됨" 표시.
- 미수행: 한글 IME 조합 입력(자동화 도구는 조합 없이 글자를 넣음), 확인 창이 있는 삭제의 화면 클릭(서버 검사로 대체), 여러 PC 동시 사용.
