# 대기방 비밀번호 설정·변경·해제

## 요약
- **목표:** 이미 만든 대기방의 비밀번호를 방장이 걸고, 바꾸고, 풀 수 있게 한다.
- **핵심 문제:** 기존에는 방을 만들 때만 비밀번호를 정할 수 있었다.
- **해결:** 서버 API `PUT /api/rooms/current/password`를 추가했다.
  - 방 상태에 `hasPassword`를 넣었다.
  - 클라이언트 방 관리 탭에 입력칸과 "비밀번호 설정"·"해제" 버튼을 넣었다.
- **결과:** 서버 통합 검사 17개, UE 빌드, 로비·운영 자동 테스트 10개를 통과했다.
- **현재 상태:** 커밋 `f7ac87d`(Password Renewal, 사용자). 게임 화면 확인은 미실행이다.

## 9-2. 요청·범위
- **사용자 발언:**
  - "지금 현재 방 설정에 비밀번호 다시 거는것도 가능한가?"
  - 불가능하다는 답을 들은 뒤 "추가해줘".
- **합의된 범위:**
  - 방장만 바꿀 수 있다.
  - 대기 중(Waiting)인 방만 바꿀 수 있다.
  - 서버가 만든 방은 대상에서 뺀다. 랜덤 매칭 대기방, 파티 방, 봇전 방이다.
  - 이미 들어와 있는 인원은 그대로 남는다. 이후 입장부터 새 비밀번호가 필요하다.
- **제약:**
  - 비밀번호 규칙은 기존 방 생성과 같다. 비우거나 4~64자다.
  - 해시로만 저장한다.
  - MySQL은 3307을 쓰고, 격리 검사는 23307을 쓴다.

## 9-3. 구조·흐름
1. 클라이언트에서 `UProjectProject01LobbyWidget::HandleRoomPasswordSetClicked`(LoginWidget.cpp:7874)가 `UProjectProject01LobbySubsystem::SetRoomPassword`(LobbySubsystem.cpp:376)를 부른다.
2. 서브시스템이 `PUT /api/rooms/current/password {"password":...}`를 보낸다.
3. 서버(`LobbyEndpoints.cs:621`)가 다음 순서로 확인하고 처리한다.
   - 로그인 확인
   - 길이 검사
   - 현재 방 조회
   - 방장 확인
   - 상태·종류 확인
   - `game_rooms.password_hash` 갱신(빈 값이면 NULL)
4. 서버가 `{message, room}`을 돌려준다.
5. 이후 방 상태 조회(`LoadCurrentRoomAsync`)에서 `password_hash IS NOT NULL AS has_password`를 읽어 `HasPassword`로 내려준다.
6. 클라이언트가 이 값을 `bHasPassword`로 파싱한다.
7. 해제 버튼 활성화와 안내 문구에 반영된다.

| 응답 | 조건 |
|---|---|
| 401 | 미로그인. 입장 시 비밀번호가 틀려도 401(기존 동작) |
| 400 | 길이가 0도 아니고 4~64자도 아님 |
| 404 | 방 없음 |
| 403 | 방장 아님 |
| 409 | 대기 중이 아니거나 랜덤 매칭·파티·봇전 방 |
