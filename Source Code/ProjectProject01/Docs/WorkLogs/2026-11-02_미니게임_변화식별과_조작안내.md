# 미니게임: 움직였다 변화 식별·초기 게임 조작 안내 — 개발 기록

## 요약

- 목표: `움직였다`에서 무엇이 바뀌었는지 알아볼 수 있게 하고, 처음 하는 사람도 `정전 복구`·`한 칸씩`을 바로 하게 한다(재미 유지).
- 핵심 문제: 마네킹이 모두 같은 색·작은 형태라 바뀐 것을 구별할 수 없었다. 두 게임은 무엇을 해야 하는지 화면에서 알 수 없었다.
- 해결: 옷 색 12종·얼굴 방향·굵은 팔·최소 옆걸음 폭 확대. 다섯 게임 공통 시작 카드(목표/조작/요령), 화면 안 "할 일" 줄, 정전 복구 퓨즈 자동 끼우기.
- 결과: UE 미니게임 테스트 6개, 격리 서버 검사 347개 통과. 렌더 이미지로 확인. 실제 플레이 손맛 확인은 미실행.
- 상태: 커밋 `45752dc`(2026-11-02, Minigame 2)에 포함. 이후 `d0de20f`, `9dcab42`가 같은 파일을 더 바꿨다.

## 요청·목표·범위 (9-2)

- 사용자 발언: "근데 그 첫번째 게임 움직인게 뭔질 알수가 없어", 이어서 "나머지 초기 두 게임도 어떻게 조작을 하고 게임을 플레이해야할지 모르겠어 간단하게 물론 재미는 챙기고".
- 해석: (1) 변화가 눈에 보이게, (2) 정전 복구·한 칸씩의 목표와 조작을 화면에서 알려 주고 필요하면 조작을 줄인다. 규칙 난이도는 바꾸지 않는다.
- 제약: 깜빡임 금지, UI 겹침 금지, 행동 추가 시 신호·대응·약점 유지, 빌드 전 에디터·Live Coding·Codex 빌드 확인, 커밋은 요청 시에만.

## 기존 구조·흐름 (9-3)

- 서버 `Tools/ProjectProject01Backend/Game/MiniGameRules.cs`: 시드로 움직였다 라운드를 만들고 채점한다. 클라이언트는 정답을 받지 않는다.
- 클라이언트 `Source/ProjectProject01/Private/ProjectMiniGameWidgets.cpp`: `SProjectMiniGameView` 공통 틀(포커스·일시정지·카운트다운·저장) 위에 게임별 Slate 위젯. 카운트다운 화면에 `Help()` 한 문단을 보였다.
- 정전 복구 규칙 `FBlackoutSim`(`ProjectMiniGameRules.cpp`): `bHoldInstall`이 참이고 퓨즈를 들고 배전반 44 안이면 1.6초마다 끼운다.
- 흐름: 폴더 `Play()` → 게임 위젯 생성 → `Init()` → 카운트다운 → 실행.

## 문제·증상 (9-4)

- 움직였다: 렌더 이미지 `Saved/MiniGameQA/Spot_*.png`에서 마네킹이 같은 회색·작은 머리였고, 옆걸음 폭 `max(26, 110-9n)`은 뒤 라운드에서 너비의 2.6%까지 줄었다.
- 정전 복구: 퓨즈·배전반에 이름이 없고, 끼우려면 E를 누르고 있어야 하는 사실이 3초 카운트다운 문단에만 있었다.
- 한 칸씩: 문(X)이 빨간 선뿐이고, 노란 테두리(시선에 묶인 마네킹)의 의미가 화면에 없었다.
- 재현: 미니게임 렌더 테스트 `ProjectProject01.MiniGames.Render`.

## 판단·결정 (9-5)

| 선택지 | 결정 | 이유 |
| --- | --- | --- |
| 옆걸음 폭만 늘리기 | 일부 채택 | 폭 `max(70, 160-8n)`(최소 7%). 폭만으로는 고개·팔 변화가 여전히 안 보임 |
| 마네킹마다 옷 색 | 채택 | 같은 인물을 전후로 짝지을 수 있음. 정답 정보는 추가하지 않음 |

| 튜토리얼 스테이지 추가 | 기각 | 범위 큼. 시작 카드와 상황별 한 줄로 대체 |
| 정전 복구 E 키 유지 | 기각 | 조작을 줄여 달라는 요청. 서 있으면 자동 끼우기, 빛이 배전반에 묶이는 약점은 유지 |
| 한 칸씩 스테이지마다 시작 카드 | 기각 | 반복이 귀찮음. 1스테이지에만, 나머지는 상황별 한 줄 |

## 구현·시행착오 (9-6)

- `Mannequin()`: 머리 원판, 정면 두 눈/옆얼굴 코, 팔 두께 `H*.065`, 옷 색 인자. 배경 밝기 1.6 → 1.0.
- 공통 `FHowTo{Goal,Play,Tip}`와 `HowToCard()`: 새 판 시작 카드(`ShowIntro`, `EPhase::Intro`, 스페이스/Enter 시작), 카운트다운·일시정지 화면에도 표시. 다섯 게임의 `Help()`를 모두 교체.
- 정전 복구: `Input.bHoldInstall=true`, E는 로비로 새지 않게 게임 키로 남김. 배전반·퓨즈 이름표, 방 왼쪽 아래 "할 일".
- 한 칸씩: 상태줄 둘째 줄 `Hint()`(붙잡힘 → 되돌리기, 앞이 문 → 셔터, 노란 테두리 설명), 문 칸에 "문".
- 시행착오:
  - 한 칸씩 노란 테두리 위에 "멈춤" 글자를 넣었더니 머리와 겹쳤다. 글자를 빼고 테두리를 굵게 하는 쪽으로 되돌렸다.
  - 세로 화면에서 퓨즈 이름표가 방 오른쪽 가장자리에서 잘렸다. 왼쪽으로 옮겨도 점과 겹쳤다. 최종적으로 점 위쪽 가운데로 옮겼다.
  - 첫 UE 테스트 로그의 `Condition failed` 15줄은 엔진 시작 시의 자체 오류 검사 출력이었고, 미니게임 테스트와 무관함을 로그 위치로 확인했다.
