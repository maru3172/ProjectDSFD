# 퀘스트·대화 그래프 (설계, 2026-11-10)

지금의 메인 퀘스트(`탐사`)는 한 줄로 이어진 10단계뿐이고, 대화 선택지는 답장만 바꾼다. 앞으로 NPC, 메인 라인, 서브퀘스트를 계속 추가하고 선택에 따라 이야기가 갈라지게 하려고 구조를 바꾼다. 운영 도우미에서 그래프로 보고 고친다.

## 1. 정한 것

| 항목 | 결정 |
| --- | --- |
| 메인 라인 | 여러 개. 라인마다 여는 조건을 둔다. "앞 라인 완료"를 걸면 장처럼 순서대로, 걸지 않으면 동시에 진행된다. |
| 선택지 | 대화 안에서 다른 대사로 이어지고, "이야기 표시"(플래그)를 남긴다. 플래그로 다음 퀘스트 단계가 갈리고 서브퀘스트가 열린다. |
| 서브퀘스트 | 퀘스트마다 여는 조건: 처음부터 / 다른 퀘스트 완료 / 어떤 단계 도달 / 어떤 플래그 / NPC 대화에서 받음. |
| 진행 중 수정 | 플레이어는 지금 단계에 그대로 둔다. 누군가 있는 단계를 지우려면 옮길 단계를 정해야 하고, 정하지 않으면 저장을 거부한다. |

## 2. 데이터 구조

- **NPC**: `id`, 이름. 휴대폰 메신저의 대화 상대다.
- **퀘스트**: `id`, 이름, 종류(메인/서브), 여는 조건(모두 만족해야 열림, 비어 있으면 처음부터), 시작 단계, 단계 목록.
- **단계**: `id`, 제목, 목표(지금과 같은 게임 이벤트 목록: 튜토리얼, 경기 플레이, 층 탈출, 붙잡기, 승리, 대화), 이야기, 대화(선택), 다음 단계 연결 목록.
  - 연결은 위에서부터 조건(플래그 있음/없음)을 보고 처음 맞는 곳으로 간다. 마지막은 조건 없는 기본 연결이다. 연결이 없으면 퀘스트 완료다.
- **대화**: `id`, NPC, 시작 노드, 노드 목록.
  - 메시지 노드: NPC 대사 한 줄, 다음 노드.
  - 선택 노드: 선택지 2~4개. 선택지마다 보내는 말, 답장(최대 6줄), 남길 플래그, 줄 퀘스트(서브퀘스트 받기), 다음 노드.
  - 다음 노드가 없으면 대화가 끝난다.
- **플래그**: 플레이어마다 남는 이름표(예: `trust_kalin`). 선택으로만 생긴다.

## 3. 진행 기록 (서버)

- 퀘스트별 상태: 플레이어, 퀘스트, 지금 단계, 진행 중/완료.
- 목표 진행도: 플레이어, 퀘스트, 단계, 목표, 값.
- 대화 기록: 플레이어, 대화, 고른 경로(선택 노드와 고른 번호 목록). 서버가 그래프를 따라가며 경로가 맞는지 검사한다.
- 플래그: 플레이어, 플래그.
- 경기 이벤트(시작, 붙잡기, 탈출, 결과)는 지금처럼 들어오고, 진행 중인 모든 퀘스트의 지금 단계에 같은 방식으로 반영한다. 중복 처리 방지(이벤트 키)도 그대로다.

## 4. 기존 `탐사` 옮기기

- `탐사`를 메인 라인 1로 바꾼다. 10단계, 캘린·아테아 대화, 문구는 그대로다.
- 플레이어의 단계 번호를 단계 `id`로 옮기고, 저장된 선택 번호를 대화 경로로 옮긴다. 지금 대화는 한 줄이라 그대로 대응된다.
- 옛 표는 지우지 않고 남겨 되돌릴 수 있게 한다. 옮기기는 한 번만 실행된다(이미 있는 옮기기 기록 방식 사용).

## 5. 게임 화면

- 사건 기록의 퀘스트 화면: 메인과 서브를 나눠, 진행 중인 퀘스트를 모두 보여 준다.
- 휴대폰 메신저: 대화를 그래프로 따라간다. 선택하면 그 선택지의 다음 노드로 간다. 다 읽은 대화는 고른 경로대로 다시 읽을 수 있다(지금과 같음).
- 알림: 퀘스트 열림, 단계 완료, 퀘스트 완료.

## 6. 운영 도우미 편집기

- 왼쪽: NPC, 메인 라인, 서브퀘스트 목록. 추가·삭제·이름 바꾸기.
- 가운데: 퀘스트 그래프. 단계를 상자로, 연결을 화살표로 그린다. 상자 끌기, 단계 추가·삭제, 화살표 잇기·끊기, 연결 조건(플래그) 정하기.
- 단계를 두 번 누르면 대화 그래프. 메시지·선택 노드 추가·삭제·연결, 선택지의 플래그와 줄 퀘스트 정하기.
- 오른쪽: 고른 상자의 내용(제목, 목표, 이야기, 대사) 편집.
- 저장 전 검사: 시작에서 닿지 않는 단계·노드, 끝나지 않는 고리, 없는 플래그·퀘스트·NPC 참조, 글자 수, 아무도 남기지 않는 플래그를 쓰는 조건.
- 미리보기: 고른 노드부터 메신저처럼 재생. 선택지를 눌러 갈래마다 따라가 볼 수 있다.
- 저장은 지금처럼 버전 번호로 동시 수정을 막는다. 누군가 있는 단계를 지우면 옮길 단계를 고르는 창이 뜬다.
- 기존 CSV 가져오기·내보내기는 대사 문구용으로 유지한다.

## 7. 진행 순서

1. 서버: 새 데이터 구조, 검사, 진행 기록, `탐사` 옮기기, 관리자 API, 기능 검사.
2. 게임: 퀘스트 화면(여러 퀘스트), 메신저 그래프 재생, 알림, 테스트.
3. 운영 도우미: 그래프 편집기, 검사, 미리보기, 진행 중 수정 보호.
4. 문서와 전체 확인(격리 DB 통합 검사, Unreal 테스트).

## 8. 이번에 하지 않는 것

- 퀘스트 보상(재화·아이템). 지금 메인 퀘스트에도 없다. 필요하면 나중에 단계 완료 보상으로 붙인다.
- 새 목표 종류(예: 특정 아이템 사용). 지금 게임이 보내는 이벤트만 쓴다.
- 운영 서버 배포.
