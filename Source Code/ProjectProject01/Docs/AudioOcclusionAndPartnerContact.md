# 소리 차폐와 파트너 후퇴 접촉 수정

## 소리

- 싱글과 멀티의 기존 공간 효과음에 공통 적용한다. 심장박동, UI, 음악, EOS 음성은 변경하지 않는다.
- 방의 밀폐 여부 자체로 음량을 낮추지 않는다. 소리 발생점과 각 청취자 사이를 실제 메시 표면 기준으로 검사한다.
- 같은 방/탁 트인 공간에서 사이에 막는 표면이 없다면 추가 차폐는 없다. 거리 배율은 30m까지 1, 30~60m에서 선형으로 감소하며 60m에서 0이 된다. 예: 30m=1, 45m=0.5, 60m=0. 최종 청감은 개별 효과음 자체 음량과 전체/효과음 설정도 함께 따른다.
- 벽/닫힌 문 너머, 다른 밀폐 공간 밖에서 듣거나 바닥을 사이에 둔 다른 층이라면 차폐를 적용한다.
- 가려진 음량 배율은 0.25, 저역 통과는 600Hz, 전환은 0.15초다. 기존 0.4/1400Hz보다 저음 위주 발소리의 벽 차폐를 구분하기 쉽게 한다. 30m 안이어도 벽에 막히면 차폐는 적용된다. 열린 공간의 거리 감쇄는 음량만 바꾸고 벽 필터를 적용하지 않는다.
- 원본 사운드/Blueprint에 오래된 짧은 감쇄 범위가 있어도 런타임 사본/합성음은 동일한 30~60m 정책을 적용한다. Blueprint가 attenuation override나 공간음을 비활성화해 두었어도 재생 전에 복구한다. 복사된 비활성/빈 occlusion plugin 슬롯이 언리얼 기본 차폐 검사를 건너뛰지 않도록 런타임 슬롯을 제거한다. 원본 에셋은 변경하지 않는다.
- 마네킹 발밑 검사도 실제 표면을 검사하며 발생점을 표면 바깥쪽 8cm로 띄운다.
- `Visibility=Block`과 Query Collision은 유지한다. 일체형 메시를 분리할 필요는 없다. 다만 `Use Simple Collision As Complex`는 복합 검사에서도 단순 충돌을 대신 사용하므로, 빈 방을 채우는 볼록 충돌이 있다면 메시의 Collision Complexity를 `Simple And Complex` 또는 적절한 `Use Complex Collision As Simple`로 바꿔야 한다. 이번 코드 변경은 원본 맵/메시 에셋을 일괄 변경하지 않는다.

## 파트너

- 예정된 NavMesh 후퇴 경로에 플레이어가 있다는 이유만으로 미리 밀거나 데스카운트를 차감하지 않는다.
- 서버에서 실제 후퇴 이동이 있었고 플레이어 캡슐과 접촉했을 때만 밀고 데스카운트를 차감한다.
- 프레임 사이에 플레이어를 지나친 경우도 이미 이동한 짧은 구간의 캡슐 sweep으로 접촉을 검사한다. 미래 경로는 검사하지 않는다.
- 다른 층은 3차원 캡슐 접촉으로 배제한다. 정지 상태나 10m 초과 순간 이동/불러오기는 밀침으로 취급하지 않는다.
- 같은 후퇴에서 한 번만 밀고 차감한다. 기존 피격 무적 시간과 데스카운트 0 이후 파트너 제거 규칙은 유지한다.
- 차감 함수에도 접촉 확인 방어 조건을 넣어 다른 경로에서 미리 호출해도 차감되지 않는다.

## 확인

1. 같은 거리에서 마네킹 발소리를 직접 듣고 벽/닫힌 문을 사이에 뒀을 때와 비교한다. 같은 방 안이라면 주변 벽만 있다는 이유로 먹먹해지면 안 된다.
2. 문을 실제로 열어 소리와 청취자 사이의 표면이 사라지면 다시 또렷해져야 한다.
3. 파트너 후퇴 경로의 먼 위치에 서 있어도 미리 데카가 줄어들지 않아야 한다. 파트너가 실제로 다가와 접촉할 때에만 밀림과 차감이 발생한다.
4. 수정은 에디터 재실행 및 새 클라이언트 패키징 후 반영된다. 이번 작업은 원본 맵/에셋, 운영 DB, 실행 중인 서버를 임의로 변경하지 않는다.

### 귀로 분간하기 어려울 때 실제 재생 상태 확인 (에디터 전용)

PIE 콘솔 또는 출력 로그의 명령 입력란에 아래를 한 줄씩 실행한다. 새 디버그 유틸이 아니라 언리얼 기본 오디오 표시 기능이다. Shipping에는 이 표시를 넣지 않는다.

```text
au.3dVisualize.Enabled 1
au.3dVisualize.ActiveSounds 5
```

소리가 실제 재생 중일 때 발생 위치에 표시되는 숫자/색을 본다. 정상적으로 가리지 않으면 초록색, `Occlusion Volume: 1.000`, 필터 상한(보통 20000Hz)이다. 벽으로 가려지면 빨간색, 전환 후 `Occlusion Volume: 0.250`, `Occlusion Filter: 600.000`이어야 한다. 이 값은 거리 감쇄 배율이 아니라 **벽 차폐만의 값**이다. 45m에서 장애물이 없으면 차폐 값은 여전히 1이고 거리 배율만 0.5다.

같은 거리(가능하면 30m 안)에서 문을 열고 닫아 비교한다. 벽 뒤인데도 초록색/1.0이면 청감 튜닝보다 실제 가림/충돌/음원 위치 문제부터 확인해야 한다. 숫자는 맞는데 차이가 작게 느껴지면 실제 음원 특성과 청감 튜닝 문제다. 발소리는 재생이 짧아서 표시도 잠깐 나타날 수 있다.

끄기: `au.3dVisualize.Enabled 0`. 청감 A/B 비교가 필요하면 같은 위치에서 `au.DisableOcclusion 1`로 차폐만 임시 끄고, 반드시 `au.DisableOcclusion 0`으로 복구한다. 이 명령은 실제 에디터 맵에서 사용자가 확인하는 방법이며 이번 무음 자동 검사에서 청감을 검증한 것은 아니다.

자동 검사는 접촉/비접촉/다른 층/중복/이동 구간 접촉/순간이동과, 표면 차폐/빈 공간/층간 바닥/거리 감쇄를 검사한다. 실제 맵의 충돌 에셋과 청감까지 자동 검사로 보증하는 것은 아니다.

최종 30m 정책 검증 결과: UE 에디터 및 Win64 Shipping 빌드 성공. `ProjectProject01.Audio` / `Helper` / `Operations` 자동 검사 10개 성공, 실패 0개. 결과는 `Saved/AudioDistance30mChecks/index.json`, 원본 로그는 `Saved/Logs/AudioDistance30mChecks.log`에 있다. 격리 테스트는 30m까지 거리 배율 1, 45m에서 0.5, 60m에서 0, 이전 사운드 설정/Blueprint 우회 방지, 원본 에셋 비변경, 같은 밀폐방 안의 직접 경로, 그 방 밖으로 벽을 통과하는 경로를 포함한다. 이전 접촉 판정 검증 결과는 `Saved/AudioContactChecksFinal`에 남아 있다. 배포용 Cook/패키징과 실제 맵 청감 확인은 이번 자동 검증에 포함하지 않는다.
