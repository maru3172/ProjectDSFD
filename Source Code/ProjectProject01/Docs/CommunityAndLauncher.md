# 친구·차단 및 런처 운영

## 오픈 매칭 UI

- 공개방은 드롭다운 없이 스크롤 목록으로 펼쳐 표시합니다. 항목을 누르면 색상과 `✓ 선택됨`으로 강조하며, `선택한 공개방 참가`를 눌러야 실제 입장합니다. 비밀번호방을 고르면 해당 방의 비밀번호 입력란이 나타납니다.
- `참가 코드로 방 참가`를 누를 때만 코드·비밀번호 입력란과 `방 참가 / 닫기`가 나타납니다. 비밀번호가 없는 방은 비워 둡니다. 빈 코드는 선택한 공개방으로 대신 참가하지 않으며, 닫기·방 입장·화면 이동 시 입력값을 지웁니다.
- 방장 위임 대상도 펼친 목록에서 선택합니다. 선택만으로 위임하지 않으며 별도 위임 버튼을 눌러야 합니다. 새로고침은 선택한 ID를 유지하고, 대상이 나가면 선택을 해제합니다.
- 신고 팝업에서 친구·귓속말·알림 탭을 누르면 신고창을 닫고 선택한 탭으로 전환합니다. 창 전환만으로 신고를 제출하지 않습니다.

## 서버 운영 → 런처 뉴스·패치노트·문의

- 뉴스/공지 또는 패치노트를 선택하고 제목·본문을 작성해 저장합니다.
- `런처에 공개`를 켠 게시물만 클라이언트가 읽을 수 있습니다. 작성·수정·삭제·사진 첨부는 관리자 키가 있는 서버 운영 도우미에서만 가능합니다.
- `사진 첨부`: PNG/JPG, 파일당 5MB 이하, 가로·세로 각각 8192px 이하, 1600만 화소 이하입니다. 글당 최대 8장, 서버 이미지 보관 한도는 256MB입니다. 생성된 `![사진](image:...)` 줄을 본문에서 원하는 위치로 옮길 수 있습니다.
- `목록 미리보기 사진`: 본문에 첨부한 사진 중 한 장만 선택합니다. 기본값 `미리보기 없음`이면 공지 목록에는 사진이 표시되지 않습니다. 본문 사진 표시와는 별개이며, 첫 사진을 자동 선택하지 않습니다. 글마다 선택·해제를 저장할 수 있고 게시 후에도 변경할 수 있습니다.
- `표 삽입`: 행·열 수를 정하고 표의 칸에 직접 내용을 입력해 삽입합니다. `본문 미리보기`에서는 사진·표를 포함해 클라이언트와 동일한 본문 표시를 확인합니다. 본문 내부에는 아래 형태로 저장되며, 직접 수정할 수도 있습니다. 최대 12열·100행이 표시됩니다.

```text
| 항목 | 변경 내용 |
| --- | --- |
| 버전 | 1.0 |
| 수정 | 접속 오류 수정 |
```

- 클라이언트는 브라우저 없이 텍스트·사진·읽기 전용 표로 표시합니다. HTML/스크립트와 외부 이미지 URL은 실행하거나 불러오지 않습니다.
- `접수 문의·답변` 탭에서 문의를 선택하고 답변을 저장합니다. 접수자만 확인 코드로 답변을 조회할 수 있습니다.

## 런처 환경설정

- 메인에는 업데이트 확인·업데이트 및 실행·현재 버전 실행을 남겼습니다. 다운로드 중에만 중단 버튼이 나타납니다.
- 톱니바퀴 → 서버·설치 관리: 서버 IP 저장, 새 설치 위치 선택, 기존 설치 지정, 설치/복구, SHA-256 무결성 검사, 캐시 삭제, 폴더 열기.
- 새 설치 위치는 비어 있는 게임 전용 폴더여야 합니다. 기존 게임을 쓰려면 `기존 게임 설치 위치 지정`을 선택합니다.
- 캐시는 이어받기 `.update-cache`와 설치 폴더 내 게임 `Saved/DerivedDataCache`, `Saved/Shaders`만 정리합니다. 저장소·환경설정·설치 파일은 삭제하지 않습니다. 실패 시 복구용 `.update-backup`도 삭제하지 않습니다.
- 공지사항·패치노트 → 새로고침 → 글 선택. 고객센터 → 문의 접수 → 확인 코드 보관 → 답변 확인. 최근 문의 코드는 해당 PC에 보관하며 이전 코드는 따로 보관해야 합니다.

## 로그인 후 로비·방

- 친구·귓속말·종 모양 알림은 로비·방 우측 하단에서 위로 열리는 패널입니다. 방 화면을 별도 화면으로 바꾸지 않습니다.
- 친구창은 목록부터 표시합니다. 검색은 계정 ID·표시 이름으로 하고, `친구 추가`를 눌러 별도 입력창에서 요청합니다. 친구 우클릭 메뉴는 내 방 초대·친구 삭제·메시지 차단·프로필 확인입니다.
- 받은 친구 요청도 수락·거절 확인창을 띄웁니다. 요청을 보냈거나 확인창을 열었다는 이유로 자동 등록하지 않습니다. 닫기는 보류이며 친구창의 받은 요청에서 나중에 응답할 수 있습니다. 같은 요청은 매번 반복 팝업하지 않지만, 거절 후 다시 받은 새 요청은 다시 안내합니다.
- 방 참가자 이름을 **우클릭 → 프로필 확인**하면 친구가 아닌 사람과 본인의 프로필·검증 전적도 열 수 있습니다. 상시 버튼은 표시하지 않으며 좌클릭으로는 열리지 않습니다. 동일한 표시 이름이 있어도 서버 참가자 ID로 구분합니다. 방 전용 조회 API는 같은 방 참가자인지 검사하며, 프로필은 기존 방 화면 위의 패널로 열고 닫기만 하므로 준비·방 참여 상태를 변경하지 않습니다.
- 방 초대는 상대에게 수락·거절 팝업을 표시합니다. 수락 전에는 절대 입장하지 않습니다. 2분 뒤 만료되며 수락 시 방 상태·정원 3명·차단·친구 관계를 다시 확인합니다. 이미 다른 방에 있다면 먼저 그 방을 나가야 합니다. 유효한 초대는 비공개 방 입장 권한이므로 비밀번호를 상대에게 공개하지 않습니다.
- 내 프로필에서 상태메시지(160자)·소개글(500자)·색상·칭호를 변경합니다. 상태메시지는 로그인한 모든 플레이어의 최근 50개 공개 피드에 표시됩니다(차단 관계 제외). 프로필 전적은 서버의 검증된 경기 기록만 집계하며 수집하지 않은 경기는 포함하지 않습니다.
- 상대 계정 ID로 친구 요청을 보냅니다. 받은 요청에 수락/거절할 수 있고 친구 삭제·메시지 차단/해제가 가능합니다.
- 온라인/오프라인 표시/자리비움/방해금지 중 선택합니다. 친구에게 상세 활동과 경기 역할을 공개하는 상태는 온라인뿐입니다. 무응답 20초 또는 만료·폐기된 세션은 오프라인으로 취급합니다.
- 귓속말은 양쪽 모두 로비·방에 있어야 하며 경기 중에는 서버도 송수신을 거부합니다. Enter 또는 보내기를 사용합니다. 최대 500자, 10초간 최대 5건이며 조회 이력은 최근 7일/100건입니다.
- 귓속말 목록에서 상대 계정 ID를 입력하면 그 상대와의 채팅창을 엽니다. 목록으로 돌아와 `대화 삭제`를 누르면 내 과거 기록만 숨깁니다. 상대의 기록은 삭제되지 않으며 새 메시지가 오면 대화가 다시 나타납니다.
- 접속 상태는 패널 하단의 내 상태를 눌렀을 때만 선택지를 표시합니다.
- 읽지 않은 알림은 종 옆 빨간 점으로 표시합니다. 친구 요청·수락·귓속말을 알리며 삭제·차단·차단 해제는 상대에게 알리지 않습니다.
- 로비·방의 `환경설정` → 서버 연결에서 차단 목록을 볼 수 있습니다. 로그인하지 않으면 목록 버튼 자체가 숨겨집니다. 일반 로그아웃·강제 로그아웃·계정 변경은 목록과 캐시를 초기화합니다. API 역시 인증된 본인의 목록만 반환합니다.
- 친구 최대 200명, 받은/보낸 미처리 요청 각 100건, 차단 500명입니다. 목록은 3초 간격으로 갱신합니다.

## 입력란·공개방 가독성

- 방 채팅 입력·본문과 설문 주관식 답변은 20포인트, 귓속말 입력·본문은 18포인트로 표시합니다. 방 채팅 입력 최소 높이 54, 채팅 기록 180, 주관식 답변 160 UI 단위이며 기존 Enter 전송 동작은 유지합니다.
- 공개방 선택란과 펼친 항목을 키우고 선택 행을 파란색으로 강조합니다. 별도의 `✓ 선택됨` 안내에 방 이름·참가 코드를 표시합니다. 선택만으로 입장하지 않습니다.
- 새로고침으로 인원·방장·목록 순서가 바뀌어도 참가 코드 기준으로 선택을 유지합니다. 방이 삭제되거나 검색에서 제외되면 선택을 해제하며 다른 방을 자동 선택하지 않습니다.
- 실제 공개방을 클릭하면 이전에 입력한 직접 참가 코드·비밀번호를 비워 잘못된 다른 방에 들어가지 않도록 합니다. 이후 참가 코드를 직접 입력하면 기존처럼 입력 코드가 우선합니다.

## 창 닫기·강제 종료

- 창 닫기·Alt+F4·정상 종료·에디터 PIE 종료에서는 종료 직전 별도 로그아웃 요청을 보냅니다. 다른 UI 요청 때문에 로그아웃이 막히지 않습니다.
- 작업 관리자 강제 종료·크래시·전원 차단은 종료 요청 자체를 보장할 수 없습니다. 새 로그인/토큰 갱신 시 서버가 세션별 90초 접속 확인 유예를 만들고, 클라이언트가 5초 간격으로 갱신합니다. 유예 만료 뒤 서버 정리 주기(5초)에서 토큰 폐기·방장 이전/빈 방 삭제·오프라인 표시·초대 정리를 수행합니다. DB 장애 시 복구 후 다시 시도합니다.
- 만료된 세션은 늦게 도착한 접속 확인/토큰 갱신으로 부활하지 않습니다. 이전 PC의 세션 정리가 새 로그인과 그 방을 지우지 않도록 검사합니다. 접속 유예는 오프라인 표시 선택과 별개입니다.
- 싱글플레이 오프라인 실행은 로그인 세션을 만들지 않으므로 서버가 없어도 동작합니다.

## 반영 및 검사

1. 변경된 백엔드를 재시작하면 `Database/002_Community.sql`이 기존 계정·기록을 지우지 않고 새 테이블을 준비합니다.
2. 서버 운영 도우미와 새 런처를 다시 실행하고 클라이언트를 재패키징합니다. 이번 작업은 경기 규칙·게임 서버 프로토콜을 바꾸지 않았습니다.
3. 두 테스트 계정으로 친구 요청/수락, 귓속말, 차단·해제, 온라인 상태, 강제 로그아웃 후 목록 소거를 확인합니다.
4. 사진과 표를 넣은 글을 서버에서 게시한 뒤 다른 PC 런처에서 새로고침해 확인합니다. 클라이언트에는 작성 기능이 없습니다.

자동 검사는 `ProjectProject01FeatureChecks`의 CommunityChecks(별도 MySQL 23307 사용), 런처/운영 도우미 폼 검사 및 Unreal `ProjectProject01.Community.SessionCleanup`에 포함되어 있습니다. 실제 다중 PC 배포 연결 및 패키징 실행 검사는 별도로 필요합니다.
## 방 참가자 우클릭과 신고

- 방 참가자 이름을 우클릭하면 프로필, 친구 추가/삭제, 귓속말, 메시지 차단/해제, 신고 메뉴가 열립니다. 좌클릭은 작업하지 않습니다. 본인에게는 프로필만 제공합니다.
- 서버가 참가자 ID로 같은 방인지 확인하고 계정 ID와 현재 친구/차단 상태를 반환합니다. 친구 추가는 요청만 보내며 상대가 수락해야 친구가 됩니다.
- 신고는 로그인한 사용자가 같은 방의 다른 참가자를 대상으로 제출합니다. 욕설·괴롭힘 / 부정행위 의심 / 게임 진행 방해 / 기타 중 사유를 고르고 상세 내용을 1~1000자로 적습니다.
- 우클릭 외에도 로비·방의 소셜 메뉴에 별도 **신고** 버튼이 있습니다. 로그인 아이디(닉네임 아님)와 사유·내용을 입력하면 같은 방에 있지 않아도 신고할 수 있습니다. 대상 계정이 실제로 존재해야 하며 본인은 신고할 수 없습니다. 같은 방 정보가 없으면 서버에 `아이디 직접 신고 (같은 방 기록 없음)`으로 명시합니다. 두 경로의 반복 제출 제한은 공유됩니다.
- 서버는 신고자와 대상의 ID·당시 계정/표시 이름, 방 ID/이름, 사유·내용·UTC 접수 시간을 저장합니다. 방을 나가거나 방이 없어져도 이미 접수된 신고는 남습니다. 인증 토큰·비밀번호는 기록하지 않습니다.
- 반복 제출 제한: 다른 대상 30초, 동일 대상 10분, 신고자당 24시간 최대 20건. 신고만으로 자동 제재하지 않습니다.
- 서버 도우미 → 서버 운영 → **플레이어 신고 확인**에서 관리자 권한으로 조회합니다. 최신 100건씩 조회하고 상태별 필터/이전 접수 더 보기, 검토 메모, 검토 완료·보류 종료·미확인 변경이 가능합니다. 일반 클라이언트는 신고 목록과 검토 API에 접근할 수 없습니다.
- 배포 반영: 백엔드·도우미 재시작/새 실행 파일, 클라이언트 재패키징 또는 업데이트 게시가 필요합니다. 기존 데이터는 지우지 않으며 백엔드 시작 시 신고 테이블이 생성됩니다.

## 랜덤 매칭 / 오픈 매칭

- 로그인 후 로비 첫 화면에서 `랜덤 매칭`과 `오픈 매칭`을 고릅니다. 오픈 매칭은 기존 공개방 목록·검색·방 생성·코드 참가를 유지합니다.
- 랜덤 매칭은 솔로 전용이며 `시작 / 뒤로가기`를 제공합니다. 친구 초대와 매칭 채팅은 제공하지 않으며 서버에서도 거절합니다. 오픈 매칭의 친구 초대·방 채팅과 개인 귓속말은 유지합니다.
- 시작 전에는 랜덤 대기열에 들어가지 않습니다. 시작하면 `매칭 중… (1/3 또는 2/3)`으로 대기하며 취소할 수 있습니다. 취소하면 개인 신청 전 상태로 돌아옵니다.
- 랜덤 대기열에 명시적으로 참가한 개인 신청자 3명만 구성합니다. 일반 방/로비 인원은 충원하지 않습니다. 과거 버전의 다인 파티도 서버에서 신청을 차단합니다.
- 3명이 확정되면 취소·뒤로가기는 비활성화합니다. 서버도 시작 취소를 거절합니다. 각자 자기 역할(마네킹 1/생존자 2)만 확인하면서 5초 카운트다운 → 암전 → 접속 티켓으로 데디 서버 접속 순서입니다. 세션이 꽉 차면 기존 서버 준비 대기 제한과 실패 복구를 재사용합니다. 확정한 역할은 세션 준비 후 재추첨하지 않습니다.
- 랜덤 매칭의 채팅 입력·로그·전송 UI를 제거합니다. 서버는 채팅 전송을 거절하고 저장된 메시지도 응답에 노출하지 않습니다.
- 시작 전 뒤로가기는 개인 대기 공간을 나가고 두 매칭 방식 선택 화면으로 돌아갑니다.
- 경기 후에는 자동 재매칭하지 않습니다. 참가자 복귀/종료 정리가 끝나면 각자 개인 시작/뒤로가기 상태로 돌아갑니다. 복원에 필요한 방 자리는 경기 중에도 기존 방 한도 계산에 예약해 둡니다.
- 중복 요청은 신청 ID로 멱등 처리합니다. 취소가 먼저 도착한 ID는 늦은 시작 요청으로 부활하지 않습니다. 대기 중 접속 확인이 30초 끊기거나 전체 대기가 180초를 넘으면 종료합니다. 강제 로그아웃·퇴장·인원 변경도 대기를 취소/만료시킵니다. 확정 후 강제 종료 등 실제 인원 이탈은 기존 경기 시작 취소·복구 규칙으로 처리합니다.
- DB 테이블은 백엔드 시작 시 추가하며 기존 계정/기록은 삭제하지 않습니다. `MatchmakingChecks`는 격리 MySQL/실제 HTTP와 가짜 UE 프로세스를 사용합니다. 실제 다중 PC에서의 게임 접속은 별도 배포 검사가 필요합니다.
