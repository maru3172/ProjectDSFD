# 로딩 화면·관전·사망 후 음성

## 화면 흐름

오픈/랜덤 매칭 모두 5→1 카운트다운 직후 2초 암전을 시작하고, 완전한 검정 프레임에 도달한 뒤 로딩 화면을 표시한다. 세션 빈자리 대기, 전용 서버 준비, 접속 허가 확인, 서버 접속을 모두 **같은 로딩창의 진행 상태**로 표시한다. 서버가 준비될 때까지 방 화면에 남겨 두거나 별도 안내 창을 띄우지 않는다. 시작을 보여주는 연출은 접속 허가가 아니며, 서버가 Started를 확정하고 발급한 현재 경기의 티켓 없이는 실제 접속하지 않는다.

내 넓은 가로 진행 막대는 두께를 기존 24px로 유지하며 하단 중앙에, 다른 두 사람의 작은 막대(12px)는 좌측 중단에 둔다. 각 참가자의 백분율과 준비 상태, 내 경과 시간 및 확정된 내 역할을 표시하고, 화면 정중앙에는 `모든 참가자가 준비되면 시작됩니다.`만 표시한다. 전원 준비 후 로딩 내용을 검게 지운 다음 기존 게임 화면 페이드 인으로 연결한다. 최초 진입의 1.5초, 트리거 도착의 0.6초 화면 복귀 규칙은 유지한다.

맵 교체 중에는 MoviePlayer가 화면을 유지하고, 맵이 열린 뒤에는 GameInstance의 Slate 오버레이가 이어받는다. 전용 서버는 MoviePlayer를 포함하지 않는다. 싱글은 자신의 준비만 기다린다. 타이틀/로비 복귀는 새 게임 로딩으로 처리하지 않는다.

### 백분율의 의미

사용 중인 엔진의 AsyncLoading2 파일 진행률 API는 -1을 반환하므로 **파일 바이트 비율이 아니라 준비 단계 비율**이다. 세션 접속(2), 빈 세션 대기(5), 서버 준비(10), 접속 허가 확인(15), 서버 접속(20) → 맵 읽기(30) → 맵 준비(70) → 스트리밍·시점 준비(90) → 정상 화면 준비(100) 순서다. 임의 타이머로 100%를 채우지 않는다. 접속하기 전 다른 PC의 내부 파일 진행률은 수신할 수 없어 확인 대기로 표시한다. 서버에 연결한 뒤 해당 클라이언트가 보고한 준비 단계를 공유한다.

오픈 방의 방장은 Queued/Preparing일 때 로딩창의 `세션 대기 취소`로 기존 서버 취소 API를 호출할 수 있다. 확정된 랜덤 매칭 또는 접속 허가/실제 접속 단계에서는 해당 버튼을 제공하지 않는다. 취소·실패로 Waiting 상태가 되면 로딩창과 암전을 해제하고 기존 방으로 돌아간다. 대기와 서버 준비의 기존 제한(120초/90초)을 유지하고, 로딩창은 상태 전달 지연을 위한 여유 후에도 응답이 없으면 안전하게 로그인으로 복귀한다. 이 대기 시간은 이후 맵/참가자 준비의 120초 제한을 소모하지 않는다.

## 전원 준비 확인

새 월드마다 다른 식별자를 발급하고, 인증된 경기 참가자만 자신의 준비 상태를 보고한다. 중복 보고로 인원이 늘어나거나 이전 맵의 보고로 다음 맵이 시작되지 않는다. 참가자 전원이 100%이기 전에는 서버 경기 시간·AI 갱신·캐릭터 이동을 보류한다. 준비 대기 제한은 120초이며 실패한 로딩에는 승리·점수를 부여하지 않는다. 메인 스레드를 완전히 멈추게 하는 엔진/디스크 중단을 로딩 UI가 강제로 끊을 수는 없다.

## 죽은 플레이어

살아 있는 생존자의 카메라를 기준으로, **대상 몸의 뒤쪽**으로 90cm, 위로 40cm 떨어진 관전 전용 위치를 사용한다. 실제 생존자 BP 기준 캡슐 중심에서 뒤로 60cm·높이 110cm이며, 머리가 정면을 가리지 않게 높이도 확보한다. 관전자의 마우스 회전으로 이 위치가 대상 주위를 돌지 않는다. 3cm 구형 카메라 충돌 검사로 벽이 있으면 이동 거리를 줄인다. 관전 대상 모델을 숨기지 않는다. 카메라 방향은 마우스로 독립 조작하며 이동 입력과 대상 캐릭터의 회전/판정은 건드리지 않는다. 다음 맵에서도 관전 상태를 유지하는 기존 규칙을 따른다. `AProjectSpectatorCameraManager`의 `SpectatorBackOffsetCentimeters`(기본 90, 범위 0~150cm)와 `SpectatorHeightOffsetCentimeters`(기본 40, 범위 0~60cm)로 조정할 수 있다.

사망은 음성 채널 탈퇴와 구분한다. 송신 및 열린 마이크/눌러서 말하기는 차단하고, 살아 있는 생존자의 대화는 관전 대상 위치를 기준으로 계속 수신한다. 서버도 죽은 참가자를 음성 발신자로 허용하지 않는다. 나가기·퇴장·로그아웃은 기존 채널 탈퇴와 요청 취소/로컬 자격 정보 정리를 유지한다. EOS 토큰을 문자 그대로 ‘반납’하거나 즉시 전역 폐기하는 API를 호출한다는 뜻은 아니다.

## 배포

새 로딩 RPC를 모르는 구형 클라이언트 혼용을 막기 위해 NetworkProtocolVersion을 4로 맞췄다. 백엔드·클라이언트·데디 서버를 함께 갱신해야 한다. 별도 환경변수로 버전을 덮어쓰는 경우에도 4를 사용한다. 이 작업에서 패키징·배포는 하지 않는다.
