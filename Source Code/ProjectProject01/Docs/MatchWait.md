# 매칭 대기 중 다른 것 하기

랜덤 매칭을 돌리거나 오픈 매칭 방에 있는 동안 로비의 다른 기능, 튜토리얼, 연습 모드를 쓸 수 있다. 봇전은 해당하지 않는다(방이 바로 경기를 시작한다).

## 로비에서
- 랜덤 매칭 화면의 `로비로 (매칭 유지)`, 오픈 매칭 방의 `로비로` 버튼으로 매칭·방에 남은 채 로비 메뉴로 나온다. 이 상태에서도 튜토리얼·연습에 들어갈 수 있다(원래는 막혀 있었다).
- 경기가 시작되면(카운트다운·서버 준비·랜덤 매칭 성사) 로비는 저절로 방/매칭 화면으로 돌아가 기존 시작 흐름을 그대로 탄다.

## 왼쪽 상태 패널
- 화면 왼쪽, 가운데보다 조금 아래. 로비(방/매칭 화면이 떠 있을 때는 숨김), 튜토리얼·연습, 그 밖의 로비 밖 화면에서 보인다. 경기 안에서는 보이지 않는다.
- 랜덤 매칭: `랜덤 매칭 중`, 인원 n/3, 경과 시간. 버튼 `매칭 화면`(로비 밖에서는 `로비로`), `매칭 취소`.
- 오픈 매칭: 방 이름과 인원, 참가자마다 닉네임과 방장/준비/대기, 시작 직전이면 `곧 경기가 시작됩니다`. 버튼 `방 확인`(로비 밖에서는 `로비로`), 방장은 `시작`, 그 밖은 `준비`/`준비 취소`, `나가기`.
- 튜토리얼·연습 중에는 마우스가 게임 조작에 쓰이므로 Alt를 누르고 있는 동안만 커서가 나와 패널을 누를 수 있다(패널에 안내 한 줄).

## 튜토리얼·연습 중 경기가 시작되면
- 로비 밖에서는 로비 화면이 없으므로 패널(UProjectMatchWait)이 2초마다 매칭 상태/방 상태를 직접 갱신한다.
- 시작을 알게 되면 화면 가운데 `게임이 시작됩니다`를 1.3초 띄우고, 0.6초 동안 암전한 뒤 로비로 이동한다. 로비의 기존 시작 흐름(입장권·경기 서버 이동)이 이어서 경기로 데려간다.
- 경기가 끝나면 원래대로 로비의 방/매칭 화면으로 돌아온다. 연습으로 돌아가지 않는다.

## 구현
- `Public/ProjectMatchWait.h`, `Private/ProjectMatchWait.cpp`: GameInstance 서브시스템, 뷰포트 오버레이(레벨이 바뀌어도 다시 붙음), 0.2초 틱.
- `ProjectProject01LoginWidget.cpp`: `로비로` 버튼, `bMatchViewMinimized`, 튜토리얼·연습 허용 조건(`CanMinimizeMatchView`), 패널의 `방 확인` 연결, 현재 방/매칭 화면 여부 알림.

## 확인하지 못한 것
- 실제 매칭 서버와 여러 클라이언트로 "연습 중 성사 → 암전 → 경기" 전 과정을 돌려 보지 않았다. 빌드와 기존 테스트만 통과했다.

## 시작 카운트다운 (2026-11-04)
- 로비에 있을 때: 로비의 기존 카운트다운(5·4·3·2·1) 뒤 경기로 들어간다.
- 연습모드 등 로비 밖에 있을 때: 그 자리 화면 가운데에서 "게임이 시작됩니다"와 5·4·3·2·1을 센다. 다 세면 화면이 어두워지고 로비로 넘어가며, 로비는 다시 세지 않고 바로 경기 입장으로 이어진다(`ConsumeCountedDownAway`). 그 사이 시작이 취소되면 로비 도착 후 어두운 화면을 걷어 방이나 매칭 화면을 보여 준다.
- "로비로"로 대기 중 로비에 돌아올 때도 출발할 때 덮은 어두운 화면을 도착 후 걷어낸다.
- 패널의 바깥 틀은 마우스를 받지 않는다(카드만 받는다). 예전에는 화면 전체를 덮어 로비 버튼의 호버·클릭을 가로챘다.
