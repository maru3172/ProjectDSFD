기준일: 2026-11-05. 설계 문서다. 구현 완료를 뜻하지 않는다. 수치는 구현 후 플레이 확인을 거쳐 조정한다.

검사(2026-11-05, 감염 이후): Unreal 40개 통과(`CustomRules.*` 9개: `AuthorityAndRuntime`·`PlaygroundParse`·`PlaygroundCards`·`InfiniteLives`·`HideReveal`·`Ghosts`·`Infection`·`Presets`·`Render`(네 탭 × 1280×720·800×600, 버튼 겹침·탭 영역 넘침·탭 전환 시 크기 유지), `ItemRoguelike.*`, `Bots.*`, `Replays.*`, `Review.ForfeitRules`, `Multiplayer.*`(음성·관전 포함)). 분리 DB(23307) 통합 검사 통과(사용자 지정 규칙·규칙 코드 57개). 통합 검사 스크립트 마지막의 `RecoveryChecks.ps1`은 이번 작업과 무관한 스크립트 오류(`Start-ProcessWithoutInputMark` 없음)로 매번 실패한다. 실제 여러 PC 대전 플레이 확인은 하지 않았다.

규칙 하나를 켤 때는 같은 커밋에서 게임 서버 동작, 두 곳의 `Live` 스위치, 검사를 함께 바꾼다.

## 0. 이 문서의 범위

사용자 지정 게임은 일곱 번째 어트랙션 "놀이터"다. 다른 여섯 가지(싱글, PvP, 봇전, 아이템 로그라이크, 어픽스, 미니게임)를 섞고 규칙을 바꿔 노는 곳이며, 공식 기록과 분리한다.

합의한 규칙 목록은 확정이다. 이 문서는 그중 1단계만 다룬다.

| 단계 | 내용 |
| --- | --- |
| 1단계 (이 문서) | 섞기 스위치(어픽스 고르기, 아이템 카드), 자유 규칙(무한 목숨, 감염, 유령 생존자, 오래 숨으면 들킴), 프리셋, 규칙 코드와 코드별 기록 |
| 2단계 | 함께 탈출 / 마지막 한 명, 번지는 불, 시야·소리 규칙(어둠·연기 농도, 소리만 들리는 마네킹, 바라보기 시간 제한, 개인 핸디캡) |
| 3단계 | 숨바꼭질, 역할 바꾸기, 웨이브 생존, 규칙 카드 투표 (추천 프리셋으로 제공) |

지켜야 할 원칙:

- 공식 기록(리더보드, 개인 전적, 레이팅, 경험치, 포인트, 미션, 업적, 시즌 보상)에 반영하지 않는다.
- 같은 규칙으로 빠르게 다시 할 수 있어야 한다.
- 프리셋이 놀이터의 개성을 만든다. 모든 프리셋은 생존자뿐 아니라 마네킹 플레이어의 플레이도 바꾼다.
- 화면 깜빡임이 없어야 하고, UI끼리 겹치지 않아야 한다.
- 모든 규칙은 클라이언트, 게임 서버, 백엔드 세 곳에서 검증한다.
- 도전 과제와 순위표는 만들지 않는다. 코드별 기록은 판 결과 요약만 보여 준다.
- 마네킹 AI의 기존 동작은 유지한다. 감염자 대역 봇도 기존 마네킹 AI를 그대로 쓴다.

### 0.1 인원 기준

방은 최대 3명이다(`ProjectProject01LobbySubsystem.h`의 `MaxPlayers = 3`). 마네킹 플레이어 1명과 생존자 2명이 기준이다. 역할 비율을 바꾸는 규칙은 제외 목록에 있으므로, 모든 규칙과 프리셋은 생존자 2명 기준으로 맞춘다.

- 감염: 한 명이 감염되면 곧바로 "마지막 생존자 1명 대 마네킹 + 감염자" 구도가 된다. 판이 짧아지므로, 감염 프리셋은 제한 시간을 짧게(10분) 잡아 빨리 끝나고 빨리 다시 하는 판으로 만든다.
- 유령: 유령 1명이 남은 동료 1명을 돕는 1대1 구도다. 핑과 속삭임 제한은 이 구도에서 정보가 너무 많아지지 않도록 정한 값이다.
- 오래 숨으면 들킴, 무한 목숨, 섞기 스위치는 인원과 상관없이 작동한다.

## 2. 규칙 데이터

### 2.1 JSON 구조

기존 `rules` 객체에 필드를 더한다. 새 필드도 모두 필수로 하고 프로토콜을 8로 올린다. 구형 클라이언트와 구형 서버가 섞이면 지금처럼 버전 계약에서 거부한다.

```json
{
  "enabled": true,
  "deathCount": 3,
  "mannequinCount": 6,
  "timeLimitSeconds": 900,
  "affixIds": ["B09", "B10"],
  "itemCards": false,
  "infiniteLives": true,
  "infection": true,
  "ghosts": false,
  "hideRevealSeconds": 0
}
```

| 필드 | 형식 | 범위 | 기본값 |
| --- | --- | --- | --- |
| `affixIds` | 문자열 배열 | 0~6개, 중복 없음, `bPlayable` id만, 그룹(A/B/C)별 최대 3개 | `[]` |
| `itemCards` | bool | | `false` |
| `infiniteLives` | bool | | `false` |
| `infection` | bool | | `false` |
| `ghosts` | bool | | `false` |
| `hideRevealSeconds` | 정수 | 0(끔) 또는 20~120, 5의 배수 | `0`. UI에서 켜면 40으로 시작 |

`hideRevealSeconds`처럼 숫자로 끄고 켜는 필드는 0을 끔으로 쓴다. 지금 `timeLimitSeconds`의 0(무제한)과 같은 방식이다.

### 2.2 조합 규칙

아래 조합 검증은 세 곳이 같은 함수 의미를 가져야 한다.

1. `enabled=false`이면 새 필드는 모두 기본값이어야 한다. 아니면 거부한다. 꺼진 규칙에 값이 남아 있으면 혼란스럽기 때문이다.
2. `infiniteLives=true`이면 `timeLimitSeconds`가 300 이상이어야 한다. 아무도 탈락하지 않으므로 시간이 경기를 끝내야 한다.
3. `ghosts=true`는 `infection`이나 `infiniteLives`와 함께 켤 수 없다. 두 규칙에서는 탈락자가 생기지 않아 유령이 나올 수 없다.
4. `infection=true`이면 `mannequinCount`는 8 이하로 한다(제안). 감염 몸체가 더해져도 몸체 총수와 복제 부담이 기존 최대치(10) 근처에 머물게 하려는 것이다.
5. `itemCards=true`이면 `affixIds`로 이미 걸린 어픽스는 버프 카드로 나오지 않는다. 기존 `ProjectItemRoguelike::Pool`의 `ActiveBuffs` 제외를 그대로 쓴다. 따라서 어픽스를 많이 고를수록 버프 카드가 줄고 아이템 카드가 늘어난다.

### 2.3 저장 위치

방장은 한 번의 적용으로 모든 규칙을 보낸다. 백엔드는 한 트랜잭션 안에서 세 테이블에 나눠 쓴다.

| 규칙 | 저장 | 이유 |
| --- | --- | --- |
| 수치, 자유 규칙 | `room_custom_rules` 새 열: `infinite_lives`, `infection`, `ghosts`, `hide_reveal_seconds`, `rule_code` | 기존 테이블 확장 |
| `affixIds` | 기존 어픽스 방 설정(`MatchAffixes.SetRoomAsync`, 모드 `Custom`) | 티켓의 `affixes` 경로와 `IsCustomAsync`의 `Custom` 비공식 판정을 그대로 쓴다. 비어 있으면 모드 `None`. |
| `itemCards` | 기존 `room_match_modes`(`ItemRoguelike` / `Normal`) | 티켓의 `matchMode` 경로와 비공식 판정을 그대로 쓴다. |

경기 확정 때 `match_custom_rules`에도 새 열을 함께 스냅샷한다(`CaptureAsync`). `room_rule_presets`에도 같은 열과 `affix_ids`, `item_cards`를 추가한다. 새 열은 기본값을 가지므로 이미 저장된 프리셋은 "새 규칙 꺼짐"으로 그대로 유효하다.

### 2.4 세 곳의 검증

| 위치 | 바꿀 곳 | 내용 |
| --- | --- | --- |
| 클라이언트 | `FProjectCustomMatchRules::Parse`, `IsValid` | 새 필드 필수, 범위, 2.2 조합. 실패 시 통째로 거부하고 기존 값 유지(지금 방식). UI는 적용 전에 같은 `IsValid`로 막고 이유를 보여 준다. |
| 게임 서버 | `GameInstance` 티켓 파싱, `AcceptCustomRules` | 같은 `Parse`. 첫 입장에서 고정, 재접속·관전·층 전환에서도 변경 불가(지금 방식). 어픽스와 매치 모드는 기존 `AcceptMatchAffixes`, `AcceptMatchMode`가 그대로 고정한다. |
| 백엔드 | `CustomRoomRules.Valid` | 같은 범위와 조합. `affixIds`는 `MatchAffixes.ValidCustom`에 개수·그룹 제한을 더한다. 오픈매칭 대기 방에서만 적용 가능(지금 방식). |

`MatchAffixes.ModeAllowed`는 봇 난이도를 기준으로 하므로, 오픈매칭 놀이터용으로는 별도 검사(`affixIds` 개수와 그룹)를 둔다. 봇방의 기존 `Custom` 어픽스 경로는 바꾸지 않는다.

## 3. 섞기 스위치

### 3.1 어픽스 고르기

- 방장이 30개 어픽스 중 최대 6개를 고른다. 그룹마다 최대 3개.
- 생존자: 기존 어픽스 효과와 신호를 그대로 받는다. 경기 시작 때 걸린 어픽스 목록을 기존 어픽스 표시 방식으로 본다.
- 마네킹 플레이어: 마찬가지로 그대로 받는다. A그룹은 마네킹 몸체에 불리, B그룹은 유리하다. 감염이 켜져 있으면 감염 몸체도 마네킹 몸체로 취급한다(4.2).
- 기존과의 관계: 게임 서버의 어픽스 런타임(`ProjectAffixRuntime`)과 봇 대응은 이미 구현되어 있으므로 새 효과 코드는 없다. 바뀌는 것은 오픈매칭 방에서 `Custom` 어픽스를 설정할 수 있게 하는 백엔드 경로뿐이다.

### 3.2 아이템 카드

- 켜면 기존 아이템 로그라이크 규칙(층마다 3장, 새로고침 1번, 20초 자동 선택, 고르는 동안 경기 시간 정지)을 그대로 쓴다.
- 생존자와 마네킹 플레이어 모두 기존과 같이 고른다. 마네킹 쪽은 M 아이템과 생존자에게 줄 A 버프를, 생존자 쪽은 S 아이템과 마네킹에게 줄 B 버프를 받는다.
- 어픽스 고르기와 함께 켤 수 있다. `Docs/ItemRoguelikeMode.md`의 "봇전 어픽스 모드와 함께 쓸 수 없다"는 봇전 모드(마스터+, 주간)에 대한 규칙으로 두고, 놀이터에서는 2.2의 5번처럼 이미 걸린 어픽스를 카드에서 빼는 방식으로 함께 쓴다(열린 질문 4).
- 감염자의 카드: 감염된 플레이어는 다음 층부터 M 아이템만 받는다. 버프 카드는 받지 않는다(제안). 버프는 진영당 한 사람 몫으로 설계되어 있어서, 감염자가 늘수록 마네킹 쪽 버프가 겹치는 것을 막기 위해서다.

## 4. 자유 규칙

### 4.1 무한 목숨

생존자:

- 잡혀도 데스카운트가 줄지 않고 탈락하지 않는다.
- 잡히면 기존 포획 연출과 피격 유예 시간을 그대로 거친 뒤, 그 층의 시작 지점으로 돌아간다. 돌아간 뒤 3초 동안은 다시 잡히지 않는다.
- 데스카운트 표시는 "무한"으로 바꾼다. 대신 결과 화면에 "잡힌 횟수"를 보여 준다.
- S03 방화복 조각은 쓸모가 있다. 첫 포획 1번을 막아 시작 지점으로 돌아가지 않게 해 준다. 자유 연습에서는 쓰지 않는데(`PlayerCharacter.cpp:1436`), 놀이터에서는 쓴다는 점이 다르다.

마네킹 플레이어:

- 잡아도 상대가 줄지 않는다. 목표는 "끝까지 탈출하지 못하게 시간을 끄는 것"으로 바뀐다. 출구 근처에서 잡을수록 생존자를 멀리 돌려보내므로, 출구 쪽 수비가 중요해진다.
- 제한 시간이 끝날 때까지 아무도 탈출하지 못하면 마네킹 쪽 승리다.

구현:

- 연습 모드 함수(`HasPracticeInfiniteLives`)는 튜토리얼 게임 모드 전용이다. 경기용으로는 `AMultiplayTestGameMode`에 고정된 규칙을 읽는 판정을 더하고, `PlayerCharacter`의 포획 처리에서 두 판정을 함께 본다. 연습 모드 동작은 바꾸지 않는다.
- 층 시작 지점은 기존 생존자 스폰 지점을 쓴다.

### 4.2 감염

생존자가 탈락할 상황이 되면 관전으로 넘어가지 않고 마네킹 편 "감염자"가 된다.

| 상황 | 감염되는 때 |
| --- | --- |
| 감염만 켬 | 데스카운트가 0이 되는 포획 |
| 감염 + 무한 목숨 | 첫 포획. 데스카운트는 쓰지 않는다. 아무도 경기에서 빠지지 않는다는 뜻의 "무한"이다. |

감염된 플레이어:

- 잡힌 자리에서 감염 몸체 1개를 직접 조종한다. 겉모습은 마네킹이고, 몸에 그 플레이어를 알아볼 수 있는 표식(기존 생존자 색)이 남는다.
- 마네킹 규칙을 똑같이 따른다. 생존자가 바라보면 멈춘다. 그래서 감염자도 "보이지 않을 때만 움직이는" 플레이를 하게 된다.
- 생존자를 잡을 수 있다. 감염 몸체가 잡아도 일반 포획과 같다.
- 마네킹 쪽 음성·핑을 쓰고, 생존자 쪽 음성은 더 이상 듣지 못한다.
- 감염은 되돌릴 수 없다. 층이 바뀌어도 감염 상태로 이어진다(carryover에 감염 상태를 더한다).

마네킹 플레이어:

- 직접 조종 슬롯(숫자 키, 최대 10)은 그대로다. 감염 몸체는 슬롯에 들어가지 않는다.
- 스스로 움직이는 동료가 생긴다. 감염자에게 핑으로 신호를 줄 수 있다. 명령 휠로 감염 몸체를 조종하지는 못한다.
- 생존자가 줄어드는 만큼 마네킹 쪽이 늘어나므로, 후반에는 "몰이"가 핵심이 된다.

승패:

- 남은 생존자가 모두 감염되면 마네킹 쪽 승리.
- 남은 생존자 중 누군가 탈출하면 기존 탈출 판정을 따른다.
- 결과 화면에서 감염자는 "감염됨"으로 표시한다.

기존 시스템과의 관계:

- A그룹 어픽스는 감염 몸체에도 걸린다(예: A06 남는 경직). B그룹은 생존자에게 작용하므로 그대로다.
- 감염자가 나가면 기권 규칙에 따라 대역 봇이 감염 몸체를 맡는다. 대역 봇은 기존 마네킹 AI를 그대로 쓴다.
- 감염 몸체도 마네킹 몸체 수에 더해진다. 2.2의 4번 제한은 이 때문이다.

### 4.3 유령 생존자

탈락한 생존자가 관전자 대신 제한된 유령으로 남는다.

유령:

- 시점은 기존 생존자 관전(`Docs/SurvivorSpectatorTravel.md`)을 그대로 쓴다. 살아 있는 동료를 따라다니며 본다. 몸은 없고 아무것도 만질 수 없다.
- 핑: 기존 팀 핑(`ServerRequestTeamPing`)을 쓴다. 20초에 1번, 동시에 남는 유령 핑은 유령마다 1개. 살아 있는 생존자에게만 보인다.
- 속삭임: 살아 있는 생존자에게만 들리는 음성. 누르고 말하는 방식, 한 번에 최대 5초, 다음 속삭임까지 15초. 마네킹 쪽은 듣지 못한다.
- 층이 바뀌어도 유령으로 남는다(기존 관전 유지 규칙과 같다).

생존자:

- 탈락한 동료가 정보를 계속 준다. 대신 유령은 몸체를 멈추게 하지 못한다. 시선 판정에는 들어가지 않는다.

마네킹 플레이어:

- 유령 핑과 속삭임은 마네킹 쪽에 전혀 보이거나 들리지 않는다(사용자 결정, 2026-11-05).
- 한 명을 잡아도 정보가 끊기지 않으므로, 빨리 잡는 것보다 남은 생존자를 고립시키고, 유령이 알려 주기 어려운 곳(시야가 끊기는 모퉁이, 몸체가 많은 진열대)으로 몰아가는 쪽이 중요해진다.

기존 시스템과의 관계:

- C07 공유되는 핑이 걸려 있어도 유령 핑은 마네킹에게 보이지 않는다. C07은 살아 있는 생존자의 핑에만 적용한다.
- 2.2의 3번에 따라 감염, 무한 목숨과 함께 켤 수 없다.

### 4.4 오래 숨으면 들킴

생존자:

- 반경 4m 안에서 `hideRevealSeconds`초를 넘게 머무르면 위치가 마네킹 쪽에 5초 동안 드러난다.
- 4m 밖으로 움직이면 시간이 처음부터 다시 쌓인다.
- 들키기 10초 전부터 화면 가장자리의 작은 게이지가 서서히 찬다. 깜빡이지 않고 차오르기만 한다.
- 드러난 뒤에는 다시 0부터 쌓인다.
- 세지 않는 때: 아이템 카드를 고르느라 경기 시간이 멈춘 동안, 층 전환 대기 중, 탈출 트리거에서 기다리는 중, 유령과 감염자.

마네킹 플레이어:

- 드러난 생존자의 윤곽이 벽 너머로 5초 동안 보인다. 위치는 고정이고, 그 사이 생존자가 움직여도 윤곽은 따라가지 않는다.
- 생존자가 한 곳에 버티는 전략이 막히므로, 순찰보다 "드러날 때 달려가는" 플레이가 된다.

기존 시스템과의 관계:

- B05 떨어지는 먼지와 비슷한 "한자리에 오래 있음" 판정을 쓴다. 어픽스 런타임의 판정을 공용 함수로 꺼내 두 규칙이 같이 쓰게 한다. 둘 다 켜져 있으면 먼지와 들킴이 각각 따로 작동한다.
- 대역 봇이나 봇 생존자는 이 규칙이 켜져 있으면 한자리에 `hideRevealSeconds - 5`초를 넘게 머무르지 않는다.

## 5. 프리셋

### 5.1 종류

| 종류 | 위치 | 편집 |
| --- | --- | --- |
| 추천 프리셋 | 클라이언트와 백엔드에 같은 표로 내장(어픽스 주간 순환표와 같은 방식) | 읽기만. 불러온 뒤 고치면 내 규칙이 된다. |
| 내 프리셋 | 기존 `room_rule_presets`, 계정당 20개 | 지금과 같다 |

### 5.2 단계

한 테마를 1, 2, 3단계로 나눌 수 있다. 단계가 오를 때마다 이미 합의한 규칙을 더 얹을 뿐이고, 새 규칙은 만들지 않는다. 단계는 "더 세게 놀고 싶을 때 고르는 선택지"이며 순위나 보상은 없다. 2단계 이후의 규칙(어둠 등)이 필요한 단계는 그 규칙이 나올 때 추가하고, 그 전에는 목록에 보이지 않게 한다(빈 자리나 잠금 표시를 두지 않는다).

### 5.3 1단계 추천 프리셋

| 프리셋 | 규칙 | 생존자 쪽 변화 | 마네킹 쪽 변화 |
| --- | --- | --- | --- |
| 좀비 백화점 1 | 감염 + 무한 목숨, 마네킹 3, 10분 | 한 번 잡히면 감염자가 된다 | 감염자가 늘며 몰이 플레이 |
| 좀비 백화점 2 | 1단계 + B09 깨어나는 진열, B10 사냥의 열기 | 달리기가 위험해진다 | 감염이 생길 때마다 모든 몸체가 빨라진다 |
| 좀비 백화점 3 | 2단계 + 어둠 | 2단계에서 어둠 규칙이 나올 때 추가 | |
| 유령 백화점 | 유령 + 데스카운트 1 + 오래 숨으면 들킴 30초, 20분 | 한 번에 탈락하지만 유령으로 돕는다 | 남은 생존자를 유령이 돕기 어려운 곳으로 몰고, 숨은 생존자를 쫓는다 |
| 폐점 순찰 | 오래 숨으면 들킴 20초 + B05 떨어지는 먼지 + 아이템 카드 | 계속 움직여야 한다 | 드러날 때 달려가는 플레이 |
| 카드 난장 | 아이템 카드 + C01 깜짝 마주침 + C05 러시아워 | 카드 조합으로 버틴다 | 카드 조합으로 사냥한다 |

"좀비 백화점"은 원래 감염 + 무한 목숨 + 어둠으로 합의했지만, 어둠은 2단계의 시야 규칙이다. 그래서 1단계에서는 1, 2단계 프리셋만 내고, 어둠을 얹은 3단계는 2단계 작업 때 추가한다(사용자 결정, 2026-11-05).

## 6. 규칙 코드와 코드별 기록

### 6.1 규칙 코드

- 방장이 적용한 규칙 전체를 `ZB7K-2QXM`처럼 8글자 코드로 나눌 수 있다. 친구가 코드를 입력하면 같은 규칙이 편집 칸에 채워진다. 적용은 따로 한다(지금 프리셋 불러오기와 같다).
- 코드는 백엔드가 만든다. 규칙을 정해진 순서로 직렬화한 값의 SHA-256 앞부분을 Crockford Base32(0/O, 1/I/L 혼동 없음)로 바꾼다. 같은 규칙이면 언제나 같은 코드다.
- 새 테이블 `rule_codes(code, rules_json, rules_hash, created_at)`. 코드가 겹치는데 해시가 다르면 다음 글자를 더 써서 9글자 이상으로 만든다.
- 입력은 대소문자와 하이픈을 가리지 않는다.
- 코드에는 방장이나 방 정보가 들어가지 않는다.
- 엔드포인트: `POST /api/rule-codes`(규칙 → 코드), `GET /api/rule-codes/{code}`(코드 → 규칙과 기록 요약). 둘 다 로그인과 기존 `lobby` 요청 제한을 따른다.

### 6.2 코드별 기록

그 코드로 끝까지 진행된 판의 결과를 모아 보여 준다. 순위는 없다.

```
ZB7K-2QXM (좀비 백화점 2)
- 지금까지 37판
- 생존자 승 12판 / 마네킹 승 25판
- 내 결과: 3판 중 1판 탈출
```

- `match_custom_rules`에 `rule_code` 열을 더해 경기 확정 때 함께 저장한다. 요약은 이 스냅샷과 기존 경기 결과에서 계산한다.
- 공식 집계와는 기존 `OfficialFilter`로 이미 분리되어 있다. 새 요약 쿼리는 반대로 이 스냅샷이 있는 경기만 센다.
- 세는 판: 정상 종료한 판. 기권 판정이 난 판은 기권 규칙의 결과대로 센다. 서버 오류로 중단된 판은 세지 않는다.
- 전체 요약(판 수, 진영별 승리)은 코드를 아는 누구나 본다. "내 결과"는 본인에게만 보인다.

### 6.3 같은 규칙으로 다시 하기

- 방의 규칙은 경기가 끝나도 `room_custom_rules`에 남아 있으므로 방으로 돌아오면 그대로 다시 시작할 수 있다.
- 결과 화면에 규칙 코드와 "코드 복사"를 추가한다. 결과 화면의 기존 버튼과 겹치지 않는 자리에 둔다(공식 등록 버튼이 숨겨지는 자리).

## 7. 방장 설정 UI

### 7.1 배치

지금 패널(620px, 축소만, 스크롤 없음)에 다 넣으면 800×600에서 넘친다. 그래서 패널 위쪽에 탭 4개를 둔다.

```
┌ 커스텀 규칙 ───────────────────────────────┐
│ [기본] [섞기] [자유 규칙] [프리셋·코드]         │
├────────────────────────────────────────────┤
│ (탭 내용: 높이 고정 영역)                     │
│                                            │
├────────────────────────────────────────────┤
│ 상태 줄 (2줄 높이 고정)                       │
│ [적용]                         [돌아가기]     │
└────────────────────────────────────────────┘
```

| 탭 | 내용 |
| --- | --- |
| 기본 | 지금 화면 그대로: 사용자 지정, 데스카운트, 마네킹 수, 제한 시간 |
| 섞기 | 어픽스 배지 10×3 격자(그룹별 한 줄, 기존 글자 배지와 그룹 색). 선택하면 테두리가 생긴다. 격자 아래 고정 높이 1줄에 마지막으로 가리킨 어픽스의 설명. 그 아래 "아이템 카드" 토글. |
| 자유 규칙 | 무한 목숨, 감염, 유령 생존자 토글, "오래 숨으면 들킴" 토글과 초 입력(켜졌을 때만 활성) |
| 프리셋·코드 | 추천 프리셋 목록(단계 포함), 내 프리셋(지금의 콤보·이름·불러오기·저장·삭제), 코드 입력과 "코드로 불러오기", 현재 규칙의 코드와 기록 요약 3줄 |

규칙:

- 탭 내용은 처음에 모두 만들어 두고 `SWidgetSwitcher`로 바꾼다. 탭을 바꿀 때 위젯을 다시 만들지 않으므로 깜빡이지 않는다.

- 적용, 돌아가기, 상태 줄은 탭 밖에 두어 항상 같은 자리에 있다.
- 조합 규칙(2.2)에 걸리는 토글은 비활성으로 두고, 이유를 상태 줄에 쓴다. 새 팝업은 띄우지 않는다. 확인 창은 지금의 "적용하시겠습니까?" 하나만 쓴다.
- 요청 중에는 이전 값을 그대로 보여 주고 상태 줄에만 "불러오는 중…"을 쓴다(지금 방식).
- 어픽스 배지 설명은 툴팁 대신 고정 줄에 쓴다. 툴팁은 다른 UI를 가린다.

권장 순서: 데이터·검증 → 백엔드 → 섞기 스위치 → 무한 목숨 → 숨기 → 유령 → 감염 → 프리셋 → 규칙 코드. 위험이 가장 큰 감염을 뒤에 두면, 그 전까지의 묶음만으로도 놀이터를 먼저 내놓을 수 있다.

## 11. 감염 구현 계획 (2026-11-05 구현 완료, 진행 표 8번 참고)

감염은 지금까지의 규칙과 달리 경기 핵심 흐름(포획, 관전, 층 이동, 직접 조종 권한)을 건드린다. 모든 변경은 `HasPlaygroundInfection()`(사용자 지정 켬 + 감염 켬)일 때만 동작하게 해서 일반 경기에는 영향이 없게 한다. 여러 PC 실제 대전 확인이 꼭 필요하다.

| 순서 | 바꿀 곳 | 내용 |
| --- | --- | --- |
| 1 | `APlayerCharacter::HandleMannequinCatch` | 감염 + 무한 목숨이면 첫 포획에서 바로 기존 게임 오버 경로로 간다(S03은 그대로 먼저 막는다). 감염만 켜면 데스카운트 0 포획이 기존대로 게임 오버. |
| 2 | `AMultiplayTestGameMode::NotifyExistingMannequinCatch` | 탈락 처리 뒤, 기록에 `bInfected`를 표시하고 기존 사망 연출(약 3초)이 끝나면 감염 몸체를 만든다. 상태는 `Eliminated`를 그대로 써서 승패(전원 탈락 = 마네킹 승)·음성 제외·결과 경로를 바꾸지 않는다. |
| 3 | 새 `SpawnInfectedBody` | 잡은 몸체와 같은 클래스의 마네킹을 잡힌 자리에 만들고(조종 슬롯 -1, 숫자 키 목록에 안 들어감), 그 플레이어 컨트롤러가 빙의, `SetManualControlEnabled(true)`. 몸에 원래 생존자 색 표식. |
| 4 | 직접 공격 권한 | 서버의 직접 공격 판정은 지금 `IsMannequinController`(역할이 마네킹)만 허용하고, 클라이언트 입력도 `IsLocalMannequinPlayer`로 막는다. 감염자도 허용하도록 두 곳을 넓힌다. 이것이 없으면 감염자는 아무도 잡을 수 없다. |
| 5 | `RefreshSurvivorSpectatorTargets` | 감염자는 관전 대상 지정에서 뺀다(자기 몸체 시점 유지). |
| 6 | 보이면 멈춤 | 직접 조종 중인 몸체도 생존자 시선에 멈추는지 확인하고, 아니면 감염 몸체에만 적용. |
| 7 | 층 이동 | carryover에 `bInfected`. 다음 층에서 마네킹 스폰 지점 중 생존자와 먼 곳에 감염 몸체를 만들어 다시 빙의. |
| 8 | 나감·재접속 | 나가면 기본 마네킹 AI가 그 몸체를 맡는다(기존 마네킹 AI 그대로). 재접속하면 다시 빙의. |
| 9 | 결과·카드 | 결과에 "감염됨". 아이템 카드 모드에서 감염자는 다음 층부터 M 아이템만 받는다. |
| 10 | 켜기 | 두 곳의 `Live` 스위치를 켜면 좀비 백화점 1·2 추천 프리셋이 자동으로 나타난다. |

검사: 감염 전환(무한 목숨 유무 두 경우), 감염 몸체 빙의·슬롯 -1, 직접 공격 허용 범위(감염자는 되고 일반 생존자는 안 됨), 관전 제외, 전원 감염 시 마네킹 승, 층 이동 후 감염 유지, 나감 후 AI 인계. 작업량은 설계 추정대로 6~8일이며 그중 1~2일은 여러 PC 실제 확인이다.

## 12. 2·3단계 계획 (2·3단계 결정 완료 2026-11-05, 구현 전)

합의 목록의 남은 규칙이다. 새 규칙은 더하지 않는다. 각 규칙은 1단계와 같은 방식(필드 + 세 곳 검증 + `Live` 스위치 + 방장 화면 + 검사)으로 넣는다.

### 12.3 제안 순서

1. 감염(11절)으로 1단계를 마친다(완료).
2. 2단계는 작은 것부터: 바라보기 시간 제한 → 어둠·연기(좀비 백화점 3) → 소리만 들리는 마네킹 → 개인 핸디캡 → 함께 탈출 → 번지는 불.
3. 3단계는 2단계 규칙이 다 들어간 뒤 프리셋으로 묶는다.
