# 멀티플레이 어픽스·퀘스트·스토리라인 기획 초안

기준일: 2026-10-29. 사용자 확정사항과 검토용 제안을 구분한다. 이 문서의 신규 모드·퀘스트는 기획 단계이며 구현 완료를 뜻하지 않는다. 스토리 원문은 사용자가 직접 작성한다.

## 1. 적용 범위

| 항목 | 적용 범위 | 진행 구분 |
| --- | --- | --- |
| 메인 퀘스트 라인 ‘탐사’ | PvP·봇전 모두 | 공통 계정 진행 |
| 서브 퀘스트 | PvP·봇전 | PvP용과 봇전용을 분리 |
| 서브 스토리라인 | PvP·봇전 모두 | 공통 계정 진행 |
| 어픽스 챌린지 | 봇전 전용 | 일반 봇전과 선택 구분 |

메인 퀘스트는 스토리를 따라 게임의 규칙과 역할을 하나씩 익히도록 유도한다. 튜토리얼 성격의 퀘스트에는 스킵 버튼을 둔다.

## 2. ‘탐사’ 메인 퀘스트 라인

사용자가 제시한 각 목표는 하나의 별도 퀘스트다. 전체 라인은 다음 흐름으로 정리한다.

| 순서 | 퀘스트·단계 | 스토리 처리 |
| --- | --- | --- |
| 시작 | 기본 스토리 | 라인 시작 시 기본 내용 표시 |
| 1 | 튜토리얼 완료 (스킵 가능) | 해당 완료 스토리 추가 공개 |
| 2 | 어떤 매칭이든 게임 1번 플레이 | 해당 완료 스토리 추가 공개 |
| 3 | 3층 맵 탈출하기 | 해당 완료 스토리 추가 공개 |
| 4 | 2층 맵 탈출하기 | 해당 완료 스토리 추가 공개 |
| 5 | 백화점을 무사히 살아서 탈출하기 | 해당 완료 스토리 추가 공개 |
| 6 | 마네킹 튜토리얼 완료 (스킵 가능) | 해당 완료 스토리 추가 공개 |
| 7 | 마네킹으로 플레이어 1명 잡기 | 해당 완료 스토리 추가 공개 |
| 8 | 마네킹으로 승리하기 | 해당 완료 스토리 추가 공개 |
| 최종 | 튜토리얼 메인 퀘스트 ‘탐사’ 완료 | 마지막 완료 스토리 공개 및 라인 전체 완료 |

최종 완료는 앞의 필수 퀘스트를 끝냈다는 라인 종료 단계로 정리했다. 별도의 플레이 목표를 임의로 추가하지 않는다.

튜토리얼 플레이 퀘스트(1번·6번)는 스킵할 수 있다. 스킵하면 해당 튜토리얼을 플레이하지 않고 다음 퀘스트로 진행할 수 있으며, 스킵한 튜토리얼 때문에 라인 전체 완료가 막히지 않는다. 다른 플레이 목표까지 스킵 가능으로 확대하지 않는다.

### 스토리의 누적 공개

```text
시작:       기본 스토리
퀘스트 1 후: 기본 스토리 + 완료 스토리 1
퀘스트 2 후: 기본 스토리 + 완료 스토리 1 + 완료 스토리 2
...
최종 완료:  기본 스토리 + 완료 스토리 1 + ... + 마지막 완료 스토리
```

- 다음 스토리가 열려도 앞서 공개된 내용은 남긴다.
- 내용은 퀘스트 순서대로 이어서 읽을 수 있게 한다.
- 중간 퀘스트 하나를 끝낸 것은 개별 퀘스트 완료다. 스토리라인 전체 완료와 구분한다.
- 마지막 필수 퀘스트와 최종 완료 단계까지 끝내야 라인 전체 완료로 처리한다.
- 작성할 기본 데이터는 라인 이름, 기본 스토리, 각 퀘스트의 목표·완료 조건·공개할 스토리, 마지막 완료 스토리다.
- 스토리의 문장·문단은 사용자 원문을 사용한다. 줄거리를 임의로 창작하지 않는다.
- 서브 스토리라인도 개별 퀘스트 진행과 라인 전체 완료를 분리하고, 완료할수록 내용을 누적 공개한다.

튜토리얼 스킵 시 스토리·보상 처리, 이전 달성의 소급 인정, 경기 1회 플레이의 정확한 집계 시점은 아직 확정하지 않는다. PvE에서 포획·승리 목표를 진행하려면 상대 생존자 봇도 해당 역할의 대상으로 집계할 필요가 있다.

### 서브스토리라인 — 인물 7명의 연계 퀘스트

인물은 총 7명이며, 각자의 이야기를 해당 인물의 연계 퀘스트로 진행한다. 인물 이름과 스토리 원문, 개별 퀘스트의 내용·개수는 사용자가 작성한다.

```text
인물별 기본 스토리
  → 첫 번째 퀘스트 등장
  → 완료: 해당 완료 스토리 추가 공개 + 다음 퀘스트 등장
  → 완료: 해당 완료 스토리 추가 공개 + 다음 퀘스트 등장
  → ...
  → 마지막 퀘스트 완료: 마지막 스토리 공개 + 해당 인물의 라인 전체 완료
```

- 7명의 인물별로 퀘스트 진행 상태와 공개된 스토리를 구분한다.
- 각 인물의 다음 퀘스트는 이전 퀘스트의 완료·실패 결과와 진행 선택에 따라 등장한다. 이후 퀘스트를 처음부터 모두 활성화하지 않는다.
- 중간 퀘스트 하나를 끝내도 해당 인물의 전체 스토리라인이 완료되지는 않는다.
- 인물별 스토리는 톡 형태의 대화로 전개한다. 기본 대화에 완료한 퀘스트의 대화를 순서대로 더하며, 앞서 공개된 대화는 유지한다.
- 실제로 선택한 진행 경로의 마지막 필수 퀘스트까지 완료했을 때 해당 인물의 스토리라인 전체 완료로 처리한다. 선택하지 않은 대체 경로까지 모두 완료하도록 요구하지 않는다.
- PvP와 봇전 양쪽에서 진행할 수 있는 공통 계정 진행으로 유지한다. PvP용·봇전용으로 분리하는 일반 서브 퀘스트와 구분한다.
- 인물마다 퀘스트 수가 같아야 한다는 제한은 두지 않는다. 7명 사이의 추가 선행 조건이나 교차 연계는 아직 정하지 않는다.

#### 서브스토리 전용 대화·선택지

- 퀘스트 완료에 따른 이야기는 해당 인물과 주고받는 톡 형태로 공개한다.
- 대화 중 선택지가 제시되면 플레이어가 고른 답변에 맞는 후속 대화와 인물의 반응을 보여준다.
- 일반 대화 선택은 대사·반응 등 이야기 표현을 바꾼다. 이 유형의 선택은 다음 퀘스트와 목표를 바꾸지 않는다.
- 대화에서 어떤 답변을 골랐는지에 따라 퀘스트 경로 선택지가 추가·삭제되거나 자동 선택되지 않는다. 대화 반응과 실제 퀘스트 경로 선택은 독립적으로 관리한다.
- 일반 대화의 선택지 분기는 해당 반응 대화를 마친 뒤 공통 진행 지점으로 합류한다. 실제 진행 경로를 고르는 퀘스트 선택과 구분한다.
- 대화 기록에는 플레이어가 실제로 고른 답변과 그에 따른 반응을 남긴다. 선택하지 않은 반응을 같은 진행 기록에 섞어 표시하지 않는다.
- 캐릭터별 대화·선택지·반응 원문은 사용자가 작성한다.
- 이 톡·선택지 방식은 서브스토리에만 적용한다. 메인 퀘스트 ‘탐사’에 같은 대화 방식을 자동 적용하지 않는다.

#### 서브스토리 대화창의 등장·퇴장과 여러 인물 대화

- 대화창은 화면 아래에서 위로, 들어 올리는 듯한 움직임으로 등장한다.
- 대화가 끝난 뒤 ‘나가기’를 누르면 아래로 내려놓듯 움직여 닫힌다. 즉시 사라지는 방식으로 처리하지 않는다.
- 이 움직임은 대화창 패널의 열기·닫기 연출이다. 개별 메시지의 스크롤 동작과 구분한다.
- 한 인물 또는 하나의 대화만 가능한 구조로 제한하지 않는다. 다른 인물의 대화도 열어 진행할 수 있다.
- 인물별 대화 기록, 선택한 답변, 공개된 반응과 연계 퀘스트 진행 상태를 구분해 유지한다.
- 다른 인물과 대화해도 앞서 진행한 인물의 대화 내용과 진행 상태를 덮어쓰지 않는다.
- 여러 인물과 대화할 수 있다는 요구는 반영하되, 여러 대화창을 동시에 띄우는 방식까지 확정한 것은 아니다. 인물 선택·전환 배치는 별도로 정한다.

```text
서브스토리 퀘스트 완료
  → 해당 인물과 대화
  → 선택지
      ├ 답변 A → 반응 대화 A ┐
      └ 답변 B → 반응 대화 B ┘
  → 공통 후속 대화·진행 지점
  → 동일한 다음 연계 퀘스트
```

#### 퀘스트 진행 선택과 실패의 후속 영향

- 별도의 진행 선택 퀘스트에서는 플레이어가 실제로 수행할 퀘스트 경로를 고른다. 일반 대화 반응 선택과 다른 유형으로 관리한다.
- 선택한 경로의 퀘스트를 활성화한다. 선택하지 않은 대체 경로는 미선택 상태이며 실패로 집계하지 않는다.
- 퀘스트를 실패하면 그 결과에 따른 스토리와 부작용을 수습하는 후속 퀘스트가 등장할 수 있다. 실패를 성공 완료로 처리하지 않는다.
- 성공 후속 퀘스트와 실패 후속 퀘스트를 각각 지정할 수 있는 구조로 정리한다.
- 인물별 대화 기록에는 실제로 고른 경로와 성공·실패 결과, 그에 따른 후속 대화를 남긴다. 미선택 경로의 내용은 현재 진행 기록에 섞지 않는다.
- 분기가 다시 공통 퀘스트로 합류하는지, 다른 마지막 퀘스트로 이어지는지는 각 라인의 기획에 따라 정한다. 모든 분기의 결말이 같다고 미리 확정하지 않는다.
- 실패 부작용의 구체적인 내용과 지속 범위는 아직 정하지 않는다. 전투 능력 저하·재화 차감 등의 페널티를 임의로 추가하지 않는다.
- 이 진행 분기·실패 후속 구조는 현재 논의 중인 인물별 서브스토리라인에 반영한다. 메인 퀘스트 ‘탐사’의 기존 흐름은 자동 변경하지 않는다.

```text
인물별 연계 퀘스트
  → 진행 선택
      ├ 경로 A 퀘스트 → 성공 → A의 정상 후속 퀘스트
      │              └ 실패 → 실패 스토리 + 부작용 후속 퀘스트
      └ 경로 B 퀘스트 → 성공 → B의 정상 후속 퀘스트
                     └ 실패 → 실패 스토리 + 부작용 후속 퀘스트
  → 해당 경로의 이후 이야기
  → 선택한 경로의 마지막 필수 퀘스트 완료 시 인물 라인 전체 완료
```

## 3. 봇전 어픽스 모드 구성

| 모드 | 기본 난이도 | 어픽스 구성 |
| --- | --- | --- |
| 마스터+ | 마스터 | C그룹 10종 중 무작위 1개 |
| 마스터++ | 마스터 | A·B·C그룹에서 무작위로 각각 1개, 총 3개 |
| 주간 어픽스 | 쉬움·보통·어려움·전문가·마스터 | 운영자가 주간 컨셉에 맞춰 지정한 3개로 고정 |
| 사용자 지정 어픽스 | 쉬움·보통·어려움·전문가·마스터 | 사용자가 선택. 선택 개수 제한 없음 |

A그룹은 마네킹에 대응 가능한 약점을 더해 생존자에게, B그룹은 생존자의 행동에 추가 위험을 더해 마네킹에게 유리하게 한다. C그룹은 양쪽이 대응할 환경의 추가 규칙이다. ‘사람에게 유리/불리’와는 다르다. 사람이 마네킹을 플레이하는 봇전에서는 A그룹이 상대 생존자 봇에게 유리할 수 있다.

## 4. 추가 규칙형 어픽스 30종 제안

사용자가 말한 쐐기돌 어픽스·돌연변이원의 컨셉은 기본 경기 위에 고유한 추가 규칙을 조합하는 방향으로 해석한다. 아래는 앞서 작성한 수치 강화·행동 지연 중심 초안을 교체한 제안이다. 참고 게임의 개별 효과를 그대로 복제하는 목록은 아니다.

### 바꾸지 않는 메인 플레이

- 생존자는 기존 동선과 상호작용으로 탈출하고, 마네킹은 기존 몸체·명령·직접 조작으로 이를 저지한다.
- 역할 정원, 승패 조건, 탈출·포획·구출 조건, 기본 데스카운트와 피격 무적을 어픽스 때문에 바꾸지 않는다.
- 실제로 바라보는 마네킹은 멈춘다. 벽 너머 공격·실시간 위치 추적·보이지 않는 공격 판정을 허용하지 않는다.
- 새 조작키, 필수 수집품, 추가 적, 별도 보스전, 반드시 수행할 보조 목표를 넣지 않는다. 구출·엘리베이터·셔터는 원래 가능한 경우에만 사용한다.
- 달라지는 것은 접근 시점, 이동 경로, 거리, 소리와 시야의 활용이다. 새로운 장르나 별도 게임 루프를 만들지 않는다.

각 항목은 발생 조건 → 알아볼 수 있는 현상 → 기존 조작으로 가능한 대응으로 구성한다. 이름·조건·시간·범위는 검토용이며 구현 완료나 최종 밸런스를 뜻하지 않는다. 새 오브젝트가 필요한 효과는 준비된 맵에서만 지원한다.

| A09 남는 경직 + B10 들뜬 바닥 + C04 순차 셔터 | 생존자는 충분히 바라봐 이동 여유를 만든 뒤, 체력을 써서 셔터 전에 달릴지 돌아갈지 선택 | 마네킹 응시 정지·기존 이동·셔터 통과 |
| A01 점검 조명 + B06 호출 표시등 + C08 멈칫하는 승강기 | 호출 장소는 드러나고 대기는 길어지지만 점검 조명이 켜진 위치를 잠시 엄호에 활용 | 같은 호출·주변 엄호·탑승·맵 전환 |

예시는 전술의 가능성을 보여주는 초안이다. 반드시 이 행동만 해야 통과하는 퍼즐로 만들지 않는다. 각 조합이 어느 역할에 얼마나 유리한지는 실제 플레이로 검증한다.

## 5. 구현 시 지켜야 할 범위와 조합 원칙

- 이 문서는 기획 초안이다. 기존 일반전·싱글·튜토리얼·연습 AI나 맵을 이 문서만으로 변경하지 않는다.
- 추가 규칙은 명확한 발생 조건, 알아볼 수 있는 예고·현상, 제한된 지속 시간, 기존 조작으로 가능한 대응을 갖춘다. C06·C07처럼 시작부터 고정되는 조건은 시작 전에 구성을 알려주고 맵에서도 식별 가능하게 한다.
- 다른 게임의 공략을 복제하기보다 백화점 조명·진열·운행·소리·마네킹 몸체라는 기존 소재를 활용한다. UI에 장황한 설명을 자동 추가하라는 요구로 해석하지 않는다.
- 추가 현상은 제한된 예산 안에서 발생시킨다. 불규칙한 간격을 사용해도 반응할 시간 없이 연속 발동하거나 한 지점에 몰아 쌓이지 않는다.
- 같은 역할이면 사람과 봇 모두 같은 실행 제약을 따른다. 봇은 감각적으로 얻지 못한 정보를 사용할 수 없고, 표시된 바닥·조명·대기 상태에 대응할 수 있어야 한다. 지원 전에는 그 효과를 활성화하지 않는다.
- 난이도 1~5의 반응·협동·패턴 상한을 유지한다. 어픽스를 이유로 1~3단계에 잠긴 심리전이나 6·7단계 AI를 추가하지 않는다.
- A01·A02·A03·A09·A10·C10의 이동 둔화는 가장 강한 하나만 사용하고 초안에서는 총 30% 감소를 상한으로 둔다. 시야 회전·이동 방향 입력을 잠그거나 영구 정지시키지 않는다. 실제 응시에 따른 정지는 별도 핵심 규칙이다.
- 과호흡·회복 중단·피격 무적·공격 회복의 기준 시점을 분리한다. 한 타이머 종료가 다음 타이머를 무한 재시작하지 않게 한다. 피해 중복·무적 우회·회복 불가능 상태를 만들지 않는다.
- 입력·명령을 무작위로 무시하거나 목표를 바꾸지 않는다. 임시 둔화·감각 공유 중단이 끝나도 사용자가 내린 지속 명령은 유지한다. 사망·경기 종료 같은 필수 판정은 지연하지 않는다.
- 조명·안개·소리 차폐는 사람·AI 판정에 일관되게 연결한다. 청각·시각 접근성 설정을 강제로 켜거나 잠그지 않으며 대체 표현까지 검증한다. 카메라 강제 회전·과한 섬광·과도한 음량에 의존하지 않는다.
- 자국·섬광·소리는 실제 현장의 단서다. 벽 너머 표시, 관전·사망자의 새 정보 전달, 정확한 현재 위치의 전역 공개를 추가하지 않는다.
- 구출·셔터·엘리베이터 및 구역·바닥·배치가 필요한 효과는 실제 지원되는 맵에서만 선택 후보로 삼는다. 목적지 층까지 지원을 확인하며 효과가 없는 것을 정상 적용처럼 표시하지 않는다.
- C04·C06·C07·C10은 개별 검증에 더해 조합된 최종 경로와 모든 역할의 충돌 크기를 검사한다. 스폰·바닥·문·탈출 경로를 막는 조합은 시작 전에 사용 불가 처리한다. 선택 개수 제한 없음과 지원 불가능한 조합 허용은 다르다.
- A01 조명과 C01 정전처럼 같은 자원을 쓰는 효과는 우선순위를 정한다. 점검 조명은 일반등 정전과 별도로 식별 가능하게 두며, 안개·방송이 겹쳐도 예고가 모두 사라지지 않게 한다.
- 조합 상한·동시 발생 제한·지원 맵은 사용자 지정뿐 아니라 주간 3종과 마스터 무작위 선정에도 동일하게 적용한다. 이벤트 처리가 밀리면 한꺼번에 재생하지 않고 유효한 것만 제한적으로 처리한다.
- 경기 시작 시 목록을 확정하고 같은 경기의 층 이동에도 유지한다. 층별 이벤트 위치·순간 상태는 도착 맵에서 새로 초기화하고 과거 맵의 자국·몸체·예약 공격·공유 정보·타이머를 가져오지 않는다. 주간 설정 변경은 이후 시작 경기부터 적용한다.
- 효과는 원본 설정에서 한 번 계산한다. 층 이동·재접속 때 배율을 다시 곱하지 않으며 종료·사망·강제 퇴장·대상 삭제 시 관련 타이머와 입력 잠금을 정리한다.
- 승강기 지연 등 정상 대기가 서버 타임아웃을 넘지 않게 최대 시간을 대조한다. 로딩·관전 전환·결과 표시를 기다리는 동안에는 추가 위험을 멈추고 기존 전환 흐름을 유지한다.

공식 기록·레이팅·경험치·포인트·퀘스트 집계 정책은 아직 별도 확정이 필요하다. 기존 오픈매칭 커스텀 규칙의 보상 정책을 자동 대입하지 않는다. 전체 목록과 수치는 검토용이며 구현 가능 여부, 역할별 유불리와 재미는 실제 조합별 플레이로 검증한다.
