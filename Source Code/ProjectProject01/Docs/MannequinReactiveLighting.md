# 마네킹 반응 조명

기존 `AMannequinReactiveLight` 배치 액터를 그대로 사용한다. 타이틀 전용 조명·손전등·출구 표시·일반 조명에는 자동으로 덧씌우지 않는다. 싱글과 멀티의 클라이언트에서 표현하며 전용 서버는 실행하지 않는다.

현재 강도(최신 후속 요청 반영): 복도 조명을 기준으로 기본·테스트 광량 약 83786.4, 기존 높은 천장 맵 약 940195.0. 전구 발광 7, 전기 잡음 음량 배율 0.45. 소등 구간은 광량·발광 0이며 전압 붕괴·불완전 복구 두 종류에만 별도 잔광 구간을 섞는다. 회복 깊이는 90~100%에서 선택하고 발생 강도 0.15 이상은 소등 목표에 완전히 도달한다. 먼 거리·위협 해제 시에는 강도로 정상 광량에 보간한다. 패턴 5종·3개 단위 단계·접근성 설정은 유지한다. 아래 기록은 변경 순서이며 맨 아래 조정이 최신이다.

## 발생 기준

- 각 전등 아래 `DetectionRadius`(기본 15m)의 수평 범위 안에 있는 같은 층 마네킹 몸체를 센다. 카메라 위치·시선·동결·직접 조작 여부와 무관하다.
- 0~2개는 새 고장을 발생시키지 않는다. 3~5 / 6~8 / 9개 이상이 세 단계다.
- 광원 아래 실제 바닥을 충돌 조회해 기준 높이를 캐시한다. 마네킹 발과 이 바닥의 기본 수직 허용 간격은 4.5m다. 전등이 움직이면 다시 조회하며, 스트리밍 중 바닥을 찾지 못한 경우 1초 이후 재시도한다. 높은 천장도 카메라에 의존하지 않는다.
- 전등과 마네킹의 수평 거리로 강도를 보간한다. 카메라 거리는 발생 강도에 곱하지 않는다. 카메라는 해당 조명의 빛·소리가 플레이어에게 영향을 줄 수 있는지 계산 절약에만 사용한다.

## 고장 패턴

1. 전압이 급격히 꺾인 뒤, 회복을 시도하다 다시 내려앉는 단계형 복구.
2. 한 번 짧게 어두워졌다 복구.
3. 시간차를 둔 두 번의 깜빡임.
4. 점등을 시도하다 실패한 뒤 재복구.
5. 갑자기 낮은 밝기로 내려앉고, 중간에 빛이 붙었다 다시 꺾이는 불완전한 복구.

같은 패턴은 바로 연속 선택하지 않는다. 지속 시간·깊이·고장 사이의 정상 유지 시간·소리 발생 여부를 사건마다 뽑으며 렌더 프레임마다 난수를 뽑지 않는다. 강도가 높아져도 반복 속도만 무한히 올리지 않고 낮은 밝기의 지속 시간과 발생 빈도를 늘린다. 각 전등은 별도 시드로 패턴을 고르되, 가까운 전등들은 불규칙한 전원 이상을 공유해 여러 개의 고장이 겹칠 수 있다. 같은 박자로 복제 재생하지는 않는다. 범위를 벗어나도 진행 중인 고장은 강도가 서서히 줄며 끝난다.

구분 강화와 긴박한 박자: 하강은 빠르게 꺾이고 복귀는 불완전하게 여러 번 시도한다. 한 번 끊김은 짧게 끝나며 두 번 끊김은 사이에 정상 밝기 구간을 둔다. 점등 실패는 여러 차례 다시 켜지다 끊긴다. 낮은 밝기 잔류는 더 오래 유지하지만 시작부터 느긋하게 페이드하지 않는다. 거리가 멀거나 천장이 높아도 시간 구조를 읽을 수 있도록 광량 변화에 연속적인 제곱근 대비 곡선을 적용한다. 밝기 상한·하한과 접근성 배율은 그대로다.

## 광량과 소리

- 원래 광량보다 밝아지는 섬광 없음. `MinimumBrightnessFraction` 기본값 0으로 소등 구간에는 해당 전등을 완전히 끈다. 필요하면 개별 배치에서 잔광 하한을 올릴 수 있다.
- Spot Light와 전구의 기존 emissive 파라미터를 함께 조절한다. 배치 메시·기존 광량·머티리얼은 보존한다.
- 전등 위치에서 낮은 전기 웅웅거림과 거친 잡음을 합성한다. 사건 중 일부는 무음이다. 3D 위치·거리 감쇄·벽 차폐·SFX 음량 설정을 따른다.
- 번쩍임 설정 0은 정상 광량 유지, 부분 설정은 변화량 축소. 다른 클라이언트 설정에는 영향을 주지 않는다.
- 경기 결과 상태, 액터 종료·맵 전환·체크포인트 복원에서는 음원을 정리한다. 복원 후 감지와 연출을 새로 시작한다.

## 비용 및 규칙 분리

몸체 위치 목록과 시야 자료는 월드별 저빈도 캐시를 공유한다. 화면의 빛이나 가까운 전기 소리에 영향을 줄 수 있고 고장 강도가 남아 있는 조명만 30Hz로 보간한다. 먼 조명은 전기 음원을 생성하지 않는다. AI 시야·시선 정지·충돌·이동·피해 판정과 서버 규칙은 변경하지 않는다.

- 화면 자료는 월드별 최대 0.05초 간격의 캐시를 공유한다. 시야 자료가 없을 때는 조명을 끄는 대신 계산을 유지한다. 보수적인 시야 밖 제외이므로 벽 차폐를 완벽하게 판별하는 CPU 오클루전 기능은 아니며, 화면에 영향을 줄 수 있는 빛을 잘못 끄지 않는 쪽을 택한다.
- 불규칙한 공유 이상도 전등 위치·바닥별 주변 그룹으로 분리했다. 무관한 구역의 0개 전등이 다른 구역의 공유 주기를 초기화하지 않는다. 오래 사용하지 않은 그룹은 정리하고, 그룹 재생성·이동 때 사건 번호를 새로 연결해 중첩이 멈추지 않게 한다.
- 최종 빌드 성공. 실제 테스트 카메라를 200m 옮겨도 감지 수·강도가 유지되는지, 12.8m 천장 바닥 기준·다른 층 제외·전구는 화면 밖이지만 바닥이 보이는 경우·먼 빛 제외·쉬는 동안 계산 중지·부드러운 복귀·완전 소등·기존 중첩·렌더·접근성을 포함한 검사 7개 모두 성공(경고·실패·미실행 0). 보고서: `Saved/ReactiveLightQA/FixtureVisibilityFinal/index.json`.
- 시야 검사는 자동 검사에서 실제 광원 경계와 지정 시야 체적을 비교했으며, 여러 PC의 실제 화면 전환 체감이나 FPS 개선량을 측정한 것은 아니다. 에셋 재저장·패키징은 수행하지 않았다.

- 전체 깜빡임에 더해 발광판 내부 3개 영역이 서로 다른 밝기로 불규칙하게 떨리고 끊기는 표현을 기존 5종에 연결했다. 고장 구간에만 0.055~0.19초 간격으로 약해질 영역을 예약하고, 일부는 두 영역이 함께 약해져 한쪽만 빛이 남는다. 영역 상태용 난수는 전체 패턴과 별도 시드를 사용한다.
