# 외곽 중심 현기증 VFX

> 현재 구조: 별도 `VertigoShader.h`와 `VertigoTests.cpp`는 사용자 요청으로 제거했다. 셰이더 코드는 기존 `ProjectProject01EditorModule.cpp`의 심박 머티리얼 생성 함수에 통합했다. 아래 이전 검사 내용은 변경 이력이며, 현재 사용법은 마지막 ‘다중 머티리얼 선택 및 실제 연결’ 절을 따른다. 기존 Vertigo 전용 콘솔 명령도 제거했다.

2026-10-17 변경. 기존 전체 코드 검토의 30개 수정 작업과는 별개로, 사용자가 추가 요청한 시각 연출 조정만 수행했다.

## 변경 내용

- 기존 화면 전체의 동일한 사인파/가로 물결을 제거했다.
- 외곽에서 초점이 풀리는 흐림, 약한 이중상, 천천히 불규칙하게 변하는 시야 쏠림을 조합했다.
- 중앙 반경은 보호하고 바깥으로 갈수록 강해지게 했다. 방향별 강도도 다르게 변화한다.
- 매 프레임 난수를 뽑는 깜박임이 아니라 연속 보간된 느린 잡음으로 변화를 만들었다.
- 밝은 섬광 대신 약한 회색 안개와 초점 흐림을 사용한다. 카메라를 실제로 크게 회전시키거나 이동 입력을 바꾸지 않는다.
- 플레이어마다 다른 시작 위상을 사용한다. 접근/밀집도·거리 조건, 기존 데이터테이블의 강도·속도·주파수 파라미터, 로컬 VFX/일렁임 감소 설정은 유지했다.
- 일렁임 강도 0이면 추가 흐림/잔상/안개도 사라진다. 일반 엔진 모션 블러와는 별도의 현기증 효과다.

## 적용 경로

`M_HeartbeatScreenVFX`의 새 그래프/셰이더를 실제 `.uasset`으로 생성·컴파일·저장했다. 별도 느슨한 HLSL/CSV 파일을 클라이언트가 읽는 구조가 아니다. `/Game/MyProject/VFX`는 기존 AlwaysCook 대상이다.

일반 머티리얼 재생성 명령에도 새 구조를 반영했다. 보관용 노이즈 머티리얼은 이번에 다시 생성하지 않았다. 활성 현기증 머티리얼만 재생성하는 명령은 `ProjectProject01.CreateHeartbeatVertigoMaterial`이다.

클라이언트에 배포하려면 새 머티리얼을 포함하여 다시 패키징/업데이트 게시해야 한다. 게임 규칙·네트워크 프로토콜 변경은 없으며 이 로컬 연출만을 위해 데디 서버를 다시 패키징할 필요는 없다.

## 검증

- Editor Development 빌드 성공.
- Win64 Shipping 빌드 성공. 전체 쿠킹/패키징 실행은 하지 않았다.
- 새 머티리얼 생성·셰이더 컴파일·저장 성공.
- DX12/SM6 자동 검사 4개 모두 통과: `Vertigo.RenderAndAccessibility`, 기존 `DeathFallDirection`, `HeartbeatVFXMapping`, `StaminaRules`.
- 중앙 시야 보존, 외곽의 실제 렌더 변화, 서로 다른 시간 위상의 변화, 불투명도 0의 해제를 검사했다. 원래 OFF 화면도 프레임별 렌더 노이즈가 있으므로 반복 OFF 촬영으로 기준 편차를 측정하고 비교했다.
- 최종 평균 RGB 차이(3채널 절댓값 합, 채널 범위 0~255): 중앙 5.042/기준 4.972, 외곽 53.112/기준 4.406, 비활성화 4.529/기준 4.555. 중앙·비활성화는 기준 편차 수준이고 외곽만 그보다 크게 변했다.
- 최종 결과: `Saved/VertigoChecks/AutomationCalibrated/index.json`, 로그: `Saved/VertigoChecks/EditorCalibrated.log`. 비교 이미지는 같은 폴더의 `Off.png`, `Vertigo.png`, `VertigoLater.png`, `OpacityZero.png`, `BaselineRepeat.png`다.

초기 렌더 테스트는 조명 없는 기준 장면과 수동 SceneCapture의 뷰 상태/동일 프레임 비교 문제로 실패했다. 테스트 장면 보정 과정에서 임시 머티리얼을 직접 재컴파일하던 개발용 검사 프로세스가 한 번 종료되었으며, 해당 경로는 제거했다. 플레이 코드의 크래시 재현이 아니다. 실패 로그는 `Saved/VertigoChecks/`에 남겨 최종 통과 결과와 구분한다.

## 실제 플레이 확인

1. 싱글 또는 멀티 생존자로 심박 VFX 조건을 만족시키고 중앙보다 외곽에서 흐림/약한 겹침이 생기는지 확인한다.
2. 그 상태로 잠시 머물러 모든 부위가 일정한 박자로 동시에 흔들리지 않는지 확인한다.
3. 환경설정의 일렁임 감소/강도를 낮추고 0으로 하여 추가 효과도 감소/제거되는지 확인한다.
4. 범위 밖으로 나가거나 게임을 종료했을 때 기존 해제 조건대로 제거되는지 확인한다.

연출의 ‘현기증처럼 느껴지는 정도’는 주관적인 부분이므로 최종 강도는 실제 플레이에서 확인해야 한다.

## 소폭 강도 상향

사용자의 추가 요청에 따라 정규화 강도 계수를 20% 상향했다(분모 0.012 → 0.010). 중앙 보호 범위, 움직임 속도, 데이터테이블 값과 기존 접근성 설정은 바꾸지 않았다. 지각되는 연출 전체가 정확히 20% 증가한다는 뜻은 아니다.

기존 검사가 고정 amount=0.012를 사용했던 점을 보완하여 실제 `DT_PlayerTuning` Default 행을 로드하도록 변경했다. 실제 값은 amount=0.003, speed=2, frequency=35로 확인했다. 이 값으로 활성 머티리얼 생성·컴파일·저장과 렌더 포함 4개 자동 검사가 모두 통과했다.

최신 평균 RGB 차이: 중앙 5.042/기준 4.972, 외곽 11.414/기준 4.406, 비활성화 4.529/기준 4.555. 위 초기 검증 수치는 더 강한 합성 입력 조건이고, 이 수치가 현재 게임 튜닝 조건의 결과다. 최신 결과는 `Saved/VertigoChecks/AutomationMildGain/index.json`, 로그는 `Saved/VertigoChecks/EditorMildGain.log`에 남겼다.

## 실제 PIE에서 보이지 않는다는 재현 후 수정

- `LevelTest01`을 실제 PIE로 실행해서 확인했다. `BP_PlayerCharacter` 카메라의 PostProcessBlendWeight=1, 머티리얼 weight=1, DistortionAmount=0.0024, EffectOpacity 약 0.66으로 전달됐다. 머티리얼 경로 누락이나 카메라 미부착으로 단정할 수 없었다.
- 기존 셰이더는 실제 최대 튜닝 0.003을 0.010으로 정규화하고, 작은 이동·흐림을 계산한 다음 최종 장면 혼합에도 그 강도를 다시 곱했다. 밀집도와 불투명도가 더해지는 실제 플레이 조건에서는 변화가 지나치게 작아졌다. 앞선 20% 계수 조정만으로는 해결하지 못했다.
- 실제 기준 0.003으로 정규화하고, 강도는 이동/초점 흐림에 적용하되 최종 혼합에서 중복으로 줄이지 않도록 수정했다. 외곽 이동·흐림 반경도 보정했다. 중앙 보호와 강도 0의 완전 해제는 유지한다.
- 런타임 검사에는 실제 블루프린트, 데이터테이블, 마네킹 두 개, 실제 컴포넌트 Tick과 CalcCamera를 사용한다. PIE 검사에는 원본 `LevelTest01`을 복제한 플레이 월드를 사용하며 원본 맵을 저장/수정하지 않는다.
- PIE 카메라의 실제 MID 파라미터를 복사한 SceneCapture로 ON/OFF/반복 OFF 화면을 비교한다. 이는 실제 맵과 실제 카메라 파라미터의 렌더 확인이며, 사용자 PC에서의 최종 연출 체감이나 모든 멀티 상황의 육안 확인을 대신하지는 않는다.
- Rider/Visual Studio 솔루션 및 Rider 프로젝트 메타데이터도 요청에 따라 다시 생성했다. 새 셰이더 헤더와 자동 검사 소스가 프로젝트 목록에 포함됨을 확인했다.
- 최종 Editor 빌드와 머티리얼 재생성/저장 완료. `RuntimeVerified/index.json`의 6개 검사는 실패 없이 완료(일반 성공 4, 엔진 경고 동반 성공 2)했다. 실제 맵 외곽 RGB 차이는 ON 25.969 / 반복 OFF 6.428, 두 마네킹 강도 렌더는 외곽 33.138 / 기준 4.386, 중앙 4.975 / 기준 4.992, 비활성 4.594 / 기준 4.556이었다. 비교 화면은 `Saved/VertigoChecks/PIE_Off.png`, `PIE_On.png`, 검사 로그는 `Saved/VertigoChecks/RuntimeVerified.log`다.

## 다중 머티리얼 선택 및 실제 연결

- Tools의 `Create or Repair Heartbeat Screen VFX Materials`를 누르면 기본 머티리얼 선택창을 띄운다. Ctrl/Shift로 여러 개를 고르고 열기를 누른다. 머티리얼 인스턴스는 노드 그래프 편집 대상이 아니므로 제외한다.
- 확인창에는 선택한 개수·전체 경로와 기존 노드를 심박 현기증 VFX로 교체한다는 경고가 나온다. 취소하면 그래프와 연결을 변경하지 않는다.
- 선택한 모든 머티리얼을 생성 함수에서 재생성·컴파일·저장하고, 그 목록 전체를 `Config/DefaultGame.ini`의 `[ProjectProject01.HeartbeatVFX]` 아래 `+Materials=` 배열로 저장한다. 목록은 기존 선택을 대체하며 중복 경로는 제거한다. 다른 설정 절은 보존한다.
- 런타임 `UPlayerHeartbeatComponent`가 같은 목록을 읽어 실제 활성 카메라에 각각 MID를 연결한다. 거리·밀집도·접근성 설정의 파라미터를 모든 MID에 갱신하고, 해제 시 전체를 제거한다. 목록이 없으면 기존 단일 Material 키/블루프린트 기본 경로를 호환 경로로 사용한다.
- PIE 중 적용하면 이전 MID들을 제거하여 다음 로컬 Tick에 새 목록으로 연결한다. 각 연결의 머티리얼·소유자·카메라·후처리 가중치는 Output Log의 `[HeartbeatVFX]`에 출력한다.
- 여러 머티리얼을 선택하면 각 후처리가 중첩된다. 임의로 하나만 적용하거나 한 개로 축소하지 않는다. 보관용 노이즈는 자동 재생성하지 않으며, 사용자가 선택한 경우에만 해당 자산도 새 그래프로 바뀐다.
- 선택한 패키지를 ModifyCook에 추가하여 기존 VFX 폴더 밖의 프로젝트 머티리얼도 다음 쿠킹에 포함한다. 실제 전체 패키징은 이 작업에서 실행하지 않았다.
- 원래 콘솔 명령 `ProjectProject01.CreateHeartbeatVFXMaterial`은 저장한 목록을 사용한다. 머티리얼의 전체 오브젝트 경로를 공백으로 여러 개 전달할 수도 있다. 이 명령은 비대화형 검사/배치용이므로 UI 덮어쓰기 확인은 거치지 않는다.
- 삭제한 소스가 Rider 목록에도 남지 않도록 프로젝트 메타데이터를 다시 생성했다. 과거 검사 결과물은 `Saved/VertigoChecks`의 기록으로만 남아 있다.
- 이번 변경은 Editor Development와 Win64 Shipping 빌드가 모두 성공했다. 일회성 검사로 실제 `LevelTest01` PIE 카메라의 WeightedBlendables에 선택한 두 머티리얼의 MID가 각각 들어감을 확인했다. 원래 선택으로 복원한 뒤 임시 머티리얼 2개와 검사 스크립트는 제거했다. 로그: `Saved/HeartbeatMaterialSelectionCheck3.log`의 `PASS` 항목. 보관용 `M_HeartbeatScreenNoiseVFX.uasset`의 해시는 검사 전후 동일했다. 선택창 자체를 마우스로 누르는 육안 검사는 수행하지 않았다.

## 불규칙한 기하 왜곡 강화

- 같은 기존 머티리얼 생성 함수 안에서 수정했다. 별도 셰이더/소스 테스트 파일은 다시 만들지 않았다.
- 기존 공간 사인파와 회전하는 로브를 제거하고, 사인파를 쓰지 않는 해시 기반의 매끄러운 1차원/2차원 잡음으로 교체했다. 두 공간장이 서로 다른 방향으로 이동하고 좌표 자체도 변형되어, 화면 각 부위의 휨·쏠림·늘어짐이 같은 박자를 따르지 않는다.
- 시간도 느린 잡음으로 변형하여 움직임 속도와 세기 상승 구간이 일정한 주기로 반복되지 않게 했다. 매 프레임 난수를 바꾸는 깜박임은 사용하지 않는다.
- 흐림만 남지 않도록 실제 낮은 밀집도에서의 기하 변위를 높이고, UV 변위 길이는 최대 0.024로 제한했다. 중앙 보호 반경과 기존 외곽 초점 흐림은 유지한다.
- 런타임 거리·밀집도 계산은 수정하지 않았다. 범위 밖은 완전 투명/분리, 가까워질수록 불투명도 증가, 적 수가 많아질수록 설정된 최대치까지 왜곡 강도 증가다. 처음 접근 시 보간과 접근성 강도 설정도 그대로다.
- Editor 빌드와 현재 연결 머티리얼 재생성·컴파일·저장 완료. `LevelTest01`의 1280×720 SceneCapture에 두 마네킹 기준 파라미터(amount=0.0012, speed=1.01, frequency=17.6, opacity=0.75)를 적용해 시간 위상별 렌더를 비교했다. 높이 30px의 벽/하늘 경계는 OFF와 반복 OFF가 x=629로 같았고, 위상별로 x=640/632/631로 변했다. 흐림만 바뀌는 게 아니라 실제 기하 경계가 서로 다르게 움직임을 확인했다. 중앙 보호·거리 계산은 코드 기준이며, 이번 검사는 실제 플레이 세션 전체의 육안 검사를 대신하지 않는다.
- 비교 이미지: `Saved/HeartbeatWarpPreview/Off.png`, `Warp0.png`, `Warp3.png`, `Warp8.png`, `Baseline.png`. 최신 로그: `Render3.log`. 초기 수동 캡처는 이미지 읽기 시점 문제로 위상 비교에 사용하지 않았으며, 최종 검사는 매 프레임 렌더와 파라미터 갱신/읽기 프레임 분리 후 수행했다. 임시 렌더 검사 스크립트는 제거했다.
