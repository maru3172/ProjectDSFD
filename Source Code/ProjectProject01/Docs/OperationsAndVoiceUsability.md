# 음성 편의 기능과 서버 운영 보완

목표·진행 상황 UI(제외 요청한 2번)는 추가하지 않았다.

## 반영 및 재실행

- 도우미와 백엔드는 최신 소스로 빌드하여 다시 실행해야 한다. 실행 중인 운영 프로세스는 자동으로 중지하지 않았다.
- 클라이언트 UI/음성 설정은 클라이언트 재패키징 또는 새 업데이트 게시 후 반영된다.
- 방별 서버 배정은 **데디케이티드 서버도 재패키징**해야 한다. 같은 소스 엔진으로 클라이언트/서버를 빌드한다.
- 기존 MySQL 데이터는 유지한다. 백엔드 시작 시 `account_restrictions`, `game_server_slots` 테이블을 추가하고 기존 `lobby_state.max_rooms`를 사용한다. 초기화/삭제는 필요 없다.

## 최대 방 수와 동시 경기

1. MySQL → 백엔드를 시작한다.
2. 도우미 메인 창의 **방 한도 설정·적용** → 숫자 지정 → **서버에 적용**을 누른다(1~100개, 기존 기본값 30개). 기존 서버 운영 → 최대 방 수에서도 같은 설정을 변경할 수 있다.
3. 대기/시작 준비/경기 중 방을 모두 합산한다. 한도 축소 시 기존 방은 삭제하지 않으며, 개수가 한도 아래로 내려가기 전까지 새 방 생성을 거부한다. 값은 DB에 저장되므로 백엔드를 재시작해도 유지된다.
4. 도우미 메인 창의 **최대 동시 경기 수**를 방 한도 이하에서 선택하고 **동시 경기 수 적용**을 누른다. 백엔드가 성공 응답한 뒤 도우미에도 저장한다. 준비·진행 중인 세션이 있으면 변경을 거부하고 기존 설정/경기를 유지한다. 세션이 없는 동안에는 운영을 중지하지 않고 한도만 바꿀 수 있다. 운영 중지 상태에서 한도만 적용해도 운영이 자동 시작되지는 않으며, **게임 서버 운영 시작**을 별도로 눌러야 한다. 이 버튼은 운영 활성화이며 경기 서버를 미리 실행하지 않는다. 백엔드 재시작 후에도 도우미에서 저장한 수로 운영을 다시 활성화한다.
5. `-port=7777` 기준으로 7777, 7778, 7779 … 연속 UDP 포트를 사용한다. 수를 늘리면 도우미의 **IP 직접 연결 방화벽 설정**을 다시 실행한다. 이 버튼을 누르기 전에는 방화벽을 변경하지 않는다. 외부 인터넷 운영 시 공유기 포트포워딩도 해당 범위가 필요하다. MySQL 3307은 외부에 공개하지 않는다.

방에서 시작을 누르면 먼저 **게임 시작 준비 / 5…4…3…2…1…**을 표시한다(`Starting`). 카운트다운 중에는 프로세스/역할/입장 허가가 없다. 5초가 지나 방장이 확정하면 대기열(`Queued`)에 들어가 **세션 찾는 중…**을 표시한다. 한도가 꽉 차 있어도 방과 로그인을 유지하고 먼저 기다린 방부터 빈 세션을 예약한다. 예약한 방만 프로세스를 실행한다(`Preparing`). 실제 데디 서버의 준비 완료 heartbeat 뒤 서버가 MatchId/역할을 배정하고 입장을 허용한다(`Started`). 이때만 **게임을 시작합니다 / 역할: …**을 표시하며 2초 암전 후 접속하고, 게임 월드 준비 완료 후 기존 페이드 인으로 화면을 드러낸다. 대기 중에는 화면을 검게 가리지 않으며 준비 완료 뒤 카운트다운을 반복하지 않는다. 포트/부팅 ID/준비 여부/MatchId와 별도로 관리 세션 식별자를 대조하므로 오래된 세션 또는 구형 데디의 heartbeat를 준비 완료로 오인하지 않는다.

카운트다운 중에는 기존 취소 버튼을 사용하고, 자리 대기/서버 준비 중에는 **세션 대기 취소**를 누른다. 자리 대기는 최대 120초, 예약 뒤 서버 준비는 최대 90초다. 확정 응답 없는 카운트다운은 30초 후 해제된다. 시간 초과·실행 실패·프로세스 크래시·인원 변경·운영 중지 시 대기열/역할/입장 티켓을 정리하고 기존 방과 로그인을 유지한다. 대기 취소나 시간 초과 후 뒤늦게 실행하지 않는다. 서버와의 통신 자체가 끊긴 경우에는 기존 인증/연결 실패 처리를 따른다. 실제 시작이 허용되어 역할을 표시하고 암전하는 동안에는 시작 취소를 허용하지 않는다.

경기 종료 후 전원이 방으로 돌아오거나 방이 사라지면 해당 프로세스를 종료한다. 한 명만 복귀했다면 남은 경기 세션을 종료하지 않는다. 모두 네트워크로 이탈한 경우에는 기존 재접속 유예를 존중하며, 유예가 끝나 빈 서버로 돌아왔다는 응답이 있어야 정리한다. 정상 정리는 세션 전용 종료 신호 파일을 통해 UE의 Shutdown을 실행하여 정상 종료가 크래시로 잘못 수집되지 않도록 한다. 5초 내 정상 종료하지 않는 프로세스만 강제 종료한다. 전체 운영 중지는 진행 중인 경기까지 종료하는 관리자 작업이다. 백엔드를 재시작하면 운영은 비활성 상태이므로 도우미에서 다시 활성화해야 한다. 관리 데디는 운영 백엔드에 30초 동안 정상 응답을 받지 못하면 고아 프로세스로 남지 않도록 종료한다.

이 구현은 **한 서버 PC의 경기별 프로세스**를 자동 관리하는 방식이다. EOS/OnlineSubsystem의 세션 목록 API를 새로 도입한 것이 아니며, 기존 백엔드 방과 MatchId를 경기 세션으로 관리한다. 하나의 UE 프로세스 안에서 서로 독립된 여러 경기 월드를 동시에 실행하는 기능이나 다중 클라우드 호스트 오케스트레이터는 아니다. 로그는 `Saved/GameServerSessions/Session-{port}-{id}.log`에 저장한다.

스모크 테스트는 실제 서버 heartbeat를 위조하지 않는다. 전체 흐름 테스트 전 경기 세션 운영과 최신 데디 패키지를 준비한다. 세션 준비 단계는 별도 100/110초 제한 시간으로 기다리고, 나머지는 기존 단계별 제한 시간을 유지한다. API 검사는 실제 Unreal 클라이언트 6명/서버 2개 접속을 대신하지 않는다.

## 음성 편의 기능

환경설정 → 사운드 → **음성 채팅 설정**:

- 입력/출력 장치 선택, 새로고침, 시스템 기본 장치로 복귀.
- 보이스 수신 음량 게이지와 퍼센트. 전체 음량/전체 음소거/백그라운드 음소거도 함께 적용.
- 마이크 테스트: 입력 레벨 게이지만 표시하며 녹음 파일을 만들거나 네트워크로 송신하지 않는다. 테스트 중 경기 음성 송신도 중지한다. 테스트 중지/장치 변경/뒤로 가기/로그아웃 시 캡처를 닫는다.
- 같은 생존자 채널의 동료를 개별 음소거/해제. 마네킹은 음성 채널에 포함되지 않는다. 개별 음소거는 현재 경기 한정이며 장치/수신 음량은 로컬 PC에 저장한다.
- 동료별 0~100% 수신 음량과 실제 발화 상태 표시도 지원한다. 즉시 적용/초기화/재연결 처리 및 검사 방법은 [생존자 동료별 보이스 제어](SurvivorVoiceParticipantControls.md)를 참고한다.
- 장치/음량은 적용 버튼으로 저장, 초기화는 즉시 기본값으로 적용한다. 돌아가기는 아직 적용하지 않은 장치/음량 선택을 버린다.
- EOS 사용 불가 또는 Windows 권한/장치 오류 시 실패 안내를 표시한다. 기본 마이크 입력 검사는 EOS 접속과 독립적으로 동작한다.

실제 장치 목록과 생존자 간 통화/감쇄/음소거는 서로 다른 두 PC 및 정상 EOS 환경에서 확인해야 한다. 자동 검사는 마이크를 열거나 통화하지 않는다.

## 계정 이용 제한

도우미 → 서버 운영 → **계정 이용 제한**:

- 계정 ID/사유를 지정해 기간제(1분~1년) 또는 영구 제한, 선택 계정 해제.
- 적용 즉시 기존 로그인 토큰/게임 입장 티켓을 폐기하고 방 멤버를 정리한다. 일반 클라이언트는 기존 세션 확인 흐름으로 로그아웃된다.
- 올바른 비밀번호여도 제한 중이면 로그인 거부, 기간이 지나거나 관리자가 해제하면 다시 로그인 가능.
- 해제해도 폐기된 이전 토큰은 부활하지 않는다. 적용/해제 이력은 유지한다.
- 관리자 API 키가 필요한 별도 경로이며 일반 클라이언트가 제한/해제/이력 조회를 할 수 없다.

## DB 백업·복원

도우미 메인 창 → **DB 백업·복원**:

- 백업 목록/생성 시각/크기/SHA-256 확인, 현재 DB 백업, 선택한 백업 복원.
- 백엔드와 모든 데디 서버를 먼저 중지하고 **MySQL만 실행된 상태**에서 복원한다.
- 복원 대상은 이 프로젝트의 `LocalMySql/Backups` 안에 있는 SQL 및 일치하는 `.manifest.json` 쌍이다. 이전에 만든 manifest 없는 백업은 자동 검증/복원 대상이 아니다. 먼저 새 백업을 만든다.
- 확인창에서 동의해야 진행하며 현재 DB를 별도 자동 백업한 후 **projectproject01 DB 전체**를 선택한 시점으로 교체한다. 선택 시점 이후 추가된 테이블도 남겨 두지 않는다.
- 복원 실패 시 자동 생성한 직전 백업으로 롤백을 시도한다. 롤백마저 실패하면 백업 경로/오류를 표시하며 백엔드를 중지한 채 원인을 확인해야 한다. 백업 폴더를 별도로 복사해 보관하는 것을 권장한다.
- 복원 후 백엔드를 다시 시작하면 필요한 최신 스키마를 안전하게 추가한다.

## 설문 답변과 크래시 ZIP

- 게임 내 설문 객관식/OX 답변은 흰색, 주관식 답변도 흰색+어두운 입력 배경을 사용한다. 로그인 등 다른 입력창의 검은 글씨 설정은 유지한다.
- 서버에는 원본 첨부파일(`Crash.dmp`, `Game.log`, `CrashContext.xml`)을 보관한다. 서버 원본 폴더에 `.zip`이 없는 것은 정상이다.
- 도우미 → 서버 운영 → 크래시 보고서 보기 → 보고서 선택 → **선택 보고서 덤프·로그 ZIP 다운로드** → 저장 위치 지정. ZIP은 요청 시 묶어서 **선택한 PC 경로**에 저장한다.
- 파일을 끝까지 받은 뒤 ZIP을 검증하고 임시 파일에서 최종 파일로 이동한다. 실패 시 기존 ZIP을 지우거나 부분 파일로 덮어쓰지 않는다. 저장 완료 창에 절대 경로를 표시한다.
- JSON 보고서만 있고 실제 첨부파일이 없으면 ZIP은 만들 수 없다. 404(첨부 없음)와 인증/서버 오류를 구분해 표시한다.

## 검증

- Editor Development / Client Shipping C++ 컴파일.
- .NET 도우미/백엔드/검증 도구 빌드, 별도 MySQL 23307 및 전용 데이터 디렉터리에서 API/DB 통합 검사. 운영 3307과 운영 데이터는 변경하지 않는다.
- 실제 SQL 백업/복원: 한글 유지, 새 테이블 제거, 해시 변조 차단, 잘못된 SQL 복원 실패 후 직전 상태 복구, 명시적 확인 강제.
- 설문 답변 색상과 음성 설정 위젯 구성에 대한 Unreal 자동 검사. 도우미 창 이미지도 별도 테스트 폴더에 렌더링.
- 남은 실환경 확인: 소스 빌드 UE Dedicated Server 재패키징 후 6명/2개 방 동시 경기, 각 방의 서로 다른 포트/역할/결과/복귀, 실제 마이크/스피커 및 EOS 통화.

경기 세션 자동 관리 검사는 실제 API/별도 MySQL과 모의 UE 프로세스로 수행한다. 카운트다운 먼저, 5초 전 대기열 진입 금지, 한도 초과 대기와 FIFO 자동 배정, 취소/120초 자리 대기·90초 준비 제한/실행 실패/크래시 후 방 복구, 준비 완료 시에만 역할 배정, 중복 확정 시 역할 유지, 전원 복귀 후 종료, 두 동시 세션 격리, 구형·다른 세대 heartbeat 거부를 포함한다. Unreal 자동 검사는 검색 중 무암전, 실제 입장 때만 시작/역할 표시, 취소 후 문구 제거도 확인한다. 실제 패키징된 UE 프로세스의 기동/정상 종료까지 이 검사로 대체하지 않는다.

실제 패키지 확인 순서:

1. 최신 클라이언트/데디를 같은 소스 엔진으로 패키징하고 도우미/백엔드를 최신 빌드로 실행한다.
2. 최대 동시 경기 수 2 → 게임 서버 운영 시작. 방만 만들어 대기할 때 작업 관리자에 경기 서버 프로세스가 없는지 확인한다.
3. 3명이 준비 후 시작 → 5초 카운트다운 → 세션 찾는 중 → 서버 프로세스 1개 생성 → 준비 완료 후 시작 문구/역할/암전/접속을 확인한다.
4. 준비 중 또는 카운트다운 중 취소 시 게임에 들어가지 않고 기존 방을 유지하며 프로세스가 정리되는지 확인한다.
5. 2개 방을 동시에 시작하면 서로 다른 UDP 포트/경기 ID/역할을 받는지 확인한다. 세 번째 방은 세션 찾는 중으로 대기하고, 앞선 경기의 세션이 정리되면 시작을 다시 누르지 않아도 자동으로 준비되어야 한다. 대기 취소·120초 초과 시 방을 유지하고 뒤늦게 입장하지 않아야 한다.
6. 경기 결과 화면에서 한 명만 방으로 복귀했을 때 세션은 유지되고, 전원 복귀하면 세션 프로세스만 종료되어야 한다. 대기방과 운영 기능은 유지되어 다음 시작이 가능해야 한다.
7. 정상 세션 종료 뒤 오탐 크래시 보고서가 생기지 않는지 확인한다. 세션 실행 로그는 `Saved/GameServerSessions`에 남는다.
