# Daybook · 팀 기록실

팀의 회의·계획·목표·대화·기록이 날짜와 주제로 이어지는 웹 협업툴입니다. 기존 게임과 Git 관리 도구와 별도 프로젝트입니다.

## 사용 흐름

1. 로그인하고 협업 공간을 만듭니다.
2. 공간 관리에서 프로젝트를, 왼쪽 메뉴에서 주제와 필요한 사용자 항목을 만듭니다.
3. 팀 목표·개인 목표·계획안·회의록·결정·할 일·문서·작업 로그·일정·의논·대화방을 남깁니다.
4. 기록의 날짜, 기한, 담당자와 상태를 지정합니다. 목표나 회의록에 후속 할 일을 연결합니다.
5. 같은 기록을 오늘·달력·항목별 목록·작업 보드·검색에서 확인합니다.
6. 기록 상세에서 댓글·팀원 알림·사진·파일·변경 이력을 봅니다.

주제와 사용자 항목은 팀에 공유됩니다. 생성한 팀원이나 관리자가 이름·설명·색상·보관 상태를 관리합니다. 보관은 내용을 삭제하지 않으며 공간 관리에서 다시 꺼낼 수 있습니다.

## 공유와 권한

- 로그인은 Sites의 ChatGPT 인증을 사용합니다. 별도 비밀번호를 저장하지 않습니다.
- 새 사이트는 소유자만 접근 가능합니다. 실제 팀원이 사용하려면 **사이트 공유 설정의 접근 권한**과 **협업 공간 초대**가 모두 필요합니다. 공간 초대 코드만으로 사이트의 접근 제한을 우회하지 않습니다.
- 초대는 한 번 사용할 수 있고 7일 동안 유효합니다. 특정 이메일로 제한하거나 취소할 수 있습니다. 초대 링크를 열면 참여 요청이 생성되며, 공간 소유자가 **팀원 관리 → 참여 요청**에서 승인하거나 거절합니다. 승인 전에는 기록을 읽거나 수정할 수 없습니다. 승인할 때 읽기 전용·팀원·관리자 권한을 선택합니다. 사이트 외부 접근 권한은 기존 사이트 공유 설정에서 별도로 검토·부여합니다.
- 소유자·관리자·팀원·읽기 전용을 구분합니다. API가 모든 기록·댓글·파일 요청의 소속과 권한을 검사합니다.
- 삭제한 기록은 휴지통에 보관합니다. 작성자나 관리자가 복원할 수 있습니다. 영구 삭제 버튼은 제공하지 않습니다.
- 수정 시 버전을 확인하여 다른 팀원의 변경을 조용히 덮어쓰지 않습니다.
- 편집 중 버전 충돌이 발생하면 내 초안을 유지하고 최신 서버 내용을 비교할 수 있습니다. 최신 내용으로 다시 작성하기는 확인 후 실행합니다.
- 현재 접속 중인 팀원과 같은 기록을 편집 중인 사람을 표시합니다. 약 15초마다 갱신하며, 응답이 없는 접속은 45초 후 목록에서 빠집니다. 동시에 같은 문장을 실시간 병합하는 편집기는 아니며, 저장 단위 버전 검사로 충돌을 막습니다.
- 작성 중인 텍스트와 분류 설정은 이 브라우저에 계정·공간·기록별 임시 초안으로 보관합니다. 저장 전에 창을 닫거나 연결이 끊어져도 다시 해당 기록을 열어 초안을 복구할 수 있습니다. 첨부파일은 복구 후 다시 선택해야 합니다. 서버 저장 성공 시 해당 임시 초안을 제거합니다.
- 접속 상태·참여 신청자의 정보·개인 임시 초안은 Git 파일 내보내기에서 제외됩니다.

## 문서와 파일

- .docx: 문단과 표의 텍스트를 불러옵니다.
- .pptx: 프레젠테이션에 지정된 슬라이드 순서대로 텍스트를 불러옵니다.
- .xlsx: 시트별 값·표를 불러옵니다. 수식은 실행하지 않으며 저장된 계산값을 사용합니다. 시트당 최대 500행·50열을 미리 봅니다.
- .txt, .md, .csv: 텍스트를 읽습니다. UTF-8·UTF-16 및 한국어 인코딩을 처리합니다.
- 원본 파일을 함께 첨부합니다. 파일당 최대 10MB입니다.
- 원본 Office 문서의 페이지 배치·도형·차트·수식 편집이나 OCR은 제공하지 않습니다. 구형 .doc/.ppt/.xls는 새 형식으로 변환해야 합니다.
- 사진은 인증된 파일 경로로 미리 보고 다운로드할 수 있습니다. SVG·실행 파일은 첨부할 수 없습니다.

## 관리와 기록 범위

- 기록·주제·항목·팀 권한 변경과 첨부·댓글 이력을 보존합니다.
- 담당자 배정·댓글·파일 공유 알림을 제공합니다. 앱이 열려 있을 때 갱신하며 이메일·모바일 푸시는 보내지 않습니다.
- 대화는 약 5초, 공간 목록은 약 12초 간격으로 갱신합니다.
- 목록에서 한 번에 최대 1,000개를 표시합니다. 초과 시 날짜나 검색어로 범위를 좁히도록 안내합니다. 검색은 저장된 전체 본문을 대상으로 합니다.
- 관리자는 JSON으로 기록·댓글·이력을 내보낼 수 있습니다. 현재 가져오기는 본문 기록을 새 기록으로 추가하며 프로젝트·댓글·첨부파일의 전체 복원은 지원하지 않습니다. 원본 첨부는 별도로 다운로드해야 합니다.

## 요약과 Git 변경사항 저장

- 작성·가져온 내용에서 핵심 문장과 키워드를 추립니다. 별도 AI API 요금은 없습니다. 수동 요약을 입력하면 그 내용을 우선합니다.
- 공간 관리의 ‘Git 변경사항으로 저장’에서 **이 PC에 복제한 저장소 최상위 폴더**를 선택합니다. Chrome/Edge에서 페이지를 직접 열어 사용합니다.
- 기록은 `daybook/<공간ID>/` 아래에 JSON·Markdown으로, 직접 올린 첨부는 원본 파일로 저장됩니다. 설정 창을 닫아도 페이지가 열려 있고 반영이 켜져 있으면 저장 후 반영하며, 다른 팀원의 변경도 약 30초마다 확인합니다.
- 페이지를 닫으면 폴더 반영은 멈춥니다. 다시 열면 ‘반영 시작’으로 접근 권한을 허용합니다. 폴더 접근은 이 브라우저·계정·공간에만 기억합니다.
- 로그인 정보·초대 코드·개인 알림·환경 비밀값·캐시·빌드·임시파일은 내보내지 않습니다. 앱 소스 전체나 DB 원본도 복사하지 않습니다. 직접 올린 문서 내용은 그대로 포함되므로 커밋 전에 검토합니다.
- 충돌 감지를 위한 로컬 상태 파일은 기록 폴더의 `.gitignore`로 제외합니다. 저장소 최상위의 기존 `.gitignore`는 수정하지 않습니다.
- PC에서 따로 수정한 파일은 덮어쓰지 않고 충돌을 알립니다. Git의 `.git`·브랜치·스테이징 영역은 건드리지 않습니다.
- **커밋·푸시·GitHub 쓰기는 수행하지 않습니다.** 사용자가 기존 Git 도구에서 변경된 파일을 선택해 커밋·푸시합니다. GitHub 토큰은 필요하지 않습니다.
- 현재는 서버 기록을 PC 파일로 내보내는 단방향 반영입니다. Git에서 변경한 파일을 서버로 자동 가져오지는 않습니다.

## 개발·검사

```powershell
npm run dev -- --hostname 127.0.0.1 --port 5173
npx tsc --noEmit
node scripts/check-collaboration.mjs
```

`check-collaboration.mjs`는 로컬 미리보기의 개발용 계정과 새 QA 공간만 사용합니다. 운영 사이트에서 실행하지 않습니다. 개발용 인증은 Sites starter가 루프백에서만 처리하며 운영 빌드에는 포함하지 않습니다.

`.wrangler/`, `outputs/`와 로컬 테스트 데이터는 소스·배포에서 제외됩니다. 운영 DB와 파일 저장소는 D1·R2로 분리되어 있으며 브라우저 저장소에는 선택한 공간 ID 같은 표시 설정만 보관합니다.
