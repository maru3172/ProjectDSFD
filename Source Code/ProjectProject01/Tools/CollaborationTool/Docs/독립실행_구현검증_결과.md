# 독립 실행·Git 공동 자료 전환 결과

2026-10-31 / Windows x64

## 확정된 사용 방식

- 팀원은 Daybook.exe를 실행해 로컬에서 작성·저장합니다. 서버를 직접 관리할 필요가 없습니다.
- 운영자가 공동 서버를 켠 동안에는 승인받은 계정으로 같은 자료를 함께 사용합니다.
- 오프라인 변경을 합치는 기준은 Git입니다. 작업 폴더의 파일을 직접 커밋·푸시·받아온 뒤 프로그램에서 미리 확인하여 반영합니다.
- Git 충돌은 선택 없이 덮어쓰지 않습니다. 자동 커밋·푸시와 서버 재접속에 의한 오프라인 자료 자동 업로드는 없습니다.
- 로그인·승인·권한·세션을 Git에서 가져오지 않습니다. 로컬 공간 소유권과 공동 서버 소유권은 별개입니다.

## 자동 검사 근거

- `scripts/check-standalone.mjs`: **43개 통과**. 실제 HTTP 요청으로 권한·동시 수정·중복 재시도·첨부·Git 반영·충돌·Windows 줄바꿈·암호화 백업·변조 차단·다른 PC를 모형화한 새 자료 폴더 가져오기 검사.
- `scripts/check-standalone-extended.mjs`: **30개 통과**. 인수인계·알림·반복/시간 경계·위임·탈퇴·1,105개 기록 검색·이전 대화·지정 메시지·새 설치 DB/원본 첨부 복원·세션 회수 검사.
- `scripts/check-purge.mjs`: **15개 통과**. 휴지통의 기록과 바로 영구 삭제(댓글·이력·체크리스트·첨부·원본 파일·즐겨찾기까지 제거, 하위 기록은 연결만 풀림, 이력에는 내용 없이 삭제 사실만), 파일의 모든 버전 영구 삭제, 휴지통 비우기(관리자만, 휴지통의 기록과 버린 파일만), 권한 없는 팀원 차단, Git 작업 폴더에서 파일 제거와 다시 받아와도 되살아나지 않음.
- `scripts/check-contacts.mjs`: **37개 통과**. 메시지 고치기·지우기(쓴 사람만 고침, 관리자는 남의 대화방 메시지 삭제 가능, 일반·읽기 전용 팀원 차단, 파일 메시지는 휴지통으로, 1:1 수정·삭제가 상대 화면에도 반영, 1:1 파일 삭제 시 파일까지 제거), 1:1 사진·파일 전송(이름·종류·크기·설명 표시, 사진 바로 보기), 보낸 사람·받는 사람만 열람하고 같은 공간의 다른 팀원·공간 밖 사람은 열 수 없음, 공간 첨부 목록·일반 파일 주소에 나오지 않음, 시스템 백업 포함, 실행 파일·빈 파일·10MB 초과 거부. 1:1 메시지 안 읽음·읽음 표시, 제3자·공간 밖 사람 차단, 1:1 내용이 기록 목록·검색·내보내기·알림·관리자 백업에 나오지 않음, 대화방 새 메시지 알림(쓴 사람 제외), 배정 알림 전달.
- `scripts/check-tool-import.ts`(`npx tsx`): **12개 통과**. Notion 내보내기(안쪽 zip, 32자리 id 제거, 하위 페이지 연결, 링크·사진·데이터베이스 _all 처리), Obsidian 위키 링크·사진, 낱개 파일, CSV 인용 규칙.
- `scripts/check-browser-crypto.mjs`: 내부망 HTTP용 해시 대체 경로 **14개 입력을 Node SHA-256과 비교**, **UUID 1,000개**의 형식·중복 검사 통과. 비밀번호 암호화는 이 코드로 하지 않습니다.
- 기존 문서 가져오기 **8개**, 브라우저 폴더 내보내기 **18개** 회귀검사 통과.
- TypeScript 검사·프런트엔드 번들·Windows 자체 포함 런처 빌드 수행. 실제 Windows 배포본이 동봉 Node로 공간 1개를 열고 정상 종료되는 결과를 `outputs/launcher-execution-result.json`에 기록했습니다.

## 실제 화면에서 확인한 부분

첫 실행 이름 설정, 로컬 로그인, 기존 기록 화면, 업무·자료 관리창, Git 폴더/반영/가져오기 화면을 확인했습니다. 관리창은 본문과 분리해 표시하고 탭 이동·키보드 포커스·390px 화면에서 가로 넘침 없이 표시됐고, Escape로 닫은 뒤 원래 버튼으로 포커스가 돌아오는 것도 확인했습니다.

## 완료로 간주하지 않은 부분

- 실제 팀원 두 PC에서의 방화벽·네트워크·권한별 공동 사용 실습. 자동 검사는 같은 PC의 여러 계정과 분리된 자료 폴더를 사용했습니다.
- 기존 클라우드 운영본 및 저장소 영구 삭제. 로컬 이전과 별개이며 원본은 그대로 보존했습니다. 접근 제한만으로 향후 호스팅 비용이 없어졌다고 주장하지 않습니다.
- 별도 깨끗한 Windows PC에서의 설치/업데이트/복구 실습과 모든 브라우저·입력 방식의 사용성 검사.

현재 소규모 팀용으로 구현한 범위의 결과입니다. 보안 감사나 모든 환경에서의 무오류를 보장하는 보고서는 아닙니다.
