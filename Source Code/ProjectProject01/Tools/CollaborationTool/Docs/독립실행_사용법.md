# Daybook 사용법

## 팀원은 이렇게 사용합니다

1. 배포 폴더 전체를 풀고 **Daybook.exe**를 실행합니다. 기록실이 열리고 이 PC에 바로 저장됩니다. Node나 별도의 서버 프로그램을 설치할 필요가 없습니다.
2. 처음에는 **공간 만들기**를 누르거나, Git으로 받아온 자료를 반영합니다.
3. Daybook 창의 **Git 폴더 선택**, 또는 **업무·자료 관리 → 이 PC·Git**에서 자신의 Git 저장소 최상위 폴더를 지정합니다. 저장소는 먼저 복제하거나 만들어 두세요. 저장한 자료가 그 폴더의 `daybook` 아래에 JSON과 원본 첨부로 나타납니다.
4. 평소 쓰는 Git 도구에서 변경사항을 확인하고 직접 커밋·푸시합니다. 프로그램은 Git 명령을 대신 실행하지 않습니다.
5. 다른 사람의 변경을 Git으로 받아온 뒤 **받아온 자료 확인 → 확인한 자료 반영**을 누릅니다. 양쪽에서 같은 기록을 수정했다면 내용을 비교하고 어느 쪽을 반영할지 선택합니다. 선택 전에는 덮어쓰지 않습니다.

Git에는 기록·댓글·프로젝트·주제·공유 양식·반복 규칙·원본 첨부·작성자 이름을 저장합니다. 비밀번호·세션·계정 승인·관리자 권한·개인 알림·개인 양식·임시 초안·실행 로그·실행용 DB는 내보내지 않습니다. Git에서 자료를 가져와도 공동 서버의 계정·접근 권한이 생기지 않습니다. 파일 삭제는 프로그램의 휴지통을 사용하세요. Git 충돌 표시가 남은 JSON은 반영할 수 없습니다.

프로그램을 닫아도 자료는 `%LOCALAPPDATA%/DSFD/Daybook`에 남습니다. 프로그램·배포 폴더와 분리되어 있습니다. 해당 폴더와 자동 백업 복구 키는 별도로 보관하세요. 배포할 때 개인 자료 폴더를 함께 보내지 마세요.

## 운영자가 공동 작업을 열 때

1. 기록실의 **서버 관리**에서 운영자 비밀번호를 설정합니다. 처음 로컬 실행에서만 사용하는 자동 접속 키는 서버 PC 내부에서만 유효합니다.
2. Daybook 창의 **공동 서버 시작**을 누릅니다. 창에 표시되는 서버 IP·포트를 팀원에게 알려줍니다. 사용한 포트만 방화벽에 허용하며 전체 방화벽을 끄지 않습니다.
3. 팀원은 자신의 기록실 **이 PC·Git → 공동 서버 접속**에서 주소를 엽니다. 처음 가입할 때 **이 PC의 작성자와 연결 요청**을 선택하면, 운영자가 **서버 관리 → 계정 승인**에서 이름을 확인하고 **작성자 연결**을 선택해 승인할 수 있습니다. 오프라인과 공동 계정에서 같은 작성자·담당자로 표시됩니다. Git 파일만으로는 이 연결이나 공간 권한이 생기지 않습니다.
4. 공간 초대를 보내고, 팀원이 참여를 신청하면 공간 관리자가 별도로 승인합니다. 계정 승인과 공간 권한은 별개입니다.
5. 공동 서버를 종료하면 원격 접속은 멈춥니다. 팀원은 자기 PC의 기록실에서 계속 작성할 수 있습니다. 로컬 내용은 공동 서버 재접속으로 자동 전송·덮어쓰기하지 않습니다. 합치는 기준은 Git입니다.

공동 서버의 자료도 운영자가 지정한 Git 폴더로 반영할 수 있습니다. 평문 HTTP는 신뢰할 수 있는 내부망에서만 사용하세요. 외부 인터넷에 사용할 경우 TLS 인증서와 키 경로를 자료 폴더의 `settings.json`의 `tlsCert`, `tlsKey`에 설정해야 합니다. 프록시의 사용자 인증 헤더는 신뢰하지 않습니다.

## 업무와 문서

- 기존 기록·날짜·할 일·주제 화면에서 작성합니다. 기록 상세의 톱니바퀴는 해당 기록의 업무 관리로 연결됩니다.
- **선택한 기록**에서 체크리스트·선행 업무·중요 결정 확인·인수인계·이전 버전 복원을 관리합니다. 미완료 선행 업무나 체크리스트가 있으면 완료를 막습니다. 관리자는 사유를 남겨 예외 완료할 수 있습니다.
- **양식·반복**에서 개인·팀 양식, 주·월 단위 반복, 종료일, 다음 회차 건너뛰기·중단을 관리합니다. 프로그램 중단 기간은 재실행부터 최대 60회씩 이어서 생성합니다. 월말 기준일은 다음 달에도 유지됩니다.
- **내 업무**에서 마감·정체·즐겨찾기·인수인계와 저장한 필터를 봅니다. 전체 검색과 페이지 불러오기로 이전 자료에 접근합니다.
- 대화는 최근 100개부터 불러오며 이전 대화는 기록 업무 관리에서 이어서 봅니다. 메시지 초안과 기록 초안은 현재 브라우저에 보관됩니다.
- **첨부 자료**에서 이름 변경·휴지통·복원·새 첨부로 교체합니다. 교체 전 자료를 보존합니다. 원본은 첨부당 10MB, 공간별 기본 합계 2GB입니다.
- **공간 운영**에서 보관·다시 열기·소유권 위임 수락·담당 업무 재배정 후 탈퇴가 가능합니다.

## 팀 도구

업무 관리의 **팀 도구** 탭에 있습니다.

- **발표 자료**: 파워포인트처럼 슬라이드를 만듭니다. 슬라이드마다 제목, 내용("- "로 시작하면 글머리표), 사진 한 장을 넣고, 추가·복제·순서 바꾸기·삭제를 합니다. 내용과 사진이 없는 슬라이드는 가운데 제목만 있는 표지가 됩니다.
  - **발표**: 전체 화면으로 띄우고 방향키·스페이스·클릭으로 넘깁니다. Esc는 발표만 끝내고, 편집 화면에서 한 번 더 누르면 편집을 닫습니다.
  - **.pptx**: PowerPoint 파일로 내려받아 PowerPoint에서 이어서 고칠 수 있습니다. 글자, 글머리표, 사진과 배치가 옮겨지며 애니메이션·디자인 테마는 없습니다. webp 사진은 PNG로 바꿔 넣습니다.
  - 발표 자료도 기록("발표 자료" 항목)이라 댓글·검색·변경 이력·Git 내보내기가 그대로 되고, 다른 팀원이 먼저 저장했으면 덮어쓰지 않고 알려 줍니다.
- **내보내기**: 선택한 기록 하나는 텍스트(.txt), Markdown(.md), Word(.docx), PDF로 내보냅니다. PDF는 인쇄 창이 열리면 프린터를 "PDF로 저장"으로 고릅니다. 기록 목록은 종류·상태·기간으로 골라 CSV, Excel(.xlsx), Word(한 문서로 모음), 텍스트로 내보냅니다(한 번에 5,000개까지, 첨부 파일 제외). Excel·CSV에서 `=`로 시작하는 내용은 수식이 아니라 글자로 들어갑니다.

- **작업 잠금**: 맵(.umap)·에셋(.uasset)처럼 Git이 합칠 수 없는 파일을 고치기 전에 저장소 기준 경로(예: `Content/Maps/Lobby.umap`, 폴더 전체는 끝에 `/`)로 잠급니다. 4시간~일주일 뒤 저절로 풀리며, 같은 파일이나 그 폴더를 다른 팀원이 잠그려 하면 누가 언제까지 쓰는지 알려 주고 막습니다. 잠근 사람이나 관리자만 풀 수 있고, 관리자가 풀면 잠근 사람에게 알림이 갑니다.
  - 잠금은 알림판이며 파일을 실제로 막지는 않습니다. 커밋 전에 **내 변경 확인**에 `git status --short -uall` 결과를 붙여 넣으면, 남이 잠근 파일을 고쳤는지와 아직 잠그지 않은 에셋을 알려 줍니다. 서버가 실행되는 PC에서는 **이 PC·Git**에서 연결한 Git 폴더를 바로 확인할 수 있습니다.
- **버그·플레이테스트**: 버그는 제목, 빌드, 위치, 심각도, 빈도, 재현 순서, 기대·실제 결과, 스크린샷을 정해진 칸에 적어 "버그" 항목의 업무로 만듭니다(치명·높음은 높은 우선순위). 플레이테스트 의견은 좋았던 점·불편한 점·제안을 "플레이테스트" 항목의 메모로 남깁니다. 아래에 열린 버그를 심각한 순서로 보여 줍니다.
- **마일스톤**: "목표" 기록이 마일스톤입니다. 업무·계획의 상위 기록을 목표로 정하면 여러 단계 아래까지 모아 진행률, 완료·진행·막힘·기한 지남 수, 남은 날(D-day)을 보여 줍니다.

- **회의 기록 가져오기**: 회의 기록 도구(`Tools/MeetingRecorder`)가 만든 회의 폴더를 고르면 요약·메모·대화문이 회의 기록 하나로 들어옵니다. 요약의 "할 일" 줄은 그 회의 아래 업무로 만들어지며, 가져오기 전에 고치거나 지울 수 있습니다. 응답이 끊겨 다시 눌러도 두 번 만들어지지 않습니다.
- **주간 보고**: 고른 주(월~일, 한국 시간)의 끝낸 일, 진행 중, 막힌 일, 기한이 지났거나 그 주까지인 일, 작업 로그, 회의·결정을 사람별로 모은 Markdown입니다. 복사, `.md` 내려받기, 작업 로그로 저장(같은 주는 한 번만)을 할 수 있습니다.
- **커밋 연결**: 기록을 고르면 `DB-1a2b3c4d` 같은 기록 코드가 보입니다. 커밋 메시지에 이 코드를 넣으면, **이 PC·Git**에서 연결한 Git 폴더의 최근 1년 커밋 중 그 코드가 든 커밋이 기록 옆에 보입니다(대소문자 무관, 읽기만 함). 주간 보고의 각 줄에도 코드가 붙습니다.

## 1:1 대화와 알림

- 왼쪽 아래 `1:1 대화`에서 같은 공간 팀원과 둘이서만 이야기합니다. 1:1 대화는 두 사람에게만 보이며 기록 목록·검색·내보내기·백업 파일에 나오지 않습니다. 읽기 전용 팀원도 쓸 수 있고, 상대가 읽으면 `읽음`이 붙습니다.
- 여러 명이 함께 쓰는 대화는 `의논과 대화`의 대화방을 씁니다.
- 대화방 새 메시지, 1:1 메시지, 배정·언급 같은 알림이 오면 오른쪽 아래에 알림 카드가 뜹니다. 누르면 그 대화로 갑니다. 1:1 대화창이 열려 있을 때는 카드가 창 안에 뜹니다.
- `1:1 대화` 창에서 `브라우저 알림 켜기`를 누르면 창을 내려 둔 동안에도 Windows 알림으로 알려 줍니다.

## 다른 도구에서 가져오기

- `기록과 자료` 또는 `새 기록` 메뉴의 `다른 도구에서 가져오기`를 누릅니다.
- Notion: 페이지나 워크스페이스 설정 → 내보내기 → `Markdown & CSV`(또는 HTML)로 받은 .zip을 그대로 고릅니다. 하위 페이지는 부모 기록 아래에 연결되고, 데이터베이스는 표로, 페이지 안 사진은 첨부로 들어옵니다.
- Obsidian 등: 보관함 폴더를 .zip으로 묶거나 .md·.html·.txt·.csv 파일을 여러 개 고릅니다. Google 문서·Confluence·Evernote는 Markdown이나 HTML로 내보낸 파일을 쓰면 됩니다.
- 가져올 페이지와 기록 종류를 고른 뒤 가져옵니다. 한 번에 80MB, 300페이지까지이며 사진은 장당 10MB까지입니다.

## 백업과 복원

운영 PC의 **서버 관리 → 전체 백업·복원**에서 백업 암호를 지정합니다. DB와 모든 원본 첨부를 AES-256-GCM으로 암호화하고 각 파일의 SHA-256·DB 무결성·연결 관계를 검사합니다. 백업 암호가 없으면 다른 PC에 복원할 수 없습니다.

자동 백업은 기본 24시간마다 7개 보관합니다. 복구 키는 `backup-recovery-key.txt`에 따로 저장합니다. 자동 백업 파일만 복사해서는 복구할 수 없으니 키도 안전한 별도 장소에 보관하세요. 이 키를 Git에 넣지 마세요.

브라우저에 올리는 복원 파일은 256MB 이하입니다. 큰 파일은 **이 PC의 큰 백업 파일로 검사**에서 파일 전체 경로와 암호를 입력하세요. 시스템 백업은 원본 합계 16GB·파일 20만 개까지 지원합니다.

복원 파일과 암호를 선택해 미리보기한 뒤, 현재 자료를 보호할 백업 암호를 입력하여 복원을 예약합니다. 프로그램을 정상 종료하고 다시 실행하면 검증된 자료로 교체합니다. 기존 로그인 세션은 회수합니다. 잘못된 암호·손상·호환되지 않는 DB 버전은 반영하지 않습니다.

## 업데이트

프로그램을 완전히 종료한 뒤 새 배포본의 `Daybook.exe`, `runtime`, `app`만 교체합니다. **자료 폴더를 지우거나 새 빈 폴더로 덮어쓰지 않습니다.** 먼저 전체 백업을 만들고 복구 키를 따로 보관합니다. DB 구조 변경 전에는 자동 보호 복사본을 만들며, 이미 적용한 변경 파일이 달라졌으면 시작을 중단합니다. 실패하면 기존 프로그램과 확인된 전체 백업으로 복원합니다.

사용 소프트웨어에 유료 호스팅·API·구독은 필요하지 않습니다. 자신의 PC·인터넷·전기·디스크와 Git 저장소 용량은 각자 관리합니다. 기존 클라우드 운영본은 별도 이전 확인 전까지 삭제하지 않았습니다.
