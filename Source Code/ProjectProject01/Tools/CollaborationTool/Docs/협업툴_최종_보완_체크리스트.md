**Daybook 협업툴 — 최종 구현·보완 범위와 완료 기준**

작성일: 2026-10-31, 한국 시간

이 문서는 최초 합의한 범위와 완료 기준이다. 현재 구현 결과·검증 근거·미수행 항목은 `독립실행_구현검증_결과.md`에서 구분한다. 구현 체크와 실제 다중 PC 실습 완료는 다르다.

**범위와 고정 조건**

- 목적은 팀원이 브라우저로 함께 쓰는 소규모 팀 협업툴이다.
- 회의록·계획·목표·할 일·의논·대화·자료를 날짜·프로젝트·주제로 관리한다.
- 추가 호스팅 사용료, 유료 API, 유료 저장소와 유료 구독을 운영 필수 조건으로 삼지 않는다. 기존 PC의 전기·인터넷·저장장치 비용은 소프트웨어 무료 여부와 별개다.
- 최종 운영 방식은 기존 PC 또는 학교 PC에서 직접 실행하는 형태로 전환한다. 서버 PC가 꺼져 있으면 다른 사람도 해당 서버에 접속할 수 없다.
- 현재 Sites 배포본은 독립 서버로 전환되지 않았다. 개발용 로컬 로그인이나 인증 헤더를 신뢰하는 코드를 그대로 외부에 노출하지 않는다.
- Git에는 선택한 협업 자료만 파일 변경사항으로 반영한다. 자동 스테이징·커밋·푸시는 하지 않는다.
- 비밀번호·인증키·활성 세션·개인 알림·임시 초안·캐시·실행 로그·DB 작업 파일은 Git 자료 내보내기에서 제외한다.
- 팀원 참여는 소유자 검토 후 승인한다. 가입한 것만으로 다른 공간을 읽을 수 없게 한다.
- 기존 운영 데이터의 영구 삭제와 클라우드 사이트 삭제는 이전·복원 확인 후 별도로 확정한다.

**이미 있는 기능 — 새 기능으로 중복 계산하지 않음**

- 여러 협업 공간, 프로젝트, 주제와 사용자 항목.
- 날짜별 기록과 달력, 할 일 목록과 상태 보드, 목표와 후속 기록 연결.
- 회의록·문서·작업 로그·계획안·결정·의논·대화방.
- 댓글·팀원 지정 알림·사진과 파일 업로드 및 다운로드.
- DOCX·PPTX·XLSX·TXT·MD·CSV 내용 가져오기. Office 원본 편집기는 아님.
- 본문 검색, 수동 요약과 문장 추출 방식 자동 요약, 날짜별 요약.
- 소유자·관리자·팀원·읽기 전용, 일회용 초대, 참여 요청 승인·거절.
- 휴지통과 기록 복원, 변경 이력 열람.
- 접속자·동시 편집 표시, 버전 충돌 차단과 최신 본문 비교.
- 기록 편집 초안의 브라우저 임시 보관·복구.
- 관리자의 기록 JSON 내보내기와 본문 기록 가져오기.
- Git 저장소 폴더에 협업 자료를 파일로 반영. 이 기능은 서버 동기화나 전체 시스템 복원과 다르다.

**A. 무료 직접 운영에 필요한 전환 — 1~4**

1. [x] **독립 실행 배포본** — 전환.
   - 서버 프로그램·DB·첨부 저장소를 지정한 PC에서 실행·보관한다.
   - 무료로 사용할 수 있는 구성요소를 사용하고, 일반 업무에 외부 유료 서비스를 요구하지 않는다.
   - 실제로 실행할 수 있는 시작 절차와 종료·재시작 절차를 제공한다. 최초 설치·업데이트에 필요한 다운로드와 일상 실행의 의존성을 구분한다.
   - 완료 기준: 외부 호스팅에 연결하지 않아도 학교 또는 팀 내부망에서 기본 업무를 수행한다.

2. [x] **독립 계정·로그인·세션 관리** — 전환.
   - 현재 Sites 인증을 대체하는 로그인, 가입 신청, 관리자 승인, 비밀번호 변경·복구 절차를 제공한다.
   - 비밀번호를 안전하게 저장하고 로그인 시도 제한·세션 만료·로그아웃·세션 회수를 적용한다.
   - 계정 비활성화와 팀원 제거 후 기존 세션으로 접근할 수 없어야 한다. 권한은 요청마다 서버에서 확인한다.
   - 사용자에게서 온 인증 헤더만으로 로그인한 사람을 결정하지 않는다.
   - 완료 기준: 소유자·팀원·읽기 전용·미승인 계정이 실제 독립 서버에서 구분된다.

3. [x] **서버 관리 화면 또는 도우미** — 신규.
   - 실행·정상 종료·재시작, 접속 IP·포트, 저장 폴더, 접속 주소 복사를 제공한다.
   - 서버 상태·최근 오류·저장 공간·최근 백업 결과를 항목별로 정리한다.
   - 실행 설정을 저장하고 다음 실행에 반영한다. 방화벽 전체 해제나 무분별한 인터넷 공개를 기본 동작으로 삼지 않는다.
   - 완료 기준: 운영자가 터미널 명령을 기억하지 않아도 접속 주소와 서버 상태를 확인할 수 있다.

4. [ ] **기존 데이터 이전과 클라우드 운영 정리** — 전환.
   - 현재 공간·기록·댓글·첨부·연결 관계를 이전하고, 계정 식별자와 소유권을 검토해 연결한다.
   - 이전 전후 수량과 파일 내용을 비교한다. 로그인 세션은 그대로 복사하지 않는다.
   - 이전·복원 확인 후 기존 클라우드 운영본과 저장소 정리 절차를 확정한다. 화면 접근 제한만으로 향후 저장 비용이 사라진다고 가정하지 않는다.
   - 완료 기준: 최종 운영이 유료 전환 가능한 호스팅을 필수로 사용하지 않는다.

**B. 기록과 자료를 안전하게 유지하기 — 5~8**

5. [x] **전체 백업·복원** — 보완.
   - 기록 본문뿐 아니라 프로젝트·주제·사용자 항목·댓글·첨부·목표 연결·담당자 관계를 포함한다.
   - 수동 백업, 정기 백업, 보관 개수와 저장 위치, 실패 알림을 제공한다.
   - 백업 형식·파일 무결성을 검사하고, 복원 전 내용을 미리 확인한다. 깨진 백업을 기존 데이터에 일부만 덮어쓰지 않는다.
   - 공유용 자료 내보내기와 관리자 전용 시스템 백업을 구분한다. 인증 정보가 포함되는 시스템 백업은 별도로 보호한다.
   - 완료 기준: 새 설치 환경에서 백업 하나로 자료와 관계를 복구하고 원본 첨부를 다시 열 수 있다.

6. [x] **기록 이전 버전 복원** — 보완.
   - 기존 변경 이력에서 이전 내용을 비교하고 선택한 버전으로 복원한다.
   - 현재 내용을 먼저 보존하고 복원 자체도 새 이력으로 기록한다. 다른 사람의 동시 수정을 버전 검사 없이 덮어쓰지 않는다.
   - 완료 기준: 실수로 내용을 지워 저장한 경우에도 복원할 수 있다.

7. [x] **첨부파일 관리 완성** — 보완.
   - 첨부의 이름 변경·삭제·복원과 파일 교체 시 이전 자료 보존 범위를 정한다.
   - 동일 파일의 중복 업로드를 알려주고 파일별·공간별 사용량과 허용 용량을 표시한다.
   - 첨부를 삭제·교체할 때 댓글과 기록의 파일 연결이 끊어지지 않도록 처리한다.
   - 완료 기준: 업로드 외에도 잘못 올린 파일을 관리하고 용량 부족을 파악할 수 있다.

8. [x] **안전한 프로그램·DB 업데이트** — 신규.
   - 업데이트 전 백업, 데이터 구조 변경 검사, 호환되지 않는 버전 안내와 실패 시 복구 절차를 제공한다.
   - 실행 파일·소스와 실제 자료 폴더를 분리해 업데이트가 기록을 초기화하지 않게 한다.
   - 완료 기준: 새 버전 적용 후 기존 기록을 유지하고, 실패 시 확인된 백업으로 복구한다.

**C. 실제 협업 흐름을 완성하기 — 9~16**

9. [x] **마감 업무 모아보기·알림** — 보완.
   - 마감 임박·기한 초과·오래 정체된 일을 담당자별로 확인한다.
   - 완료·보관 상태는 제외하고 같은 알림을 계속 쌓지 않는다. 알림 종류와 빈도를 조절한다.
   - 유료 이메일·문자 서비스를 기본 의존성으로 두지 않는다. 서버가 꺼져 있을 때의 처리 규칙도 표시한다.
   - 완료 기준: 언제 누구의 어떤 일이 지연됐는지 한 화면에서 확인한다.

10. [x] **작업 선후관계·체크리스트** — 신규.
    - 현재의 후속 기록 연결을 유지하면서, 먼저 끝내야 할 작업과 작은 완료 조건을 지정한다.
    - 순환 의존을 막고 선행 작업 미완료 상태를 표시한다. 완료 규칙과 관리자의 예외 처리를 명확히 한다.
    - 완료 기준: 다음에 무엇을 해야 하는지와 작업을 완료할 조건이 보인다.

11. [x] **반복 업무** — 신규.
    - 주·월 단위 반복, 요일·기준 시간, 종료일, 이번 회차 건너뛰기·반복 중단을 제공한다.
    - 서버 재시작·중복 실행·자정 경계에서도 같은 회차를 두 번 만들지 않는다. 중단 기간의 지난 회차 처리 규칙을 정한다.
    - 완료 기준: 매주 같은 회의나 점검을 다시 작성하지 않아도 된다.

12. [x] **문서 템플릿** — 신규.
    - 회의록·작업 로그·계획안·보고서 양식을 저장하고, 팀 공유 또는 개인 양식을 선택해 새 문서를 만든다.
    - 양식 변경이 이미 작성한 문서를 바꾸지 않는다.
    - 완료 기준: 팀원이 매번 같은 항목과 문서 구조를 다시 입력하지 않는다.

13. [x] **업무 인수인계** — 보완.
    - 담당자 변경에 현재 상태·남은 작업·막힌 이유·참고 자료를 함께 남긴다.
    - 새 담당자의 확인 상태와 이전 담당자 이력을 보존한다.
    - 완료 기준: 이름만 바뀌어 업무 맥락이 사라지는 일을 줄인다.

14. [x] **내 업무·즐겨찾기·저장한 보기** — 신규 편의.
    - 나에게 배정된 일, 내가 확인해야 할 일, 내가 자주 보는 기록을 빠르게 연다.
    - 상태·담당자·기한 등 자주 쓰는 필터를 저장한다. 팀 공용 고정과 개인 즐겨찾기는 구분한다.
    - 완료 기준: 팀 전체 목록을 매번 뒤져 자기 일을 찾지 않아도 된다.

15. [x] **대화방의 읽지 않은 내용 관리** — 보완.
    - 방별 읽지 않은 수·마지막 읽은 위치·나를 지정한 메시지로 이동을 제공한다.
    - 재접속 후 놓친 내용을 확인하고, 오래된 대화는 필요한 만큼 불러온다.
    - 완료 기준: 대화방을 오가거나 다시 접속해도 어디까지 확인했는지 잃지 않는다.

16. [x] **중요 공지·결정 확인** — 신규.
    - 기존 결정·기록을 중요 항목으로 지정하고 대상 팀원이 직접 확인 표시를 남긴다.
    - 확인자·미확인자와 중요한 내용의 변경을 확인한다. 내용을 바꿨는데 이전 확인을 그대로 유효하게 처리하지 않는다.
    - 완료 기준: 중요한 결정이 전달됐는지 관리자가 확인할 수 있다.

**D. 공간 운영과 사용 안정성 — 17~20**

17. [x] **공간 보관·소유자 위임·탈퇴** — 보완.
    - 끝난 공간을 읽기 전용으로 보관하고 다시 연다.
    - 소유자 위임은 대상·권한·수락을 확인하고, 소유자가 사라져 관리 불가능한 공간을 만들지 않는다.
    - 팀을 떠난 사람의 작성 기록·담당 업무·표시 이름을 보존 또는 재배정한다.
    - 완료 기준: 프로젝트 종료나 팀원 변경에도 관리 권한과 기록이 유지된다.

18. [x] **자료가 많아졌을 때의 목록 처리** — 보완.
    - 현재 기록 1,000개·변경 이력 100개 수준의 목록 제한 이후에도 페이지 이동이나 더 불러오기로 접근한다.
    - 검색·정렬·필터·더 불러오기의 기준을 일치시키고, 열람 중 새 기록이 들어와도 목록을 갑자기 바꾸지 않는다.
    - 완료 기준: 기록·대화가 많아져도 필요한 내용을 누락 없이 찾는다.

19. [x] **연결 끊김·재전송 안전장치** — 보완.
    - 요청 시간 초과·취소·저장 성공 여부 확인과 명확한 재시도를 제공한다.
    - 응답을 못 받아 다시 요청해도 같은 기록·댓글·반복 업무를 중복 생성하지 않는다.
    - 기록 외에도 작성 중인 메시지 보존, 첨부 실패 재선택과 재시도를 정리한다.
    - 완료 기준: 잠시 연결이 끊겨도 무한 대기·중복 저장·조용한 내용 손실을 막는다.

20. [x] **직접 운영 환경의 보안·자원 관리** — 보완.
    - 기존의 권한 검사·쿼리 매개변수화·파일 형식 제한·안전한 응답 처리를 유지한다.
    - 독립 서버에 맞는 접속 보호·로그인 방어·CSRF·신원 헤더 위조 방지·업로드 검증·요청/용량 제한을 점검한다.
    - DB·첨부·백업·로그를 공개 웹 경로와 분리한다. 디스크 부족, 로그 증가와 실패 상태를 관리한다.
    - 민감한 인증 정보나 일반 팀원이 접근할 수 없는 데이터가 로그·백업·Git 파일에 새지 않게 한다.
    - 완료 기준: 무료 직접 운영으로 옮겨도 기존 보호가 빠지지 않는다.

**완료 판정을 위한 검증 — V1~V6**

- [ ] **V1. 실제 여러 계정·PC의 권한 검증:** 소유자·팀원·읽기 전용·미승인·퇴장 계정으로 공간·기록·파일에 직접 접속한다. 승인 전과 권한 회수 후 접근이 막히는지 확인한다.
- [ ] **V2. 공동 수정·네트워크 장애 검증:** 같은 기록 동시 저장, 댓글 응답 유실 후 재시도, 접속 단절·브라우저 종료·서버 재시작을 재현한다. 내용 손실·중복 생성과 권한 우회를 확인한다.
- [x] **V3. 복원·업데이트 검증:** 실제 첨부를 포함한 공간을 새 설치에 복원해 내용·수량·연결·권한을 비교한다. 손상된 백업과 업데이트 실패를 재현한다.
- [x] **V4. 날짜·반복·알림 검증:** 자정·주간/월간 경계, 서버 중단 뒤 재시작, 완료·보관·기한 변경에서 중복과 잘못된 알림이 없는지 확인한다.
- [ ] **V5. 사용성·자료량 검증:** 자료·대화를 충분히 쌓고 검색·페이지 이동·읽지 않은 내용·대량 첨부를 확인한다. 좁은 화면·키보드·확대 배율에서도 주요 버튼과 입력이 불편하지 않은지 확인한다.
- [ ] **V6. 추가 사용료 없는 독립 운영 검증:** 깨끗한 PC에서 설치·실행·종료·백업·복원을 수행한다. 외부 호스팅이나 유료 API 연결 없이 내부망 공동 작업이 가능한지, 기존 클라우드 자료가 이전됐는지 확인한다.

**현재 확인한 근거와 한계**

- `app/chatgpt-auth.ts`, `worker/index.ts`, `app/api/*`: 현재 실행과 인증은 Sites/Cloudflare 환경을 전제로 한다. 독립 운영 전환 완료 상태가 아니다.
- `db/schema.ts`, `app/api/data/route.ts`: 현재의 기록 구조·권한·목록 제한·백업/가져오기 범위를 확인했다. 반복 업무·템플릿·체크리스트·선후 작업 등은 별도 구현이 필요하다.
- `app/workspace-app.tsx`, `app/collaboration.tsx`, `app/drafts.ts`: 현재 UI, 참여 승인, 접속/편집 표시, 초안 보관, 최신 본문 비교를 확인했다.
- `app/api/file/route.ts`, `app/import-documents.ts`: 첨부 업로드/다운로드, 원본과 추출 본문, 문서 형식별 제한을 확인했다. 첨부 관리·전체 복원을 모두 제공하는 상태는 아니다.
- `app/export-data.ts`, `app/api/local-files/route.ts`, `app/local-files*.ts*`: Git 파일 반영은 단방향 내보내기이며 로그인·초대·접속/개인 상태는 제외한다.
- 기존 로컬 자동 검사 결과는 공동 작업 25개와 기존 기능 30개 통과 기록이다. 이것이 독립 서버 전환 또는 위 20개 구현·V1~V6 전체 완료를 증명하지는 않는다.
- 이 목록은 현재 규모와 사용 목적의 기능 범위를 정리한 것이다. 외부 보안 감사, 모든 라이브러리 코드의 검증, 실제 팀 전체의 실습 완료를 주장하지 않는다.
