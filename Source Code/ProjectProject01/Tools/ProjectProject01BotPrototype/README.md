# 봇 정책·엔진 검증 도구

2026-10-23. 실제 구현은 Unreal Source와 백엔드 프로젝트에 있으며 이 폴더에는 공통 정책/실행 검사 도구가 있다. 운영 반영과 외부 PC 검증은 별도로 구분한다.

- 검사 스크립트 자체는 게임·서버 빌드에 포함되지 않는다. 실제 AI 소스는 `Source/ProjectProject01`에 포함된다.
- 이 폴더의 예전 연결 초안은 빌드에 포함하지 않는다. 이후 별도 봇전의 실제 소스는 게임/백엔드 프로젝트에 새로 구현하고 있으며, 진행 상태는 `Docs/BotAndObserverImplementation.md`에 기록한다. 기존 성능 개선은 보존했다.
- 강화학습·신경망 초안과 그 연결 패치는 2026-10-23 확정 요구사항에 따라 제거했다.
- `Backend/BotRoomSupport.cs`: 봇 별도 신원, 방장 권한, 3명 경기+2명 관전, 난이도/레이팅 연결의 미검증 초안. 운영 DB에 적용하지 않았다.
- 공통 판단 코드는 `Source/ProjectProject01/Public/ProjectAdaptiveBotPolicy.h`로 새로 구현했다. 신경망·보상·강화학습 갱신은 없다.
- `RunPolicyChecks.cmd`는 같은 코드의 독립 C++ 검사를 실행한다. 결과물은 `Saved/AdaptiveBotChecks`에만 생성된다. 1,066개 검사 통과. 의도적인 유인·습관 역이용은 4~5단계만 허용한다.
- `RunEngineChecks.ps1`은 별도 보고서/outbox 경로에서 실제 경기 게임 모드의 봇 10조합, 관전 자유/고정 시점, 기존 연습 AI·장애물·엘리베이터·암전·관전 연출 회귀 검사를 실행한다. 새로운 빌드나 패키징은 하지 않는다. 결과 JSON의 실패/누락을 확인해 실패로 종료한다.
- 실제 서버 + 별도 네트워크 클라이언트 검사는 `Run-IsolatedIntegration.ps1 -EditorServerExecutable <UnrealEditor.exe>`의 선택 검사다. 테스트 DB 23307과 정확한 격리 데이터 경로를 부모 검사가 먼저 검증한다. 프로세스·로그·결과 outbox는 `Saved/FeatureChecks/EditorNetwork`에 분리한다. 실제 패키징/다중 PC 검증을 대신하지 않는다.
- 연습모드는 기존 AI를 유지한다. 새 난이도 정책과 연결하지 않으며, 실전형 벽·엄폐물 토글만 추가한다.

## 권장 진행 순서

1. 기존 경기와 같은 규칙을 사용하는 고정 봇: 방장 추가/삭제, 5단계 선택, 서버 로스터/로딩/승패/이탈/맵 전환 검사.
2. 오픈매칭 전용 관전 인원/권한 및 독립 UI. 생존자 사망 관전과 분리해 검증.
3. HFSM으로 필수 규칙 우선순위와 중단/복귀를 보장하고 유틸리티로 전술 선택.
4. 같은 팀이 실제 관측한 정보만 유효 시간/출처와 함께 공유. 협공·엄호·역할 분담을 추가.
5. NavMesh/A* 경로 위에서 제한된 분리·감속·회피 Steering. 최근 길찾기 최적화/낙하 방지 보존.
6. 통계 적응 활성/비활성 및 난이도별 전술·이동·부하를 비교한다. 신경망/강화학습은 추가하지 않는다.

경기 중 적응은 학습 알고리즘 없이 상대 패턴 통계/기억을 유틸리티 점수에 반영해서도 가능하다. 이것을 강화학습이나 신경망 학습이라고 부르지 않는다. 신경망을 넣었다는 사실만으로 좋은 봇이나 난이도 균형이 보장되지는 않는다.

각 단계는 기본 비활성, 독립 검사, 기존 로직 복귀 경로를 전제로 한다. 싱글 AI 변경·게임 패키징·운영 DB 변경은 하지 않는다.
